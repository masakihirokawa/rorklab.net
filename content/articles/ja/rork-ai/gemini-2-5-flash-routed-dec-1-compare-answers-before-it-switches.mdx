壁紙アプリの画像に自動でカテゴリの候補を付ける仕組みを見直していた晩、Gemini API の廃止予定のページを開いて、しばらく画面の前で手が止まりました。12月1日の行に書かれていたのは「停止」ではなく、別のモデルへの**自動ルーティング**だったからです。

最初のうち、私は廃止といえばエラーが返るものだと思い込んでいました。エラーが返れば Crashlytics にも出ますし、ログを見れば翌朝には気づけます。ところが回されるだけなら、アプリは何事もなかったように動き続けます。変わるのは、返ってくる答えの言い回しや長さ、それに請求の単価です。

最初にお伝えしたいのは、**止まる期限より、回される期限のほうが気づきにくい**ということです。残りは今日を入れて7日。Rork で AI 機能を足したアプリをお持ちの方に向けて、前日までにできる確かめ方を順に書き残します。

## 12月1日に起きること

Gemini API の [Deprecations](https://ai.google.dev/gemini-api/docs/deprecations) のページでは、12月1日から次の呼び出しが後継モデルへ回されると案内されています。

<tr><td><code>gemini-2.5-flash</code></td><td><code>gemini-3.5-flash-lite</code></td></tr>
<tr><td><code>gemini-2.5-pro</code></td><td><code>gemini-3.8-flash</code></td></tr>

あわせて押さえておきたいのは、回されたあとの料金は**回り先のモデルの単価**で数えられる点です。2.5 系の単価を前提に月の上限を決めていた場合、そこも見直しの対象になります。開発者フォーラムには、音声の関連度を判定する処理が回り先で崩れるとして、猶予を求める投稿も上がっていました。答えの形に頼った処理ほど、影響が出やすいのだと思います。

なお、表の左側に `-001` などの版番号付きの名前や、`-preview` の付いた名前を使っている場合は、それぞれの行を同じページで確かめてください。扱いが同じとは限りません。

## 手順1: アプリが呼んでいるモデル名を洗い出す

Rork で作ったアプリでは、モデル名がどこに書かれているかを自分で把握していないことが少なくありません。私も、画面のコードには無いと思っていたら、サーバー側の関数に直書きされていました。

Rork のチャットでは、次のように一度だけ頼むのが確実です。

> このプロジェクトで Gemini API を呼んでいる箇所を、ファイル名とモデル名の一覧にしてください。コードは変更しないでください。

書き出したコードが手元にある場合は、ターミナルで探すこともできます。

```bash
# 書き出したプロジェクトの直下で実行します
grep -rnE "gemini-2\.5-(flash|pro)" --include='*.ts' --include='*.tsx' --include='*.js' --include='*.json' . \
  | grep -v node_modules
```

見つかった場所が、**アプリ本体の中**なのか、**Supabase の Edge Function や Cloudflare Workers のようなサーバー側**なのかを、ここで分けておきます。この違いが、手順4の判断に効いてきます。置き場所の考え方は [API キーを環境変数に置くか Edge Function に置くか](/articles/rork-ai/rork-api-key-placement-env-variables-vs-supabase-edge-function) にもまとめています。

## 手順2: 同じ入力で、いまのモデルと回り先を並べる

12月1日を待たなくても、回り先のモデルは今日から名前を指定して呼べます。そこで、同じ入力を両方に投げて、答えを横に並べます。

次のスクリプトは、Node.js 18 以降でそのまま動く形にしています。`inputs.json` には、アプリで実際に送っている文面を10件ほど入れてください。

```javascript
// compare-models.mjs — 同じ入力を2つのモデルに送り、答えの形と時間を並べます
// 実行: GEMINI_API_KEY=YOUR_API_KEY node compare-models.mjs inputs.json
import { readFile } from "node:fs/promises";

const PAIRS = [["gemini-2.5-flash", "gemini-3.5-flash-lite"]]; // 2.5-pro を使っていれば行を足します
const KEY = process.env.GEMINI_API_KEY;
if (!KEY) throw new Error("GEMINI_API_KEY が未設定です");

async function ask(model, text) {
  const started = Date.now();
  const res = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent`,
    {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-goog-api-key": KEY },
      body: JSON.stringify({ contents: [{ parts: [{ text }] }] }),
    }
  );
  const ms = Date.now() - started;
  if (!res.ok) return { model, ms, error: `${res.status} ${await res.text()}` };
  const data = await res.json();
  const out = data.candidates?.[0]?.content?.parts?.map((p) => p.text ?? "").join("") ?? "";
  let isJson = false;
  try { JSON.parse(out.replace(/^\x60{3}(json)?\s*|\x60{3}\s*$/g, "")); isJson = true; } catch {}
  return { model, ms, chars: out.length, isJson, tokens: data.usageMetadata?.totalTokenCount, head: out.slice(0, 60) };
}

const inputs = JSON.parse(await readFile(process.argv[2], "utf8"));
for (const [oldModel, newModel] of PAIRS) {
  for (const [i, text] of inputs.entries()) {
    const [a, b] = [await ask(oldModel, text), await ask(newModel, text)];
    console.log(`#${i + 1}`, JSON.stringify(a), "\n   ", JSON.stringify(b));
  }
}
```

見るのは、答えの中身の良し悪しより先に、**形が同じかどうか**です。`isJson` が片方だけ `false` になる、文字数が倍近く変わる、冒頭に前置きの一文が付くようになる——アプリの画面やパース処理が壊れるのは、たいていこの三つのどれかです。所要時間（ms）とトークン数も、同じ行で見比べておくと、費用の見当がつけやすくなります。

## 手順3: 答えの形をアプリ側で固定しておく

並べてみて形が揺れるなら、モデルを替える前に、答えの形を指定する側を固めます。Gemini API では `generationConfig` に `responseMimeType: "application/json"` と `responseSchema` を渡すと、決めた形の JSON で返すよう指定できます。プロンプトの文面だけで「JSON で返してください」と頼んでいた箇所は、この機会に置き換えておくと安心です。

AI の答えをキャッシュしている場合は、キャッシュのキーにモデル名が入っているかも確かめてください。入っていないと、切り替え後も古いモデルの答えが混ざって表示されます。考え方は [モデルを替えた日にキャッシュを掃除する](/articles/rork-ai/ai-answer-cache-key-model-and-prompt-version-sweep-on-swap) に書きました。

## 手順4: 自分で切り替えるか、回されるのに任せるか

ここで手順1の仕分けが効いてきます。

- **サーバー側に書かれている場合**: 並べて問題がなければ、12月1日より前に自分でモデル名を書き換えるのがおすすめです。自分で替えれば、替えた時刻が分かり、何かあれば元に戻す判断も自分でできます
- **アプリ本体に書かれている場合**: 書き換えには審査が要ります。今週中に申請しても、12月1日に間に合わないこともあります。その場合は回されるのを前提に、手順3の形の固定を先に入れ、あわせてモデル名をサーバー側から渡す形へ移す計画を立てておくのが現実的です

私自身は、**期限の日付は Google が決め、切り替える時刻は自分が決める**という線引きにしています。回されるのを待つと、変わった瞬間を自分で見届けられないからです。

同じ週の11月30日には Claude API の Sonnet 4.5 も提供を終えます。両方を使っているアプリの方は、[Sonnet 4.5 を呼んでいないかの洗い出し](/articles/rork-ai/scan-app-for-old-claude-model-ids-before-sonnet-4-5-retires) とあわせて一度に確かめておくと、手戻りが少なくて済みます。

## 次にすること

まずは手順1の一覧を作り、モデル名が書かれている場所を「アプリ本体」と「サーバー側」に分けるところまで、今日のうちに済ませていただければと思います。その一覧さえあれば、並べる作業はそれほど重くありません。答えが変わる日を、知らないうちに迎えないこと——この一点だけは、小さなアプリでも守るようにしています。
