# Rork アプリを Claude 4 に移行する完全ガイド

Claude API を組み込んだ Rork アプリを運用していると、「そろそろ Claude 4 に移行したほうがいいのかな」と気になり始める時期がきます。2026年に入って claude-sonnet-4-6 が一般提供され、Extended Thinking（拡張思考）などの新機能も使えるようになりました。

移行は難しくありません。ただ、単にモデル文字列を変えるだけでは引き出せない性能があります。この記事では、Rork アプリで Claude 3.x から Claude 4 へ移行する具体的な手順と、新機能を活用するためのコードパターンを整理します。

## Claude 4 で何が変わったか

Claude 4 の変更点を押さえておくと、移行の設計判断が楽になります。

**モデル文字列の変化**

移行でまず変える箇所がモデル識別子です。

```javascript
// Claude 3.x（旧）
const response = await client.messages.create({
  model: "claude-3-5-sonnet-20241022",
  ...
});

// Claude 4（新）
const response = await client.messages.create({
  model: "claude-sonnet-4-6",  // または claude-opus-4-6, claude-haiku-4-5-20251001
  ...
});
```

claude-4 系のモデル文字列はサフィックスが異なります。既存コードのすべての model 指定を洗い出して更新が必要です。

**Extended Thinking（拡張思考）の追加**

Claude 4 で最も実用的な新機能が Extended Thinking です。通常の応答に加えて、モデルが「どう考えたか」の推論過程が取得できます。複雑な判断が必要なアプリ機能（法律・医療・財務に関わるQ&A、多段階の問題解決など）で、回答の信頼性を大幅に高めることができます。

**コンテキストウィンドウの拡大**

claude-sonnet-4-6 は最大200Kトークンのコンテキストをサポートします。長い会話履歴や大量のドキュメントを参照させたい場合に、従来よりも多くの情報を一度に渡せるようになりました。

**レート制限の変化**

Claude 4 では Tier 別のレート制限が調整されています。特に claude-haiku-4-5-20251001（最も軽量なモデル）の制限が緩和され、高頻度リクエストが必要なユースケースに使いやすくなっています。

## 3 ステップで完了する移行手順

### Step 1: モデル文字列の一括置換

Rork プロジェクトでは、モデル名を直接ハードコードしているケースが多いはずです。まず環境変数か定数に切り出しましょう。

```javascript
// utils/claude.js — モデル管理を一元化
export const CLAUDE_MODELS = {
  // 軽量・高速：チャット返答、補完、分類タスク向け
  fast: "claude-haiku-4-5-20251001",
  // バランス型：主力の会話AI、コンテンツ生成向け
  balanced: "claude-sonnet-4-6",
  // 最高精度：法律・医療・複雑な推論向け
  advanced: "claude-opus-4-6",
};
```

これを移行後の標準とし、各 API 呼び出しで `CLAUDE_MODELS.balanced` のように参照することで、将来のモデル更新時に変更箇所が1か所で済みます。

### Step 2: max_tokens の見直し

Claude 4 では max_tokens のデフォルト挙動がやや変わっています。以前は省略しても安全に動いていたケースでも、明示的に指定することをお勧めします。

```javascript
// 移行後の標準パターン
const response = await client.messages.create({
  model: CLAUDE_MODELS.balanced,
  max_tokens: 1024,  // 用途に合わせて調整（Extended Thinking 使用時は +budget_tokens 分）
  messages: conversationHistory,
  system: systemPrompt,
});
```

チャットアプリなら 512〜1024、コンテンツ生成なら 2048〜4096 が目安です。

### Step 3: ストリーミングコードの確認

ストリーミング応答のイベント型が Claude 4 で整理されました。既存のストリーミング実装を確認し、イベントタイプのハンドリングが適切か確かめます。

```javascript
const stream = await client.messages
  .stream({
    model: CLAUDE_MODELS.balanced,
    max_tokens: 1024,
    messages,
  })
  .on("text", (text) => {
    // テキストデルタをリアルタイムで UI に反映
    setPartialResponse((prev) => prev + text);
  });

const finalMessage = await stream.finalMessage();
```

`content_block_delta` イベントではなく `.on("text", ...)` を使うシンプルなパターンが、Rork の React Native 環境では安定して動作します。

## Extended Thinking を Rork アプリで活用する

Extended Thinking はオプションの機能ですが、使いどころを知ると実装の幅が広がります。有効化すると `thinking` ブロックがレスポンスに追加され、モデルの推論過程を確認できます。

```javascript
const response = await client.messages.create({
  model: "claude-sonnet-4-6",  // Extended Thinking は Sonnet 4.6 / Opus 4.6 で利用可
  max_tokens: 16000,
  thinking: {
    type: "enabled",
    budget_tokens: 10000,  // 推論に使うトークン数の上限
  },
  messages: [
    {
      role: "user",
      content: "ユーザーが入力したテキスト",
    },
  ],
});

// レスポンスに thinking ブロックが含まれる
for (const block of response.content) {
  if (block.type === "thinking") {
    console.log("推論過程:", block.thinking);
  } else if (block.type === "text") {
    console.log("最終回答:", block.text);
  }
}
```

`budget_tokens` はコストに直結します。10,000 トークンが1つの目安ですが、複雑なタスクほど高く設定するとより精度が上がります。ただし Simple なチャット機能では Extended Thinking は不要で、むしろコスト増になるだけです。使いどころは「ユーザーが明確な判断を求める場面」に絞るのが実用的です。

## モデル選定の実践ガイド

3種類のモデルをどう使い分けるかが、コストパフォーマンスに直結します。

**claude-haiku-4-5-20251001（高速・低コスト）**
- テキスト補完や短い応答が多い機能
- 検索インデックス生成、タグ付け、分類
- レート制限に余裕があるため高頻度リクエストに向く

**claude-sonnet-4-6（バランス型・主力）**
- チャット UI のメイン会話AI
- コンテンツ生成（説明文、要約、翻訳）
- ほとんどのユースケースにこれが適している

**claude-opus-4-6（最高精度・高コスト）**
- 法律・医療・財務に関わるアドバイス
- 複雑な多段階タスクの自動化
- Extended Thinking と組み合わせた深い推論が必要な場面

```javascript
// 用途別にモデルを切り替えるヘルパー関数
function getModelForTask(taskType) {
  switch (taskType) {
    case "chat":
      return CLAUDE_MODELS.balanced;
    case "classification":
    case "summary":
      return CLAUDE_MODELS.fast;
    case "legal_advice":
    case "complex_reasoning":
      return CLAUDE_MODELS.advanced;
    default:
      return CLAUDE_MODELS.balanced;
  }
}
```

## 移行時によくあるトラブルと対処法

**「model_not_found」エラーが出る**

古いモデル文字列（例: `claude-3-opus-20240229`）がどこかに残っています。コードベースを `claude-3` でグレップして全箇所を更新します。

```bash
# プロジェクト内の古いモデル文字列を検索
grep -r "claude-3" --include="*.js" --include="*.ts" .
```

**Extended Thinking 使用時にレスポンスが遅くなる**

`budget_tokens` が大きすぎる可能性があります。まず 5,000 程度から始めて、実際の推論品質と速度のバランスを見ながら調整するのがお勧めです。

**max_tokens 不足でレスポンスが途中で切れる**

claude-sonnet-4-6 は前のモデルより詳細な回答を生成することがあります。以前 512 で足りていたケースで 1,024 に増やすと解消することがほとんどです。

**ストリーミングで UI の更新が遅延する**

React Native でストリーミング UI を実装する場合、setState の更新頻度が高すぎると表示が詰まることがあります。debounce を入れるか、ref で中間状態を持って一定間隔で setState する方法が有効です。

## まとめ：移行は小さな一歩から

Claude 4 への移行は、最初の一歩がモデル文字列の変更だけでも始められます。まず claude-sonnet-4-6 に切り替えてみて、応答品質の変化を確認する。その上で Extended Thinking が必要なユースケースがあれば追加する、という段階的なアプローチが実際のアプリ開発では現実的です。

Claude 4 の新機能をフルに使い始めると、AIの回答精度と信頼性が明らかに上がります。Rork プロジェクトのパフォーマンス向上に、ぜひ活用してみてください。
