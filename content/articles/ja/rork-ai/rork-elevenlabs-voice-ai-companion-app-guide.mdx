TestFlight に配ったキャラクターアプリのアクセス解析を、数日おきに見返していた時期がありました。テキストチャットだけのコンパニオン系アプリは、配って数日たつと起動する人がみるみる減っていきます。同じジャンルのアプリでも似た傾向を耳にしますが、数字は集計の仕方で大きく変わるため、ここでは私の手元で見えた範囲にとどめます。

空気が変わったのは、ElevenLabs の音声合成を組み込んで、キャラクターが「声で返す」ようにしたときでした。テキストの内容は同じでも、声がつくだけで一回あたりの滞在が目に見えて長くなり、トライアルを始めてくださる方も増えた——というのが私の実感です。ここでは、Rork で作ったアプリに ElevenLabs をつなぐ手順と、費用を抑えながら続けていくための線引きを書き残します。

## なぜテキストだけのコンパニオンアプリは続かないのか

最初に作ったキャラクターアプリは、Claude API でテキストを生成し、画面下部に吹き出しで表示するシンプルな構成でした。リリース直後の感想で多かったのが「結局 ChatGPT と何が違うのか分からない」という声です。当然です。テキストチャットの体験は、すでに大手のチャットアプリで完成されています。

声を加えたあとに見えた変化は、数値以上に「使い方」の質的な変化でした。

- ベッドサイドに置いて、寝る前に話しかける方が増えました
- 朝の通勤中、画面を見ずにイヤホンで会話する使われ方が出てきました
- 「キャラクターが自分の名前を呼んでくれる」という声のレビューが付くようになりました

つまり「声で返す」体験は、画面に拘束されない時間帯のユーザーを掴むための鍵になります。Rork で UI を素早く組めるのと、ElevenLabs で日本語の自然な発話が API 経由で取れるのを掛け合わせると、個人開発でもこのレベルの体験を1週間程度で組み上げられるようになりました。

## ElevenLabs を選ぶ理由（OpenAI TTS / Google Cloud TTS との比較で迷ったとき）

音声合成 API はいくつか選択肢があります。私は主要なものを一通り課金して試し、コンパニオンアプリ用途では ElevenLabs を選んでいます。ただし料金表やモデル名は数か月で入れ替わるため、以下の数値は執筆時点の目安として読んでください。契約の前には、必ず各社の公式ページで最新の条件をご確認ください。

- **日本語の自然さ**: ElevenLabs の Multilingual v2 は、漢字交じりの長文でもイントネーションが自然に聞こえました。OpenAI TTS は流暢ながらやや平坦に、Google Cloud TTS は WaveNet でも語尾の抑揚が薄く感じました（あくまで私の耳での比較です）
- **キャラクター性**: ElevenLabs は Voice Design 機能で、声色（明るい／落ち着いた／少し低め など）をプロンプトで指定して新しい声を作れます。OpenAI は用意された声から選ぶ形で、Google は性別や年代の違いが中心です
- **レイテンシ**: ElevenLabs Flash v2.5 は、最初の音声チャンクが返るまで 75ms 前後と公式が案内しています。他社は数百ミリ秒台のことが多く、リアルタイムの会話では Flash 系の差が体感に出ます。ただし通信環境しだいで数字は動きます
- **コスト**: ElevenLabs の文字単価はやや高めです（執筆時点の目安で、Creator プランが月 $22・100k 文字、超過分は 1k 文字あたり $0.30 前後）。それでもキャッシュを組めば、運用は十分に現実的です

「キャラクターらしい個性的な声」「日本語の自然さ」を最優先するなら ElevenLabs、「とにかくコストを抑えたい」なら OpenAI TTS、という棲み分けが私の中での結論です。迷ったときの目安を表にまとめます。

## アプリの全体構成

今回作るのは、以下のフローで動くシンプルなコンパニオンアプリです。

1. ユーザーがテキストまたは音声で話しかけます
2. Whisper（または OpenAI Realtime API）でテキスト化
3. Claude / GPT に投げて応答テキストを生成
4. 応答テキストを ElevenLabs API に渡して音声に変換
5. アプリ側で再生＆字幕表示

Rork 側は React Native / Expo ベースで、状態管理は Zustand、音声再生は expo-av を使います。バックエンドは Cloudflare Workers に置いて API キーをアプリに埋め込まない構成にしています。

## ElevenLabs API キーの取得とセキュアな置き場所

まず [ElevenLabs](https://elevenlabs.io) にサインアップし、ダッシュボードから API キーを発行します。注意点を3つ挙げます。

- **アプリにキーを直接埋め込まない**: バンドルを解析されると簡単に抜かれます。Cloudflare Workers などのバックエンドで中継します
- **Voice ID もログに残さない**: Voice ID だけで第三者が発話できるわけではありませんが、API キーが漏れたときに、どの声が使えるかを教える手がかりになってしまいます。Voice Cloning で作ったカスタム Voice は、とくにログやアプリ側に残さない運用にしています
- **使用量アラートを設定する**: ダッシュボードの Usage タブで、月間文字数の80%にメール通知を入れておくと、暴走したときの被害を抑えられます

私は最初これを怠って、デバッグ中の無限ループでひと晩のうちに1万円分の文字数を使い切ってしまいました。朝、請求の通知を開いたときの胃の重さはいまも覚えています。アラートは初日に入れておくのがお勧めです。

## Cloudflare Workers でのプロキシ実装

Rork で開発するアプリから直接 ElevenLabs を叩かず、Cloudflare Workers をプロキシにします。Worker 側のコードは以下のような形になります。

```typescript
// worker/src/index.ts — ElevenLabs プロキシ
// 機能: アプリから受け取ったテキストを ElevenLabs に渡し、音声バイナリを返す
// なぜ Worker 経由か: API キーをアプリに埋め込まないため + レート制限/キャッシュ層を持つため

export interface Env {
  ELEVENLABS_API_KEY: string;
  ELEVENLABS_VOICE_ID: string;
  AUTH_SECRET: string;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    if (request.method !== "POST") {
      return new Response("Method Not Allowed", { status: 405 });
    }

    // ① アプリからのリクエスト認証（Rork 側で発行する短期トークンを検証）
    const auth = request.headers.get("Authorization");
    if (auth !== `Bearer ${env.AUTH_SECRET}`) {
      return new Response("Unauthorized", { status: 401 });
    }

    // ② リクエストボディからテキストとモデルを取得
    const { text, modelId = "eleven_flash_v2_5" } = await request.json<{
      text: string;
      modelId?: string;
    }>();

    if (!text || text.length > 1000) {
      return new Response("Invalid text length", { status: 400 });
    }

    // ③ ElevenLabs にリクエスト（音声バイナリをそのまま返却）
    const elevenRes = await fetch(
      `https://api.elevenlabs.io/v1/text-to-speech/${env.ELEVENLABS_VOICE_ID}`,
      {
        method: "POST",
        headers: {
          "xi-api-key": env.ELEVENLABS_API_KEY,
          "Content-Type": "application/json",
          "Accept": "audio/mpeg",
        },
        body: JSON.stringify({
          text,
          model_id: modelId,
          voice_settings: {
            stability: 0.5,        // 0.5 で表現の幅と安定性のバランス
            similarity_boost: 0.75, // 元音声への忠実度
            style: 0.3,            // キャラクター性の強さ（高すぎるとノイズが出る）
            use_speaker_boost: true,
          },
        }),
      }
    );

    if (!elevenRes.ok) {
      const errText = await elevenRes.text();
      console.error("ElevenLabs error:", elevenRes.status, errText);
      return new Response("TTS upstream error", { status: 502 });
    }

    // ④ 音声を MP3 として返す（クライアントで expo-av が再生）
    return new Response(elevenRes.body, {
      headers: {
        "Content-Type": "audio/mpeg",
        "Cache-Control": "private, no-store", // 音声の再利用は後述のキャッシュ層で行う
      },
    });
  },
};
```

レスポンスの `Cache-Control` を `public` にすると、認証つきの応答が共有キャッシュに載る余地が生まれます。再利用は後述のキャッシュ層に任せ、この Worker では `no-store` にしています。

`AUTH_SECRET` は、あくまで動作確認用の共有トークンです。後述のフックでは `EXPO_PUBLIC_` 付きの環境変数から読んでいますが、この接頭辞の値はアプリのバンドルに含まれ、取り出せてしまいます。つまり固定の文字列では、キーをアプリに入れないという線引きが半分しか守れていません。本番では、Sign in with Apple や Firebase Auth で発行したユーザーごとの JWT を Worker で検証し、レート制限も併せて入れてください。期待する動作は、テキストを POST すると数百ミリ秒で MP3 が返ってくることです。

## Rork アプリ側の音声再生フック

Rork で UI を組むとき、音声再生は再利用できるカスタムフックにしておくと後が楽です。なお、以下では `expo-av` を使っていますが、Expo 側ではすでに `expo-audio` への移行が案内されています。新しく作るアプリでは、お使いの Expo SDK のドキュメントで現在の推奨を確かめてから選んでください。考え方（再生前に前の音を解放する、失敗しても無音で続ける）はどちらでも変わりません。

```typescript
// hooks/useVoiceResponse.ts — テキストを ElevenLabs 音声で再生するフック
// 解決すること: 重複再生防止、ローディング状態管理、エラー時の無音フォールバック

import { useState, useRef, useCallback } from "react";
import { Audio } from "expo-av";
import * as FileSystem from "expo-file-system";

const PROXY_URL = process.env.EXPO_PUBLIC_TTS_PROXY_URL!;
const AUTH_SECRET = process.env.EXPO_PUBLIC_TTS_AUTH_SECRET!;

export function useVoiceResponse() {
  const [isPlaying, setIsPlaying] = useState(false);
  const [isLoading, setIsLoading] = useState(false);
  const soundRef = useRef<Audio.Sound | null>(null);

  const speak = useCallback(async (text: string) => {
    if (!text.trim()) return;
    // 再生中なら一度止める（被って再生されると不快なため）
    if (soundRef.current) {
      await soundRef.current.unloadAsync();
      soundRef.current = null;
    }

    setIsLoading(true);
    try {
      const res = await fetch(PROXY_URL, {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "Authorization": `Bearer ${AUTH_SECRET}`,
        },
        body: JSON.stringify({ text }),
      });

      if (!res.ok) throw new Error(`TTS HTTP ${res.status}`);

      // ファイルとして保存（expo-av は URI から読み込む方が安定）
      const blob = await res.blob();
      const reader = new FileReader();
      const base64 = await new Promise<string>((resolve, reject) => {
        reader.onload = () => resolve((reader.result as string).split(",")[1]);
        reader.onerror = reject;
        reader.readAsDataURL(blob);
      });

      const fileUri = `${FileSystem.cacheDirectory}voice_${Date.now()}.mp3`;
      await FileSystem.writeAsStringAsync(fileUri, base64, {
        encoding: FileSystem.EncodingType.Base64,
      });

      const { sound } = await Audio.Sound.createAsync(
        { uri: fileUri },
        { shouldPlay: true }
      );
      soundRef.current = sound;
      setIsPlaying(true);

      sound.setOnPlaybackStatusUpdate((status) => {
        if (status.isLoaded && status.didJustFinish) {
          setIsPlaying(false);
          sound.unloadAsync();
        }
      });
    } catch (err) {
      console.error("TTS playback failed:", err);
      // 失敗時はサイレントフォールバック（テキスト表示のみで継続）
    } finally {
      setIsLoading(false);
    }
  }, []);

  const stop = useCallback(async () => {
    if (soundRef.current) {
      await soundRef.current.stopAsync();
      await soundRef.current.unloadAsync();
      soundRef.current = null;
      setIsPlaying(false);
    }
  }, []);

  return { speak, stop, isPlaying, isLoading };
}
```

このフックを画面側で呼び出せば、Claude から返ってきた応答テキストをそのまま音声で再生できます。`Audio.Sound` は使い終わったら `unloadAsync` で解放しないと、メモリが膨らみ続けて、しばらく会話したあとにアプリが落ちることがありました。実機テストで私は3度この壁にぶつかっています。シミュレータでは気づきにくいので、書き忘れないようにしてください。再生まわりの解放漏れは新しい API でも起こりやすく、[expo-audio の createAudioPlayer が40回目で鳴らなくなった話](/articles/rork-dev/expo-audio-createaudioplayer-stops-after-40-plays-remove-needs-release)も併せてご覧いただければ幸いです。

## コストを抑えるためのキャッシュ戦略

ElevenLabs は文字単価で課金されるため、同じセリフを毎回 API に投げると請求がすぐに膨らみます。私は以下の3層キャッシュを入れて、運用コストをはっきり実感できる幅で減らせました（削減率は定型文の割合で変わります）。

- **クライアント側ローカルキャッシュ**: ユーザーごとに、最近聞いた100件をローカルファイルに保存します。よく聞く挨拶（「おはよう」「ありがとう」など）はここで受け止めます
- **Cloudflare KV キャッシュ**: テキストの SHA-256 ハッシュをキー、音声 URL を値にして保存します。全員で共有できる定型文（オンボーディングやエラー文言）はここで打ち返します
- **Cloudflare R2 に音声ファイルを保存**: KV にはメタデータだけを置き、音声のバイナリは R2 に TTL 30日で置きます

順序としては、まず KV キャッシュだけを入れて運用し、ヒット率を見ながらローカルキャッシュと R2 を足していくのが安全です。最初から3層を一度に組んだとき、どの層が効いているのか、あるいは古い音声を返しているのかが分からなくなり、手が止まってしまいました。

## 実装後に必ず確認すべき3つのこと

リリース前に確かめておきたい点です。私はここを飛ばしてしまい、公開後に修正版を3回出す羽目になりました。

- **iOS のサイレントモードでも鳴るようにする**: 起動時に `Audio.setAudioModeAsync({ playsInSilentModeIOS: true })` を呼びます。呼ばないとサイレント時に無音になり、「壊れている」というレビューが付きます
- **Bluetooth イヤホン接続時の音切れに備える**: AirPods などでアプリをバックグラウンドにすると、音が止まる場合があります。`staysActiveInBackground: true` を設定します
- **長文は分割して再生する**: 1リクエストは1000文字前後までが安定した範囲でした。Claude の応答が長いときは、句点で区切って順に再生します

手元で確かめるときは、症状から原因を引ける表にしておくと、レビューが届いた日に慌てずに済みます。

## まずは「自分のキャラクター」を1つ作ってみる

ここまで読んでいただいた方には、次のアクションとして「自分のアプリ用に ElevenLabs Voice Design で1つだけキャラクターボイスを作って、Rork のサンプル画面で再生してみる」ところまで進めてみることをおすすめします。実際に音が鳴った瞬間、テキストチャットだけのアプリでは届かなかった層に手が届く感覚が掴めるはずです。

ElevenLabs の Free プランは月30,000文字まで使えるので、まずは無課金でキャラクター1体分の発話を仕込んで、自分のアプリのトップ画面に置いてみてください。声が出た瞬間に、UI に何を足すべきかが一気に見えてきます。
