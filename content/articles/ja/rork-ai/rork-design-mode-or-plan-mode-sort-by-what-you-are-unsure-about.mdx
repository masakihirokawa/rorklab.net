たとえば、手元の壁紙アプリに「お気に入り」だけを集めた画面を足したい、と考えた場面を思い浮かべてみます。やりたいことは決まっています。けれども、入力欄の横のメニューを開くと、Build、Plan、Design の三つが並んでいて、手が止まります。

どれを選んでも、送ったあとに取り返しがつかなくなるわけではありません。それでも、一日に使える数が決まっている無料枠では、最初の一回を「何となく」で選びたくないものです。

先にお伝えしたいのは、選ぶ基準を「機能の名前」ではなく、**いま自分が迷っているものは何か**に置く、ということです。以下は、2026年10月24日時点の公式ドキュメント（Design mode、Plan mode、Plans & Subscriptions の各ページ）に書かれた挙動を読み直し、私なりの線引きに整理したものです。画面の細部は更新されることがありますので、最後は手元の表示でご確認ください。

## 三つのモードが決めてくれるもの

違いは、「どこまで決めてから、コードに進むか」にあります。Design と Plan は、Build を押すまでコードを書きません。

<table>
  <thead>
    <tr><th>モード</th><th>先に決まるもの</th><th>手元に残るもの</th><th>やらないこと</th></tr>
  </thead>
  <tbody>
    <tr><td>Design</td><td>見た目（配色・レイアウト・最初の画面）</td><td>3〜4枚の画面の絵。承認した見た目は <code>.rork/DESIGN.md</code> に保存される</td><td>コードを書かない。絵なので、タップして遷移を試すことはできない</td></tr>
    <tr><td>Plan</td><td>アプリ全体（機能・画面・画面のつながり・「できた」の基準）</td><td>概要・画面・機能・デザイン・フロー・ゴールを持つ読み物の計画。新規なら主要画面の絵も付く</td><td>ファイルを書き換えない（読むだけ）。計画の画面は読み取り専用で、直すときはチャットで頼む</td></tr>
    <tr><td>Build</td><td>決めずにそのまま作る</td><td>動くアプリ</td><td>事前の計画や見た目の案は挟まない。小さな修正や不具合の修正向き</td></tr>
  </tbody>
</table>

二つ補足があります。一つは、同時に入れておけるモードは一つだけだということです。Plan を選ぶと Design が外れ、その逆も同じです。もう一つは、Plan が聞いてくる質問は最大でも二巡で、そのあとは分かっている範囲で計画を書くことです。計画が延々と続く面談になることはありません。

## 三つの問いで選びます

私は、送る前に次の三つを順に自分へ聞いております。

1. 見た目の候補を、まだ一つも持っていないか
2. 機能や画面のつながりを、人に説明できるほど決めていないか
3. 変えたいのは、色や文言のような小さな一点ではないか

一つめが「はい」で、二つめが「いいえ」なら Design です。二つめが「はい」なら Plan です。三つめが「はい」なら、迷わず Build です。

具体的な例を三つ並べます。

  <thead>
    <tr><th>やりたいこと</th><th>迷っているもの</th><th>選ぶモード</th><th>理由</th></tr>
  </thead>
  <tbody>
    <tr><td>手元のアプリに「お気に入り」画面を一枚足す</td><td>ほとんどない（既存の見た目に合わせればよい）</td><td>Build</td><td>範囲が小さく、見た目は既存の画面が決めてくれる。ここで Plan を選ぶと、計画を読む手間のほうが大きい</td></tr>

  </tbody>
</table>

一行目の例は、無料枠で最もやりがちな選び違いを含んでいます。「せっかく新しい機能だから」と Plan を選ぶと、小さな変更に計画の往復が加わるだけです。逆に、三行目の例を Build で始めると、見た目はモデルの判断任せになり、あとから「全体の雰囲気が違う」と直すことになります。

## 無料のまま確かめられるのは、見た目まで

料金のページには、Free プランは Design mode で動き、動くアプリを作る Build mode は有料プランで開く、と書かれています。ここは数字で押さえておきます。

- Free は 1 日 5 クレジットが上限で、月の枠は対象の国で 35、それ以外の地域で 5 です
- Rork Pro は月 20 ドルで 100 クレジット、Build mode と Dev mode が含まれます
- Rork Max は月 200 ドルからで、iPad や Apple Watch、ウィジェットなどが加わります

無料のままできるのは、「見た目を決めて、有料にするかどうかを判断する」ところまでです。Design の画面で Build を押すと、無料アカウントでは「Turn your design into a real app」というプラン選択の画面が開きます。ここまで来て初めて、お金の話になります。

三点、はっきりしないことがありますので、書き残しておきます。

- **Design mode が一回あたりに何クレジット減るか**は、公式のページには書かれていません
- **Plan mode が無料枠で使えるか**も、料金表の記述だけでは判断できません
- 無料アカウントの一部は、最初から Design で始まり、モードのメニュー自体が見えないことがあります

最初の一回だけ、送る前と送った後の残りクレジットを見比べていただけましたら、一日の枠で何回頼めるかが見積もれます。一日 5 クレジットの考え方は、[Rork の無料枠は月35クレジットですが、実際にぶつかるのは1日5という上限のほうです](/articles/rork-basics/rork-free-tier-daily-five-credit-cap-planning)に書き残しました。

## 最初の一通は、「決めたこと」と「決めていないこと」で分けます

どのモードを選んでも、最初のメッセージで見た目を書いておくと、聞かれる質問が減る、と公式のヒントにも書かれています。私は、これを二つの箇条に分けて書いております。

```
【決めたこと】
- 目的: 年配の家族が毎日開く、4択の県名クイズ
- 見た目: 白い背景、文字は大きく、ボタンは指で押しやすい大きさ
- 画面: 問題、結果の二つだけ

【決めていないこと】
- 正解したときの演出
- 成績を残すかどうか
```

「決めていないこと」を明示すると、Rork が質問の形で拾ってくれます。質問のカードでは、色やレイアウトは絵で選べます。「Surprise me」を選ぶと Rork に任せられますし、「Other...」に自分の言葉を書くこともできます。意見のないところは任せ、気になるところだけ言葉にします。この割り切りが、一日の枠を守ってくれるのです。

## 決めたあとに、確かめておきたいこと

Design から Build へ進んだあとも、見た目の決定は消えません。承認した配色・書体・画面の判断は <code>.rork/DESIGN.md</code> に保存され、あとの変更でも読み直されます。見たい場合は、More の Code から <code>.rork</code> フォルダを開きます。ただし、できあがるのは絵の写しではなく本物のコードです。プレビューで動かして、違うところは通常どおり頼み直します。

画面が少なすぎて Build が押せないときは、Review Design のカードに「Try design again」が出ます。最初の案は 3〜4 枚なので、足りない画面は Build のあとでチャットから頼む前提で考えておくと、慌てません。

Build のあとで「やはり戻したい」と感じた日の手順は、[Rork の AI が直した場所の隣が壊れたとき、Undo・Revert・メッセージ編集のどれで戻るかを先に決めます](/articles/rork-ai/rork-undo-revert-edit-message-choosing-the-way-back)に書き残しました。

## 次に試していただきたいこと

送信の前に、紙の端でも構いません、「決めたこと」と「決めていないこと」を二行ずつ書いてみてください。決めていないことのほうが多ければ Plan、見た目だけなら Design、一点だけなら Build です。

私自身、画面を作る前に迷っているものの名前を書き出すだけで、手が動き出す日が少なくありません。**迷いの名前が分かれば、モードはほとんど決まっています**。この線引きは、クレジットが十分にある日でも、守っていきたいと感じています。
