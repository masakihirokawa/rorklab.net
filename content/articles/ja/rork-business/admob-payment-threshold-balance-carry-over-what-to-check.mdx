月初の朝、AdMobの「お支払い」ページを開くと、残高の欄には数千円が並んだまま、口座には何も入っていませんでした。広告を載せて三か月目の小さなアプリです。画面を閉じたあとも、「届かないまま半年過ぎたら、この残高はなくなるのだろうか」という問いが頭から離れませんでした。

同じ画面の前で手が止まっている方は、少なくないと思います。個人開発の小さなアプリほど、基準額までの道のりは長くなりがちです。ここでは、思い込みではなくGoogleのAdMobヘルプに書かれている内容だけを根拠に、残高がどう扱われるのか、そして本当に入金を止めるのは何なのかを整理します。

最初にお伝えしたいのは、**基準額に届かないこと自体で残高が消えることはない**という点です。そのうえで気をつけたいのは、残高ではなく「手続きの期限」と「配信の止まったアカウント」のほうです。

## 結論：基準額に届かない月の残高は、翌月に持ち越されます

AdMobのヘルプ「Payments and transactions」には、月の収益が支払い基準額に届かなかった場合、その収益は**翌月の収益と合算して繰り越される**と書かれています。合算した残高が基準額を超えれば、まとめて1回で支払われます。

日本円で報告しているアカウントの支払い基準額は **8,000円** です（米ドルのアカウントは100ドル）。基準額はアカウントの「報告通貨」ごとに決まっていて、ヘルプ「Payment thresholds」の通貨別の表で確認できます。

ここで一つ、取り違えやすい点があります。基準額の判定に使われるのは、ホーム画面に出る推定収益ではありません。ヘルプには「すべてのしきい値は、推定収益ではなくお支払い履歴（Payments）ページに基づく」と明記されています。推定収益が8,000円を超えた月にまだ入金がないのは、多くの場合この差によるものです。

## 支払いが実行されるまでの月のカレンダー

支払いは月次で回ります。銀行振込（EFT）を選んだ場合の目安は、ヘルプに次のように書かれています。

<tr><th>時期</th><th>起きること</th><th>自分がやること</th></tr>

<tbody>
<tr><td>毎月3日ごろ</td><td>前月の推定収益が確定し、「お支払い」の取引履歴に計上されます。無効なトラフィックの調整もこの時点で反映されます</td><td>確定額を確認します</td></tr>
<tr><td>毎月20日</td><td>この日までの変更（支払い保留の解除を含む）だけが当月の支払いに反映されます。20日時点の残高が基準額に達していることが条件です</td><td>保留の有無と残高を確認します</td></tr>

着金のタイミングは、タイムゾーン、21日が週末や祝日に当たるかどうか、選んだ支払い方法によって前後するとされています。20日を過ぎてから保留を解除した場合、その変更は翌月の支払いサイクルに回ります。

私自身は、このカレンダーを覚えるまで、毎週のように残高を見に行っておりました。見るたびに数字が動かないことに胃が痛くなり、何かを見落としているのではと設定画面を行き来していたのです。不安の正体は残高の少なさではなく、いつ何が起きるのかを知らないことのほうだったのだと気づいたのは、このカレンダーを紙に書き出してからでした。いまは**月に二度、3日と20日だけ「お支払い」ページを開く**ことにしています。確定額を見る日と、保留を確かめる日です。それ以外の日に見ても、判断できることはほとんどありません。

## 基準額は1つではありません — 4種類のしきい値

「基準額」と一口に言っても、ヘルプには役割の違うしきい値が並んでいます。日本円アカウントの値を、2026年11月時点のヘルプの表から抜き出しました。

<table>
<thead>
<tr><th>しきい値</th><th>日本円アカウントの値</th><th>届いたときに起きること</th></tr>
</thead>
<tbody>
<tr><td>確認（本人確認／住所確認）</td><td>$0／$10相当</td><td>本人確認と住所確認（PIN）が求められます</td></tr>
<tr><td>支払い方法の選択</td><td>1,000円</td><td>振込先などの支払い方法を登録できるようになります</td></tr>
<tr><td>支払い</td><td>8,000円</td><td>保留がなければ、その月の21日前後に支払われます</td></tr>
<tr><td>解約</td><td>1,000円</td><td>解約時、これを超えていれば最終支払いの対象になります</td></tr>
</tbody>

支払い方法の選択に1,000円のしきい値があるのは、基準額に届かない額では支払いを行わないため、それまでは支払い方法を選ばせない、という理由だとヘルプは説明しています。「振込先を登録しようとしたのに項目が出てこない」という場面は、たいていこれかもしれません。

## よくある誤解を3つ、ヘルプの記載で訂正します

**誤解1：「推定収益が8,000円を超えたら、その月に入金される」**
判定は「お支払い」ページの確定済み残高で行われます。たとえば11月に推定で8,000円を超えても、確定するのは12月3日ごろで、支払いは12月21日前後になります。

**誤解2：「残高が少ないまま放置すると、残高だけが失効する」**
基準額未満の残高は繰り越されます。消えるかどうかを分けるのは残高の大きさではなく、後で触れる「6か月の無配信」と「解約時の条件」です。

**誤解3：「アカウントが無効化されたら、残っていた収益は受け取れない」**
ヘルプ「About deactivated AdMob accounts」には、無効化されたアカウントでも、再有効化するか、関連付けられたAdSenseアカウントから未払いの収益にアクセスできると書かれています。ただし、最終支払いを受けるための条件を満たしていることが前提です。

どの保留も、「お支払い」ページのアラートをクリックすると、解除に必要な手順が表示されます。ヘルプによれば、通常のサイクルで保留により支払われなかった残高は、保留を解除してから数日以内に支払われます。

## 住所確認（PIN）には4か月の期限があります

切り分け表のなかで、いちばん見落としやすいのがPINです。仕組みはヘルプ「Address verification (PIN) overview」に、次の順で書かれています。

1. 収益が確認のしきい値に届くと、6桁のPINが記載された郵便物が、支払い先の住所へ普通郵便で送られます（追跡番号はありません）
2. 本人確認を求められている場合は、本人確認が済むまでPINは送られません
3. 届くまでの目安は約3週間です。届かなければ再発行を依頼できます
4. **PINが発行されてから4か月以内**に住所確認を完了する必要があります

見落とされがちなのは、期限を過ぎたときの扱いです。ヘルプには、4か月以内に住所確認が済まない場合、**広告の表示が止まる**と書かれています。残高が消えるのではなく、収益を生む配信そのものが止まるのです。小さなアプリほど郵便物は「急ぎではないもの」に見えてしまうので、届いた日に入力してしまうのがいちばん確実です。

## 本当に注意したいのは、残高ではなく「配信が止まったアカウント」です

繰り越しは保証されていても、アカウント自体が無効になると話が変わります。ヘルプ「About deactivated AdMob accounts」には、**6か月間まったく広告を配信していないAdMobアカウントは無効化される**と書かれています。ここで言うのは「収益が少ない」ではなく「配信がゼロ」の状態です。

無効化されたアカウントは、次の手順で再有効化できると案内されています。

1. AdMobにサインインし、再承認を希望するチェックボックスにチェックを入れます
2. 「アカウントを再有効化」をクリックします
3. 電話番号を認証します

その後、アカウントの確認が行われ、通常は24時間以内に終わるとされています。以前にPINで住所確認を済ませていれば、PINをやり直す必要はありません。ただし、アプリの配信を再開するには、あらためてアプリの審査（app readiness review）に出す必要があり、それまでアプリは「要審査」の状態になります。

## 解約する前に確かめる条件

更新を止めたアプリのためにアカウントごと解約する場合は、さらに条件があります。ヘルプ「Cancel your AdMob account」によると、AdSenseを使っていない場合、最終支払いを受けるには次のすべてが必要です。

- 残高が解約のしきい値（日本円は1,000円）を超えていること
- 支払い方法の選択、本人確認、住所と受取人名の確認など、支払いを受けるための手続きが済んでいること
- 支払い保留が解消されていること

条件を満たさないまま解約を進めると、残りの収益が支払われないことを理解した、というチェックボックスへの同意を求められます。条件を満たしていれば、最終支払いは月末からおおむね90日以内とされています。なお、無配信で無効化されたアカウントは、解約の前にまず再有効化が必要です。関連付けたAdSenseアカウントを使い続けている場合は、AdMobの最終支払いはAdSenseの残高に移されます。

## 3つの道の比較と、どれを選ぶか

基準額まで遠いアプリを前にしたとき、選べる道はおおむね次の3つです。

<table>
<thead>
<tr><th>選択</th><th>残高の扱い</th><th>気をつけること</th><th>向いている場面</th></tr>
</thead>
<tbody>
<tr><td>配信を続けて待つ</td><td>毎月繰り越され、基準額に届いた月に支払われます</td><td>PINの4か月期限だけは先に済ませます</td><td>少しでも配信が続いているアプリ</td></tr>
<tr><td>更新を止めて放置する</td><td>配信が6か月ゼロになると無効化されます</td><td>再有効化と再審査の手間が残ります</td><td>近いうちに作り直す予定があるアプリ</td></tr>
<tr><td>アカウントを解約する</td><td>条件を満たせば、1,000円を超える残高が最終支払いされます</td><td>支払い条件を満たす前に解約すると受け取れません</td><td>今後AdMobを使う予定がまったくない場合</td></tr>
</tbody>
</table>

判断の一文にまとめるなら、**ほかのアプリで配信が続いているなら待つ、AdMobを完全にやめるときだけ、支払い条件を揃えてから解約する**、です。同じアカウントに複数のアプリを載せていれば、1本の更新を止めても、ほかのアプリの配信がある限り6か月の無配信には当たりません。

## 到達月を見積もるスクリプト

「あと何か月で8,000円に届くのか」を、確定済み残高から見積もる小さな計算です。PINの期限と並べて表示するようにしました。

```python
import math
from datetime import date

THRESHOLD_JPY = 8000      # 日本円アカウントの支払い基準額（2026年11月時点のヘルプ記載値）
PIN_DEADLINE_MONTHS = 4   # PIN 発行から住所確認までの期限

def add_months(d: date, months: int) -> date:
    y, m = divmod(d.month - 1 + months, 12)
    return date(d.year + y, m + 1, 1)

def payout_plan(confirmed_balance: int, monthly_confirmed: int, today: date,
                pin_issued: date | None = None) -> dict:
    """確定済み残高と毎月の確定額から、支払いが見込める月を返す。"""
    if monthly_confirmed <= 0:
        raise ValueError("毎月の確定額が0以下だと基準額に届きません")
    remaining = max(THRESHOLD_JPY - confirmed_balance, 0)
    months = math.ceil(remaining / monthly_confirmed)
    # 確定は翌月3日ごろ、支払いはその月の21日前後
    payout_month = add_months(today, months + 1)
    plan = {"months_to_threshold": months,
            "expected_payout": f"{payout_month:%Y-%m} の21日前後"}
    if pin_issued:
        plan["pin_deadline"] = f"{add_months(pin_issued, PIN_DEADLINE_MONTHS):%Y-%m} ごろまで"
    return plan

print(payout_plan(2300, 600, date(2026, 11, 25), pin_issued=date(2026, 10, 10)))
```

Python 3.10 以降で実行すると、次のように出力されます。

```text
{'months_to_threshold': 10, 'expected_payout': '2027-10 の21日前後', 'pin_deadline': '2027-02 ごろまで'}
```

この例では、基準額に届くまで10か月かかる一方、PINの期限はその半分以下で来ます。**支払いより先に期限が来るのはPINのほう**だということが、数字で並べるとはっきりします。確定残高には、必ず「お支払い」ページの金額を入れてください。月単位で丸めているので、PIN期限は目安として読み、正確な日付は管理画面で確かめます。

## 次に詰まりやすいところ

基準額に届いて最初の支払いが近づくと、次は「毎月の収益そのものが伸びない」という問題に向き合うことになります。その月の単価が下がったのか、国の構成が変わっただけなのかを切り分ける考え方は、[eCPM が下がった月の広告収益を、国の構成と単価に切り分けます](/articles/rork-business/admob-blended-ecpm-mix-rate-decomposition-country-shift)にまとめました。広告だけで続けるか、課金と組み合わせるかで迷っている場合は、[Rork アプリの収益モデル比較 — 広告・サブスク・買い切りを実運用の数字で選ぶ](/articles/rork-business/rork-app-revenue-model-comparison-ads-subscription-onetime)も判断の材料になると思います。
