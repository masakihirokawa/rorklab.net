月初になると、ストアの管理画面から売上の CSV を落として、表計算ソフトに貼る作業が待っています。アプリが一本なら、それで足ります。ところが本数が増えると、ストアごとに列の名前も日付の書き方も違うことが、じわじわと効いてきます。

ある月、貼り付けた合計と、ストアの画面に出ている合計が合いませんでした。差は小さく、どこで消えたのか見当がつきません。結局、返金の行を「マイナスだから」と手で除いていたことが原因でした。**合っているかどうかを確かめる手段を持たないまま足し算をすると、間違いは数字の見た目だけでは分かりません。**

その反省から組んだ集計の手順を、ここに書き残します。ストアごとの CSV を共通の4列に寄せ、月末の為替で円に直し、元の通貨のままの合計を並べて突き合わせるところまでです。ストアの CSV の列名は変わることがあるので、スクリプトの中身は「あなたの手元の CSV を開いて書き換える」前提にしています。

## 共通の4列に寄せる、という割り切り

集計に必要なのは、突き詰めると四つだけです。いつ（月）、どのアプリか、いくらか、何の通貨か。ストアの CSV にはほかにも多くの列がありますが、月別・アプリ別の収益を知るだけなら、この四つで足ります。

寄せ方は単純です。ストアごとに「うちの CSV では、日付はこの列、アプリ名はこの列」という対応表を持ちます。新しいストアを足すときは、対応表に1行足すだけです。

<table>
<thead>
<tr><th>共通の列</th><th>寄せるときの注意</th></tr>
</thead>
<tbody>
<tr><td>月</td><td>日付の先頭7文字だけ使います。<code>2026/09/05</code> と <code>2026-09-05</code> の両方を <code>2026-09</code> にそろえます</td></tr>
<tr><td>アプリ</td><td>ストアによって表示名が違うことがあります。違うなら対応表で名前を寄せます</td></tr>
<tr><td>金額</td><td>桁区切りのカンマを外し、浮動小数点でなく <code>Decimal</code> で持ちます。返金はマイナスのまま残します</td></tr>
<tr><td>通貨</td><td>大文字にそろえます。小文字で入っている CSV がありました</td></tr>
</tbody>
</table>

金額を <code>Decimal</code> で持つのは、円に直したあとの端数が、月ごとにずれていくのを避けるためです。数十行なら誤差は目に見えませんが、あとで「合わない」と気づいたときに原因が追えなくなります。

## スクリプト全体

次のスクリプトを `merge_sales.py` という名前で置きます。これは、列名の対応表と、為替の固定値を渡すだけで動くように作ってあります。**`MAPPING` の列名は例です。** 手元の CSV の1行目を見て、そのまま書き換えてください。

```python
"""store ごとに形式の違う売上 CSV を共通 4 列に寄せ、アプリ別・月別に集計する。"""
import csv, sys, json
from collections import defaultdict
from decimal import Decimal, InvalidOperation

# store ごとの列名の対応は、手元の CSV を開いて自分で書き換える（ここは例）
MAPPING = {
    "storeA": {"date": "Date", "app": "App", "amount": "Net", "currency": "Cur"},
    "storeB": {"date": "Order Charged Date", "app": "Product", "amount": "Payout", "currency": "Currency"},
}

def load(path, store):
    m = MAPPING[store]
    rows, bad = [], []
    with open(path, newline="", encoding="utf-8-sig") as f:
        for n, r in enumerate(csv.DictReader(f), start=2):
            try:
                rows.append({
                    "month": r[m["date"]].strip()[:7].replace("/", "-"),
                    "app": r[m["app"]].strip(),
                    "amount": Decimal(r[m["amount"]].replace(",", "")),
                    "currency": r[m["currency"]].strip().upper(),
                    "store": store,
                })
            except (KeyError, InvalidOperation) as e:
                bad.append((path, n, repr(e)))   # 黙って捨てず、行番号ごと残す
    return rows, bad

def main(rates_path, *pairs):
    rates = json.load(open(rates_path))          # {"2026-09": {"USD": "150.0", "JPY": "1"}}
    totals, raw_sum, bad_all = defaultdict(Decimal), defaultdict(Decimal), []
    for p in pairs:
        store, path = p.split("=", 1)
        rows, bad = load(path, store)
        bad_all += bad
        for r in rows:
            rate = Decimal(rates[r["month"]][r["currency"]])   # 無ければ KeyError で止める
            totals[(r["month"], r["app"])] += r["amount"] * rate
            raw_sum[(store, r["currency"])] += r["amount"]
    for (month, app), v in sorted(totals.items()):
        print(f"{month}  {app:<12} {v:>12,.0f} JPY")
    print("-- 元通貨のままの合計（ストア別・突き合わせ用）")
    for (store, cur), v in sorted(raw_sum.items()):
        print(f"{store}  {cur}  {v}")
    print(f"-- 読めなかった行: {len(bad_all)}")
    for b in bad_all: print("  ", *b)

if __name__ == "__main__":
    main(*sys.argv[1:])
```

為替の固定値は、月ごとに1本の JSON にまとめます。取引日ごとに変えず、月末の1回だけ決める理由は、このあと書きます。

```json
{"2026-09": {"USD": "150", "JPY": "1"}}
```

走らせるときは、為替の JSON と、「ストア名=CSV のパス」の組を渡します。

```bash
python3 merge_sales.py rates.json storeA=a.csv storeB=b.csv
```

## 小さなサンプルで、実際に走らせた結果

仕組みを確かめるため、わざと癖をつけた2本のサンプル CSV で走らせました。1本目は円建てで、返金（マイナス）の行と桁区切りのカンマを含みます。2本目はドル建てで、日付がスラッシュ区切り、通貨が小文字、1行だけ金額が読めない文字列です。為替は 1 ドル = 150 円としました。実際の収益ではなく、動作を見るためのダミーの値です。

```text
2026-09  Heal                1,888 JPY
2026-09  Wall                2,775 JPY
-- 元通貨のままの合計（ストア別・突き合わせ用）
storeA  JPY  1700
storeB  USD  19.75
-- 読めなかった行: 1
   b.csv 4 InvalidOperation([<class 'decimal.ConversionSyntax'>])
```

計算を確かめます。Wall は円建ての 1,200 円と返金の −300 円で 900 円、ドル建ての 12.50 ドルが 1,875 円で、合計 2,775 円。Heal は 800 円と 7.25 ドル（1,087.5 円）で 1,887.5 円です。表示が 1,888 になっているのは、`{:,.0f}` が小数点以下を丸めて見せているためで、中身は端数のまま持っています。

そして、4行目の `abc` が「読めなかった行」として行番号つきで出ています。ここが、このスクリプトで一番大事にしている部分です。

## 直感に反していたのは、「エラーなく終わる」ことが安全ではない点でした

最初に書いた版は、読めない行を `except: continue` で飛ばしていました。見た目はきれいで、エラーも出ません。ところがその月、ストアの画面の合計との差が出て、数日かけて探すことになりました。

読めない行を飛ばすスクリプトは、「合っていない」ことを教えてくれません。そこで次の三つを決めました。

<table>
<thead>
<tr><th>状況</th><th>この作りでの扱い</th><th>理由</th></tr>
</thead>
<tbody>
<tr><td>金額が数値として読めない</td><td>捨てずに行番号つきで一覧に出す</td><td>どの行が漏れたかを、あとから探さずに済みます</td></tr>
<tr><td>その月・その通貨の為替が JSON に無い</td><td><code>KeyError</code> で止める</td><td>0 円として黙って足すより、止まる方が間違いに気づけます</td></tr>
<tr><td>返金のマイナス行</td><td>除かず、そのまま足す</td><td>手で除いた月に、画面の合計と合わなくなりました</td></tr>
</tbody>
</table>

## 元通貨のままの合計を、必ず並べて出す

円に直した合計は、為替の値を変えれば変わってしまいます。ストアの画面に出ている合計とは、そのままでは比べられません。

そこで、ストア別・通貨別に、為替を掛けない合計も一緒に出しています。上の出力の `storeA JPY 1700` と `storeB USD 19.75` です。この数字は、ストアの管理画面に出ている同じ期間の合計と、そのまま見比べられます。

サンプルで確かめると、円建ては 1,200 − 300 + 800 = 1,700。ドル建ては 12.50 + 7.25 = 19.75。後者は、読めなかった 1 行（`abc`）を除いた合計です。画面側の合計がこの行を含んでいれば、差の 1 行が見つかります。**円に直したあとの数字は、元通貨の合計が合ったあとで見るもの**、と順番を決めると、間違いの置き場所がはっきりします。

## 為替は月末の1回で固定し、取引日ごとには変えません

取引日ごとの為替で換算すると、一見すると正確です。ただ、取引日のレートを集めて貼る作業が、そのまま月初の手間になります。

個人開発で数本のアプリを運用する範囲では、「その月の為替は1つ」と決めて JSON に1回書く方が、私には続きました。正確さは多少落ちますが、毎月同じ手順で締められるからです。**続かない精密さより、続く簡素さを選ぶ、という線引きです。** ここで出る円建ての数字は、月ごとの運用の目安を得るためのものと割り切っています。

## 月初に、これだけやります

月初の手順は短く保てるようにしています。

1. 各ストアの管理画面から前月分の CSV を落とします
2. 月末の為替を `rates.json` に1行足します
3. スクリプトを走らせ、「読めなかった行」が 0 件であることを見ます
4. 元通貨の合計を、ストアの画面の合計と見比べます
5. 合っていれば、円建ての表を記録に写します

3 と 4 のどちらかで引っかかったら、5 には進みません。この順番を崩さなければ、数字を写してから間違いに気づく、ということが起きにくくなります。

## 判断のおまけ: Rork で作ったアプリの収益を、別の場所と混ぜないこと

私が収益の記録を作るときは、課金や広告の収益と、開発側にかかる月額の費用は、別の表に分けています。Rork 側のクレジットの残高も、収益とは別に見る必要があります（[クレジットの残高が別々にある件](/articles/rork-business/rork-build-credits-cloud-credits-separate-balances-check)）。1年目に何にいくらかかるかの並べ方は、[初年度の請求を支払い順に並べた記事](/articles/rork-business/rork-first-year-bill-order-apple-google-eas-supabase-timeline)も参考にしてください。

## 今日、手元でやっておくこと

- 手元の CSV を1本ずつ開き、日付・アプリ・金額・通貨の列名を、`MAPPING` に書き写してみてください
- 先月分のストア画面の合計を控えておくと、初回の突き合わせがすぐできます
- 読めなかった行が出たら、捨てずに、その行を目で見てください。多くの場合、原因は列名のずれか、桁区切りの記号です

数字を足す作業は地味ですが、間違いがあとから見つかるほど、手間は大きくなります。月初に5分、確かめる習慣を持てると、気持ちが軽くなると感じています。
