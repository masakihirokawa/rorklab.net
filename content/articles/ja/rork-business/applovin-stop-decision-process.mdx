5 月 26 日の昼に AdMob の管理画面を開いて、AppLovin と AppLovinMax の Bidding ソースと Waterfall ソースを、私の iOS/Android アプリ 5 本すべてで Pause しました。INT・RWD・RWI の 3 フォーマット。月収にして約 $730 が止まります。

廣川政樹です。2014 年から個人開発で iOS/Android アプリを続けていて、累計で 5,000 万 DL を超えています。AppLovin は 2022 年に主要アプリすべてに統合した広告パートナーで、月収 100 万円超を支えてきた SDK の一つでした。それを切る判断に至るまでの 3 つの証拠と、停止後 4 週間の評価設計を、この記事で公開します。

「収益化を AdMob だけでなく複数ネットワークで回しているが、たまにユーザー離れと収益のどちらを取るかで迷う」「ユーザーから『閉じられない広告』『報酬が付かない』のフィードバックがあるがどう判断していいか分からない」「収益が下がっても切るべきネットワークの見極め方を体系化したい」あたりで悩んでいる方を想定読者にしています。

## 月 $730 を捨てる判断に必要だった 3 つの証拠

「お金を捨てる方の判断」は、感覚や疑いだけでは決められません。私が AppLovin 全停止に踏み切るために集めた証拠は 3 つです。どれも単独では決定打にならないものを、3 つ揃えることで判断が確定しました。

### 証拠 1 — AppDiscovery の異常な広告品質指標

AppLovin には 2 つのダッシュボードがあります。Publisher 側で広告を表示するための AppLovin MAX と、Advertiser 側で「他アプリに自分のアプリの広告を出す」AppDiscovery。多くの開発者は MAX しか見ません。AppDiscovery の存在を私が把握したのも、調査の途中でした。

AppDiscovery の過去 30 日（2026-04-27〜05-26）の配信実績がこれです。

```text
アプリ                      Platform  Imp      Click    CTR      Rev       eCPM    RPC
Beautiful HD Wallpapers     iOS       190,352  16,272   8.56%    $618.70   $3.25   $0.038
Beautiful 4K/HDR Wallpapers Android    84,218  10,981   13.04%   $101.53   $1.21   $0.0092
Relaxing Healing            iOS        16,357      29   0.18%    $0.16     $0.01   —
Law of Attraction Everyday  iOS        15,017      96   0.64%    $0.55     $0.04   —
Ukiyo-e Wallpapers          Android     8,986     644   7.17%    $9.10     $1.01   $0.014
Ukiyo-e Wallpapers          iOS         1,996      35   1.75%    $0.12     $0.06   —
合計                                  316,926  28,057   8.86%    $730.15   $2.30   —
```

ここで注目したのは Beautiful 4K/HDR Wallpapers (Android) の行。**CTR 13.04% × RPC $0.0092 × eCPM $1.21**。

健全な広告配信の範囲は、CTR が 2〜5%、RPC（クリックあたり収益）が $0.10〜$0.50 です。CTR 13% は健全範囲の 2.5〜6 倍。RPC $0.0092 は健全範囲の 1/10〜1/50。**「クリックは大量に発生するが、install には繋がらず、実収益は微々たるもの」** という、誤タップ・misleading クリックの典型パターン。

AppLovin Network は CPI 課金（インストール課金）が中心なので、click が install に転換しないと収益化されません。CTR が異常に高く RPC が異常に低いという 2 軸の同時異常は、「閉じられない広告 → 誤タップ → install には繋がらない」という UX 問題のシグナルそのものです。

### 証拠 2 — ユーザー直接観察

AppLovin の RWD（リワード動画広告）をテストモードで自分のアプリ内で再生したとき、視聴完了後に「クリック以外の選択肢がない」「報酬も付与されない」挙動を確認しました。

通常 RWD の opt-in 安全性の前提は次の 2 つです。

- 視聴完了したら報酬が確実に付与される
- 視聴後に閉じる導線が明確に提供される

両方破綻していました。これは INT より UX 損失が深刻です。

- **INT の「閉じられない」**: 「邪魔だな」と思って閉じるだけ。軽い不満
- **RWD の「報酬不付与」**: 「時間を払ったのに対価がない」。**契約違反による深い不信感**

ユーザーがアプリを開いて「報酬のために動画を見る」と能動的に選んだ後にこれが起きると、二度と RWD を見ない、もしくはアプリ自体を消すモチベーションが生まれます。

### 証拠 3 — 11 年クラッシュトレンドの時系列パターン

ここが決定打でした。App Store Connect の Analytics には、アプリの月別クラッシュ数を 2015 年以降の全期間で見られるグラフがあります。私の主要 5 アプリすべてで、グラフを 11 年スパンで開いてみました。

```text
アプリ                       App ID    累計クラッシュ  2022年ピーク  ベースライン  倍率
Beautiful 4K/HDR Wallpapers  706533906  224,148        8,500/月    1,000/月    8倍
Law of Attraction Everyday   841157677  7,360          350/月      100/月      3.5倍
Relaxing Healing             694492667  8,602          325/月      100/月      3.3倍
Ukiyo-e Wallpapers           835559799  2,380          125/月      50/月       2.5倍
旧 BW (632379876)            632379876  1,236          50/月       20/月       2.5倍
```

5 アプリすべてが、**2022 年（AppLovin を主要アプリに導入した時期）に明確なクラッシュスパイクを示しています**。BW 4K/HDR は 8 倍、他は 2.5〜3.5 倍。さらに、2023 年以降も完全にはベースラインに戻らず、**2〜3 倍水準で慢性化**。

ここで重要な観察が 3 つあります。

- **時系列パターンが 5 アプリで共通** → アプリ固有のバグではない（私の側のコード起因なら、各アプリの実装は別なので 5 アプリ同時に同じパターンを描かない）
- **段階的悪化ではなく特定時点での突発スパイク** → 環境変化（OS アップデートやデバイス世代交代）では説明できない
- **慢性化** → 一過性の SDK バグではなく、SDK 由来の構造的影響の可能性

偶然で説明できる相関ではありません。

## 「直すまでもなく切る」と判断する分岐点

「ユーザーが離れている」というシグナルを掴んだ時、選択肢は大きく 2 つあります。

- **A**: SDK を直してもらうために待つ／自分の側のコードで回避する
- **B**: SDK そのものを切る

通常はまず A から試します。InMobi や Liftoff のようなネットワークで個別の不具合が出たとき、私は SDK 更新を待ったり、メディエーションの優先順位を下げたりして対応してきました。今回 B に踏み切った理由は、上の 3 つの証拠から **「個別不具合ではなく構造的問題」** と判断したからです。

具体的には次の論理。

- 証拠 1（CTR 13% / RPC $0.0092）が示すのは「クリエイティブの品質」問題
- 証拠 2（報酬不付与）が示すのは「contract 問題」（広告サービスとしての約束破り）
- 証拠 3（11 年クラッシュトレンド）が示すのは「SDK 由来の構造的影響」

3 つが独立した側面で異常を示している以上、単発の修正待ちで治る種類のものではない、という判断です。

「直しを待つ」モードに留まっている間、毎月数百ドルの売上のために、ユーザーが沈黙離脱しているのを見ているのと同じ状態になります。私はこの状態を 6 ヶ月続けてしまっていました。気づいた時の判断は速いほどよい、というのが今回の学びです。

## 停止のスコープ — INT/RWD/RWI で AOA/BNR を残した理由

全停止と書きましたが、実際には INT・RWD・RWI の 3 フォーマットだけです。AOA（App Open Ad）と BNR（バナー）は触りませんでした。判断の根拠を整理しておきます。

- **INT** — 「閉じられない」UX 問題の主因、CTR 13% 異常の本丸。これは停止確実
- **RWD** — ユーザー観察で「報酬不付与」を確認、契約違反級。停止確実
- **RWI** — RWD と同じ AppLovin demand なので同じリスク。停止確実
- **AOA** — AppLovin が AOA waterfall に**そもそも非対応**。AdMob が選択肢に出さない。触りようがない
- **BNR** — 「閉じる」概念がなく UX 損失なし。click 力学が INT/RWD と別

…と最初は判断したのですが、その後追加で BNR も停止しました。理由は「クラッシュ寄与の可能性 + 実験信号のクリーン化」。停止後 4 週間でクラッシュ率の改善を測定する以上、AppLovin 関与の経路は 1 つでも少ないほうが因果関係を切り出しやすくなります。BNR の収益寄与は元々小さく、止めても影響軽微。実験設計のクリーンさを優先しました。

停止操作は AdMob → メディエーション → 各グループの Bidding sources + Waterfall sources で AppLovin / AppLovinMax を **Pause**。削除ではなく Pause なのは、判定で「復元」になった時に元の eCPM / 設定を保持しておくためです。

## 4 週間の評価設計

停止して終わりではなく、4 週間後に判定を下します。評価軸は重要度順に 5 つ。

1. **クラッシュ率変化（最優先）** — Firebase Crashlytics + Play Console Vitals + App Store Connect Crashes。改善判定: クラッシュフリーユーザー率 +0.3pt 以上、または広告 SDK 由来 issue 数の顕著な減少
2. **リテンション変化** — D1 / D7 / D30 を停止前 4 週間 vs 停止後 4 週間で比較。有意判定: +1pt 以上
3. **レビュー流入の質的変化** — 「広告」「閉じ」「報酬」「うざい」「ad」「reward」「crash」「落ちる」を含むレビュー件数比較
4. **収益影響** — 総収益、ネットワーク別シェア変化
5. **広告 click あたりの収益化効率** — INT 全体 CTR / RPC / eCPM の前後比較

判定とアクションのマトリクスは下記です。

- **クラッシュ率改善 + リテンション改善 + 損失許容** → 緑（停止永続化）。AppLovin Adapter SDK 完全削除を検討
- **クラッシュ率改善のみ（リテンション変化なし）** → 緑（停止継続）。クラッシュ低減だけでも価値あり、$700/月損失も許容
- **リテンション改善 + クラッシュ変化なし** → 黄（継続観察）。別の AppLovin 要因（UX）として継続、Adapter 残置で監視
- **リテンション変化なし + 収益損失あり** → 赤（部分復元）。旧 BW iOS（最大収益源）のみ復元
- **クラッシュ率悪化** → 赤（緊急復元）。即座に全復元、原因再調査

ここで重要な caveat があります。BW v2.1.1 / UE v1.8.1 のホットフィックスリリースが**停止翌日（2026-05-27）**に予定されていました。クラッシュ率の改善が AppLovin 停止由来か、リリース由来かの切り分けが必要です。

具体的には、リリースで明確に潰したバグ（BW-017 の ViewPager2 fling 中 IOOBE で 74.4% 寄与、BW-027 の Glide 同期デコード ANR など）の Crashlytics 上での減少分は、AppLovin 停止の効果から引き算します。Firebase Crashlytics の issue 別フィルタで `applovin` を含む issue を別途集計し、それだけを AppLovin 効果として測定する、というのが切り分けの方法です。

## Day 1 の観察 — 33% eCPM 下落と「焦らない」判断

停止当日（2026-05-26）の観察。

- AdMob 全体 eCPM: $1.81 → $1.20（約 33% 下落）
- 他ネットワーク（Meta, AdMob Network, Liftoff, Mintegral）の学習に 3〜5 日かかる見込み
- 1 日データはノイズが大きいため、判断は早計

ビダーが 1 つ消えると auction の競争数が減るので、瞬間的に eCPM が下がるのは予想通り。Meta や AdMob Network の自動最適化が空いた枠を取りに来るまで数日かかるので、ここで焦って何かを変えると実験信号が崩れます。**「3〜5 日観察、追加変更なし」を方針に固定**しました。

補填策として 1 つだけ AdMob の設定を触りました。

- **完全な IP アドレスを共有: オフ → オン**（eCPM +5〜15% を見込む）
- **プログラマティック制限付き広告: オン → オン（維持）**（OFF にすると逆に収益機会喪失と判明）

最後の項目は罠で、説明文を読むと「Google デマンド・認定バイヤー・SDK 入札からのデマンドにも対応できる」とあるので OFF にすると逆効果。SaaS の設定画面の説明はちゃんと全部読む、というのも収益化の地味な基本です。

## 損失予想の修正

旧 BW iOS（Beautiful HD Wallpapers 20,000+、別バイナリ・旧デバイス中心）は最大収益源（月 $618）でしたが、停止対象から除外しました。理由は「かなり古いアプリでユーザーコホートが異なる」「他 4 アプリの実験信号に影響しない」の 2 つ。

その結果、損失予想は次のように修正されました。

- **旧推定（旧 BW 含む）**: 月間 $730 / 1 週間 $170 / 4 週間 $683
- **新推定（旧 BW 除外）**: 月間 約 $111 / 1 週間 約 $26 / 4 週間 約 $104

月 $100 強の損失なら、4 週間後の判定でクラッシュ率改善が見えなくても痛みは限定的。逆にクラッシュ率が +0.3pt 動けば、累計 5,000 万 DL に対するインパクトはずっと大きい。リスクリターンが明確に立ち、Pause ボタンを押せました。

## 個人開発者がこの判断を再現するための最小手順

ここまでの工程を、別の個人開発者が同じネットワーク（または別ネットワーク）の停止判断に応用するなら、こういう順序になります。

- 該当ネットワークの Publisher 側ダッシュボードだけでなく Advertiser 側もチェックする（AppLovin なら MAX と AppDiscovery）
- CTR / RPC / eCPM の 3 つを健全範囲（CTR 2〜5% / RPC $0.10〜$0.50）と比較し、異常値があれば仮説化
- ユーザー観察（テストモードで自分のアプリ内で広告を実際に再生し、UX を体験）
- App Store Connect Analytics でクラッシュトレンドを月別 11 年スパン（あるいは導入以降全期間）で見る。SDK 導入時期にスパイクがあるか確認
- 3 つの証拠が独立して異常を示したら、停止判断
- 停止スコープを「フォーマット別」に分解（INT / RWD / RWI / AOA / BNR）。実験信号のクリーン化を優先するなら BNR も一緒に止める
- 評価軸（クラッシュ / リテンション / レビュー / 収益 / click 効率）と判定マトリクスを停止前に決めておく
- 同時期のリリースとの切り分けを意識し、Crashlytics の issue 別フィルタで因果を分離する設計を組む

「収益を捨てる判断」は、データだけでも感覚だけでもできません。**3 つの独立した証拠の交差** と、**評価設計を停止前に確定**しておくこと。この 2 つが揃うと、月収 $730 を切るボタンを押せます。

両家の祖父が宮大工で、「直せないものは見守るしかない」というのを近くで見て育ったのですが、SDK との関係もこれに近いところがあります。直せるはずだと信じて待ち続けるのは、ある時点を超えると害になる。今回の判断はその境界線を自分で引いた経験で、4 週間後の判定結果がどう出ても、判断のロジック自体は手元に残ります。次に別のネットワークで同じ症状を見たとき、もっと早く動けるはずです。
