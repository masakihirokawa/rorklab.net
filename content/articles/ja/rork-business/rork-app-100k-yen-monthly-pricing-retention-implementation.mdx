## 月10万円までの距離を「3つの軸」で分解する

思いついた施策を片端から試して、どれが効いたのか分からないまま月末を迎えてしまいます。収益化に取りかかった最初のうちは、そんな進め方になりがちです。私も、施策の数ばかり増えて、結果の読み方が追いつかない時期がありました。

そこで、月次収益を**新規流入 × 課金率 × 継続率**の積として眺め直します。単純な掛け算ですが、どの軸に手を入れるかを決める地図になるのです。

Rork で生成したアプリのうち、個人開発者が自分の手で動かしやすいのは**課金率と継続率**です。新規流入は ASO やストア露出に左右されるため、コントロールしにくい部分が残ります。一方、課金率と継続率は、アプリ内の文言・タイミング・価格・体験設計で動かせます。このガイドでは ASO には深入りせず、課金率と継続率の改善に絞って進めます。

なお、本文中の割合や金額は、考え方を示すための仮置きです。ご自身のアプリでは、必ず自分の数字で測り直してください。

## 価格テスト1: 期間限定の初月割引で「本気度」を測る

最初に試す価格テストとして扱いやすいのが、**初月限定割引**です。たとえば月額¥580のサブスクなら、初月だけ¥280で提供します。値下げというより、「本気で使う気のあるユーザーを見分けるフィルター」として使うのがポイントです。

### Rork での実装パターン

Rork のテンプレートで決済を統合する場合、自前で Stripe を組み込むより、ストア課金（StoreKit / Google Play Billing）のほうが手間は小さく済みます。月額プランと初月割引プランを別商品として登録し、新規ユーザーには初月割引版を、再加入ユーザーには通常版を見せる分岐を作ります。

実装で気をつけたいのは、端末内のフラグではなく**ユーザー識別子ベース**で割引対象かどうかを判定することです。端末に持たせたフラグだと、再インストールのたびに初月割引を取り直せてしまいます。Apple ID や Google アカウントに紐づく匿名ハッシュを使う形が、現実的な落としどころです。

### 効果の見方

初月割引の効果は、初月の課金率ではなく**3か月後継続率 × 客単価**で測ります。課金率が上がっても、3か月後の継続率が大きく落ちていたら、収益は増えていないからです。

仮置きの試算を表にまとめます。数字はあくまで考え方の例です。

継続率が下がっても、入口が広がった分だけ絶対数では勝てる場合があります。逆に入口が広がらなければ、割引は純粋な減収になります。**課金率が動いたかどうかを、3か月かけて確かめるまでは勝ちと呼ばない**——これを私の線引きにしています。

## 価格テスト2: 地域別価格で「払える金額」に合わせる

App Store と Google Play は、地域ごとの参考価格を用意してくれています。それに従うのがいちばん楽ですが、もう一歩踏み込んで、ターゲットに合わせて手動で地域価格を設定する方法もあります。

考え方としては、購買力の低い地域では価格を下げ、高い地域では据え置くか、やや上げます。ただし、どれだけ動かすかは地域ごとに反応が異なるため、一括で下げるのではなく、少数の地域から試して課金率と総売上の両方を見比べるのが安全です。

注意したいのは、為替の動きです。日本円に換算したときに想定からずれていくので、定期的に全地域の価格を棚卸しする運用が欠かせません。半年に1度など、カレンダーに固定しておくと忘れにくくなります。

## 価格テスト3: 「見せる価格」と「払う価格」を分ける

3つ目は、年額プランの**表示の仕方**です。年額¥5,800を「月あたり約¥484」と併記すると、月額プランだけを並べるより割安感が伝わり、年額への誘導がしやすくなります。

ただし、年額プランは解約や返金の相談が増えやすい点には要注意です。返金の可否はストア側の判断になるため、アプリ側で約束できるのは「どこから解約できるか」を分かりやすく示すことまでです。購入前に、更新日と解約方法が目に入る画面にしておきます。ユーザーが自分で気づいて解約できる導線を用意することが、レビューの荒れを防ぐ、いちばん確実な備えだと感じています。

価格設計の全体像は、[Rork アプリで月額継続収益を育てる運用戦略](/articles/rork-business/rork-app-monthly-recurring-revenue-operations)でも、ASO やラインナップ設計とあわせて整理しています。

## 継続率改善1: オンボーディングで「続ける理由」を体感させる

サブスク型アプリの継続率を上げるうえで、費用対効果が高いのは**オンボーディング**です。Rork で生成したアプリは、機能はそろっているのに使い方が伝わりにくい状態から始まりがちです。

### 効くオンボーディング設計

次の3ステップを、順に入れていきます。

第一に、初回起動時に**ユーザーの目的を1問だけ聞く**ことです。「英語学習で何を達成したいか」「日記を続ける目的は何か」といった問いに答えてもらうと、その後の機能が「自分のため」に見えてきます。質問が3問、4問と増えるほど離脱しやすくなるので、1問に絞ります。

第二に、**3日後・7日後・14日後にプッシュ通知**を送ります。「初回の目的を覚えていますか」「今週の振り返り」「2週間続いたあなたへ」といったトーンで、機能の宣伝ではなく、ユーザーの体験を肯定する内容にします。

第三に、**初週に1回だけ「続けるためのコツ」を表示**します。利用ログから「朝に開く回数が多いので、朝のルーチンに組み込むのがおすすめです」のような個別のメッセージを出せると、AI 統合ツールで作ったアプリの強みが活きます。

### Rork での実装

オンボーディングはコード量よりも体験設計のほうが重く、Rork でテンプレートを生成したあとに、上記3ステップを**サブスク登録画面より前**へ差し込む形にします。登録後に置いてしまうと、「続ける理由」を感じる前に課金画面が出てしまい、課金率が下がりやすいのです。

## 継続率改善2: 連続記録（ストリーク）に「中断耐性」を持たせる

ストリークは習慣化アプリの定番機能ですが、1日抜けただけで記録がゼロに戻る設計は、ユーザーのがっかり感を招きます。そこで、**保護日数（Streak Freeze）**を設けます。たとえば月に2日までは抜けても連続記録が続く、という仕組みです。

### 実装の最小構成

日付の差は、端末のタイムゾーンで数えた「日付」同士で比べます。時刻つきで引き算すると、夜遅くに開いた日と翌朝に開いた日の差が、1日と数えられない場合があるからです。

```typescript
interface StreakState {
  current: number;
  lastActiveDate: string; // YYYY-MM-DD（端末のローカル日付）
  freezeCreditsRemaining: number; // 月初にリセット
}

// "YYYY-MM-DD" を UTC の 0 時として扱い、日数の差だけを取り出す
function dayIndex(date: string): number {
  const [y, m, d] = date.split("-").map(Number);
  return Math.floor(Date.UTC(y, m - 1, d) / 86_400_000);
}

function updateStreak(state: StreakState, today: string): StreakState {
  const diffDays = dayIndex(today) - dayIndex(state.lastActiveDate);

  if (diffDays <= 0) return state; // 今日はすでにカウント済み
  if (diffDays === 1) {
    return { ...state, current: state.current + 1, lastActiveDate: today };
  }
  if (diffDays === 2 && state.freezeCreditsRemaining > 0) {
    return {
      ...state,
      current: state.current + 1,
      lastActiveDate: today,
      freezeCreditsRemaining: state.freezeCreditsRemaining - 1,
    };
  }
  return { current: 1, lastActiveDate: today, freezeCreditsRemaining: state.freezeCreditsRemaining };
}
```

このロジックは1日抜けた場合だけを救います。2日以上空いたときはリセットに戻るので、保護日数の使い方が甘い、と感じた場合は `diffDays` の条件を広げて調整してください。入れる前と後で3か月後継続率を比べ、効果があったかどうかを、自分の数字で確かめます。

## 継続率改善3: 週次振り返りで「使った価値」を見える化する

3つ目の継続率施策は、**週次の振り返り画面**です。毎週日曜の夜に「今週の記録」「先週との比較」「来週の目標」をまとめた画面を、自動で生成します。

サブスクは「使わなかった月にも課金されている」とユーザーが意識した瞬間に、解約へ傾きます。そこで、週ごとに「自分は使っている」という事実を見せておくと、その意識に先回りできるのです。

Rork で生成したアプリなら、過去7日間の利用ログを AI に渡し、振り返りの文章を作ってもらう構成が手軽です。

```typescript
async function generateWeeklyReview(env: Env, userId: string, logs: ActivityLog[]) {
  const summary = logs.map(l => `${l.date}: ${l.action}`).join("\n");
  const response = await callClaude(env, [
    {
      role: "user",
      content: `次の利用ログから、ユーザーへの励ましの週次振り返りを150字以内で書いてください。\n\n${summary}`,
    },
  ]);
  return response;
}
```

ログに個人情報が含まれる場合は、要約に必要な項目だけを渡す形にしておきます。振り返りの文面を機械に任せるぶん、**数字と事実は自分のログから、言葉選びだけを AI に**、という分担にしておくと、事実と食い違う文章が出るのを防げます。継続率そのものの設計は、[Rork で作ったアプリを『削除されない』ものにする](/articles/rork-business/rork-app-retention-design-against-uninstall)で、初日からの導線を中心に書きました。

## チャーン対策1: 解約を考えている人に「ダウンセル」を用意する

解約のそばで効きやすいのが、**価格を下げた軽量プランの提案**です。「もし価格がネックなら、月額¥280の軽量プランに変えられます」という選択肢を用意します。

ここで押さえておきたいのは、iOS では解約の操作が OS の設定側にあり、アプリが解約を邪魔することはできない点です。そのため、「解約ボタンの直前に割り込む」設計ではなく、設定画面のプラン管理まわりに**プラン変更の案内**を置く形になります。同じサブスクリプショングループ内に軽量プランを登録しておくと、ユーザーはグループ内でプランを切り替えられます。

軽量プランは「機能を絞ったもの」にします。機能が同じで価格だけ安いと、既存ユーザーが全員そちらへ移ってしまい、客単価が崩れるからです。たとえば、AI 機能の利用回数を1日5回までに絞り、広告を表示する構成が考えられます。

導入前後の解約率の差は、プランの絞り方で大きく変わります。必ず導入前の解約率を控えてから始め、変化を自分の数字で確かめてください。

## チャーン対策2: 使われていないユーザーへの先回りメール

直近2週間アプリを開いていないユーザーには、解約される前に「最近お使いいただけていないようです。困っていることがあれば返信してください」と、ひと言送ります。

Rork のテンプレートには通常メール送信機能がないため、Cloudflare Workers と Resend などで自前の仕組みを組む必要があります。メール配信にあたっては、配信停止の導線と、送信してよい同意の取得状況の確認を、先に済ませておきます。

返信率は決して高くありません。それでも、返ってきた声が次のアップデートの手がかりになる点で、小さく始める価値のある施策です。

## チャーン対策3: 「機能停止の予告」より「成果サマリ」を見せる

「解約すると過去のデータが見られなくなります」という脅し文句は、短期的に効いても、長期的には信頼を損ねます。それよりも、**過去のあなたの成果**を見せるほうが誠実です。

たとえば、解約を検討できる画面に「過去30日間で、合計42時間このアプリを開いていました。書き溜めた日記は87本になります。解約後も閲覧できますが、新しい記録は増えなくなります」のような文面を出します。数字は一例ですが、**残るものと失うものを、淡々と並べることです**。それがもっとも誠実で、納得して決めてもらえる形だと考えています。

広告とサブスクの両立を考える場合は、[Rork Max でリリースしたアプリの収益化フロー設計](/articles/rork-business/rork-max-released-app-revenue-flow-offercode-winback-push-implementation)のオファーコードとウィンバックの章が参考になります。

## さいごに

Rork はアプリを作る速度を確かに上げてくれますが、収益化の段階で効くのは、AI で作ったアプリだからこその特別な施策ではなく、価格・継続・チャーンという古くからある3つの軸を地道に磨くことでした。

この原則だけは、どの施策でも守るようにしています。**入れる前の数字を控えてから、ひとつずつ入れます。**

ご自身の Rork アプリで、いちばん足りていない施策をひとつだけ選び、来週中に本番へ出すところから始めてみてください。
