壁紙アプリのカードをタップしたときの沈み込みが、どうにも重たく感じられた夜のことです。`response` を 0.4 秒から 0.3 秒に詰めると、手応えはずいぶん良くなりました。ところが翌朝、別の癒し系アプリを開いてみると、同じ見た目のカードが古い値のまま動いていました。直したつもりの修正が、プロジェクトの壁を越えていなかったのです。

Rork Max で SwiftUI のネイティブアプリを生成していると、この種のずれはさらに起きやすくなります。生成されるコードの品質は高いのですが、設計の単位はあくまで「いま開いている1つのアプリ」です。似たカードビュー、ほぼ同じグラデーション、半ポイントだけ違う角丸が、アプリの数だけ静かに増えていきます。

最初にお伝えしたいのは、解決策が Swift Package Manager（SPM）による共通UIライブラリ化だという点です。修正は1か所、テストも1か所、反映は各アプリのバージョン更新で行います。ただし、この記事の初版に載せていたカードのコードには、そのままではコンパイルが通らない箇所がありました。今回その部分を直し、`Color(hex:)` の定義漏れも補っています。手順どおりに進めていただければ、そのまま動く状態にしてあります。

## なぜ Rork Max の生成コードに SPM が必要なのか

Rork Max は SwiftUI のコードを生成しますが、1回の生成が見ているのは1つのプロジェクトだけです。2本目のアプリを同じ水準で作ろうとすると、1本目で整えたデザインの決めごとを、別のプロジェクトで一から再現することになります。

具体的には、次の3つが分散します。

**テーマカラー**: `Color("PrimaryColor")` のような定義が各プロジェクトのアセットに入り、RGB 値もダークモードの出し分けも個別管理になります。ブランドカラーを `#7B68EE` から `#6A5ACD` に変える日には、すべてのプロジェクトを開き直すことになります。

**アニメーション定数**: `spring(response: 0.4, dampingFraction: 0.75)` のような値が、ファイルごとに埋め込まれます。手触りを少し変えたいときも、同じ作業の繰り返しです。

**ビューコンポーネントの微差**: 「カード」という共通の概念があっても、角丸が 16pt のアプリと 14pt のアプリが並びます。1pt や 2pt の違いは、使っている本人にも説明しにくい「なんとなく雑な感じ」として残ります。

これらを1つの `Package.swift` に集約するのが、SPM 化の狙いです。

ライブラリを作る前に、私は必ず「何が変わらないか」と「何がアプリごとに違うか」を紙に書き分けます。ここを曖昧にしたまま始めると、ライブラリがアプリ固有のコードを引き込んでしまうからです。

## Swift Package を作成する

アプリのプロジェクトと同じ階層に、パッケージを作ります。

```bash
mkdir -p ~/Developer/DoliceUIKit
cd ~/Developer/DoliceUIKit
swift package init --type library --name DoliceUIKit
```

生成される構造は次のとおりです。

```
DoliceUIKit/
├── Package.swift
├── Sources/
│   └── DoliceUIKit/
│       └── DoliceUIKit.swift   ← ここにコンポーネントを追加
└── Tests/
    └── DoliceUIKitTests/
        └── DoliceUIKitTests.swift
```

`Package.swift` では、`@Observable` を使えるように iOS 17 以上を明示します。

```swift
// Package.swift
// swift-tools-version: 5.10
import PackageDescription

let package = Package(
    name: "DoliceUIKit",
    platforms: [
        .iOS(.v17)
    ],
    products: [
        .library(
            name: "DoliceUIKit",
            targets: ["DoliceUIKit"]
        ),
    ],
    dependencies: [],
    targets: [
        .target(
            name: "DoliceUIKit",
            dependencies: [],
            path: "Sources/DoliceUIKit"
        ),
        .testTarget(
            name: "DoliceUIKitTests",
            dependencies: ["DoliceUIKit"],
            path: "Tests/DoliceUIKitTests"
        ),
    ]
)
```

ここで守っていただきたいのは、`dependencies` を空のままにすることです。外部 SDK がどうしても必要になったときは、別ターゲットとして切り離します。

## テーマシステムの実装

アプリごとに違う色と書体を注入する仕組みを、SwiftUI の `EnvironmentValues` で作ります。まず、サンプルコードの中で使っている `Color(hex:)` を定義しておきます。SwiftUI には標準で16進数からの初期化子がないため、この定義が抜けているとビルドが止まります。

```swift
// Sources/DoliceUIKit/Theme/Color+Hex.swift

import SwiftUI

public extension Color {
    /// "#7B68EE" や "7B68EE" 形式の文字列から Color を作る
    init(hex: String) {
        let cleaned = hex.trimmingCharacters(in: CharacterSet.alphanumerics.inverted)
        var value: UInt64 = 0
        Scanner(string: cleaned).scanHexInt64(&value)
        let r = Double((value >> 16) & 0xFF) / 255
        let g = Double((value >> 8) & 0xFF) / 255
        let b = Double(value & 0xFF) / 255
        self.init(.sRGB, red: r, green: g, blue: b, opacity: 1)
    }
}
```

続いて、テーマのプロトコルと環境キーです。

```swift
// Sources/DoliceUIKit/Theme/AppTheme.swift

import SwiftUI

/// アプリのブランドテーマを定義するプロトコル
/// 各アプリはこのプロトコルに適合した型を用意し、ルートで環境に注入する
public protocol AppThemeable: Sendable {
    var primary: Color { get }
    var secondary: Color { get }
    var surface: Color { get }
    var onSurface: Color { get }
    var fontTitle: Font { get }
    var fontBody: Font { get }
    var fontCaption: Font { get }
}

/// 開発中とプレビュー用のデフォルトテーマ
public struct DefaultAppTheme: AppThemeable {
    public var primary: Color { Color(hex: "#7B68EE") }
    public var secondary: Color { Color(hex: "#48D1CC") }
    public var surface: Color { Color(.systemBackground) }
    public var onSurface: Color { Color(.label) }
    public var fontTitle: Font { .system(.title2, design: .rounded, weight: .bold) }
    public var fontBody: Font { .system(.body, design: .default) }
    public var fontCaption: Font { .system(.caption, design: .monospaced) }

    public init() {}
}

private struct AppThemeKey: EnvironmentKey {
    static let defaultValue: any AppThemeable = DefaultAppTheme()
}

public extension EnvironmentValues {
    var appTheme: any AppThemeable {
        get { self[AppThemeKey.self] }
        set { self[AppThemeKey.self] = newValue }
    }
}
```

`AppThemeable` に `Sendable` を付けているのは、将来 Swift 6 言語モードへ移したときに、環境キーの `static let` が並行性のエラーになるのを避けるためです。この種の警告の読み方は、[Swift 6 の Strict Concurrency 移行（MainActor と Sendable）](/articles/rork-dev/rork-max-swift-6-strict-concurrency-migration-mainactor-sendable)にまとめています。

各アプリ側では、テーマ型を1つ用意してルートで注入するだけです。

```swift
// WallpaperApp/ContentView.swift（アプリ側）
import SwiftUI
import DoliceUIKit

struct WallpaperAppTheme: AppThemeable {
    var primary: Color { Color(hex: "#FF6B9D") }
    var secondary: Color { Color(hex: "#FFB347") }
    var surface: Color { Color(.systemBackground) }
    var onSurface: Color { Color(.label) }
    var fontTitle: Font { .custom("ZenMaruGothic-Bold", size: 20) }
    var fontBody: Font { .custom("ZenMaruGothic-Regular", size: 16) }
    var fontCaption: Font { .custom("ZenMaruGothic-Regular", size: 12) }
}

@main
struct WallpaperApp: App {
    var body: some Scene {
        WindowGroup {
            RootView()
                .environment(\.appTheme, WallpaperAppTheme())
        }
    }
}
```

この設計の良い点は、`AppThemeable` に新しいカラーロールを足したとき、実装が漏れているアプリがコンパイルエラーで即座に見つかることです。ブランド更新の取りこぼしを、人の注意力ではなくコンパイラに任せられます。

なお、`ZenMaruGothic` のようなカスタムフォントのファイルは、ライブラリではなくアプリのターゲットに同梱します。フォント名が合っていないと `Font.custom` はエラーを出さずにシステムフォントへ戻るため、見た目が変わっていないかを実機で一度確かめておくと安心です。

## カードコンポーネントの実装

壁紙・癒し系のアプリでいちばん頻繁に現れるカード型UIを共通化します。

初版では、フラットスタイルの枠線を `style == .flat ? RoundedRectangle(...) : nil` という三項演算子で `overlay` に渡していました。`nil` を `View` として受け取る `overlay` はないため、この書き方はコンパイルが通りません。`overlay` のクロージャ内で `if` を使う形に直したものが、次のコードです。

```swift
// Sources/DoliceUIKit/Components/ContentCard.swift

import SwiftUI

public struct ContentCard<Content: View>: View {
    @Environment(\.appTheme) private var theme
    @Environment(\.colorScheme) private var colorScheme

    private let content: Content
    private let style: CardStyle

    public enum CardStyle {
        case standard      // 標準シャドウ
        case elevated      // 強めのシャドウ、プレミアムな印象
        case flat          // シャドウなし、ボーダーあり
    }

    public init(style: CardStyle = .standard, @ViewBuilder content: () -> Content) {
        self.style = style
        self.content = content()
    }

    public var body: some View {
        content
            .background(cardBackground)
            .clipShape(RoundedRectangle(cornerRadius: cardCornerRadius))
            .shadow(color: shadowColor, radius: shadowRadius, x: 0, y: shadowY)
    }

    private var cardBackground: some View {
        theme.surface
            .overlay {
                if style == .flat {
                    RoundedRectangle(cornerRadius: cardCornerRadius)
                        .strokeBorder(theme.primary.opacity(0.2), lineWidth: 1)
                }
            }
    }

    private var cardCornerRadius: CGFloat { 16 }

    private var shadowColor: Color {
        switch style {
        case .standard: return Color.black.opacity(colorScheme == .dark ? 0.3 : 0.08)
        case .elevated: return theme.primary.opacity(0.2)
        case .flat:     return .clear
        }
    }

    private var shadowRadius: CGFloat {
        switch style {
        case .standard: return 8
        case .elevated: return 20
        case .flat:     return 0
        }
    }

    private var shadowY: CGFloat {
        switch style {
        case .standard: return 4
        case .elevated: return 8
        case .flat:     return 0
        }
    }
}
```

Rork Max が別々のプロジェクトで生成しがちなカードと、並べてみます。

**Before（各アプリに個別に存在するカード）**:

```swift
// WallpaperApp でのカード定義
struct WallpaperCard: View {
    var body: some View {
        content
            .background(Color(.systemBackground))
            .clipShape(RoundedRectangle(cornerRadius: 16))
            .shadow(color: Color.black.opacity(0.08), radius: 8, x: 0, y: 4)
    }
}

// HealingApp でのカード定義（微妙に違う）
struct HealingCard: View {
    var body: some View {
        content
            .background(Color(.systemBackground))
            .clipShape(RoundedRectangle(cornerRadius: 14))  // ← 微妙に違う
            .shadow(color: Color.black.opacity(0.1), radius: 6, x: 0, y: 3)  // ← 微妙に違う
    }
}
```

**After（DoliceUIKit を使った統一実装）**:

```swift
// どのアプリでも同じコンポーネント、テーマだけが違う
ContentCard(style: .elevated) {
    WallpaperThumbnailView(wallpaper: item)
}
```

角丸が 16pt か 14pt か、影の不透明度が 0.08 か 0.1 かで揺れていた品質が、1回の修正で全アプリに行き渡るようになります。

## アニメーションプリセットの共通化

生成されるアニメーションの値も、プロジェクトをまたぐとずれていきます。`Animation` の拡張として、共通のプリセットを定義します。

```swift
// Sources/DoliceUIKit/Animation/AnimationPresets.swift

import SwiftUI

public extension Animation {
    /// 標準的なスプリング（タップフィードバック等）
    static let doliceSpring = Animation.spring(
        response: 0.4,
        dampingFraction: 0.75,
        blendDuration: 0
    )

    /// 素早い反応（ボタン押下等）
    static let doliceSnap = Animation.spring(
        response: 0.25,
        dampingFraction: 0.8,
        blendDuration: 0
    )

    /// ゆったりした登場（画面遷移等）
    static let doliceEase = Animation.easeOut(duration: 0.35)

    /// 壁紙・背景の切り替え時のフェード
    static let doliceContentTransition = Animation.easeInOut(duration: 0.5)
}

/// 押下時に沈み込むボタンスタイル
public struct DolicePressEffect: ButtonStyle {
    public init() {}

    public func makeBody(configuration: Configuration) -> some View {
        configuration.label
            .scaleEffect(configuration.isPressed ? 0.94 : 1.0)
            .opacity(configuration.isPressed ? 0.85 : 1.0)
            .animation(.doliceSnap, value: configuration.isPressed)
    }
}
```

初版の `DolicePressEffect` には、使っていない `@Environment(\.appTheme)` が残っていました。テーマを参照しないボタンスタイルに環境値は不要ですので、取り除いてあります。

## Rork Max プロジェクトへの統合

Xcode で Rork Max の生成プロジェクトを開き、パッケージを追加します。

File → Add Package Dependencies → Add Local… からパッケージのフォルダを選びます。

```
/Users/masaki/Developer/DoliceUIKit
```

ローカルパッケージとして追加すると、ライブラリを編集した内容がアプリ側のビルドにすぐ反映されます。本番では GitHub のリポジトリに置き、バージョンタグで管理します。

```swift
// GitHub で管理する場合の依存定義（アプリ側）
dependencies: [
    .package(
        url: "https://github.com/dolice/DoliceUIKit.git",
        from: "1.0.0"
    )
],
```

統合してからは、Rork Max に新しい画面を頼む際のプロンプトにも、ひと言添えておくと手戻りが減ります。

```
このプロジェクトは DoliceUIKit（ContentCard、DolicePressEffect、Animation.doliceSpring など）を import しています。
カードやボタンを新しく書かず、これらを使ってください。色と書体は @Environment(\.appTheme) から取得してください。
```

生成されたコードが返ってきたら、「これは DoliceUIKit にすでにあるか」を確かめます。あれば置き換え、なければライブラリへ足すかどうかを判断します。

生成コードを本番品質に整えるリファクタリングは、[Rork Max が生成した SwiftUI コードを本番品質まで磨き上げる10のリファクタリング・パターン](/articles/rork-dev/rork-max-swiftui-generated-code-production-refactoring-patterns)で扱っています。React Native 側の共通コンポーネント化は、[Turborepo モノレポで複数アプリの共有コードを一元管理する](/articles/rork-dev/rork-turborepo-monorepo-shared-components-guide)をご覧ください。

## テストとバリデーション

SwiftUI のビューそのもののユニットテストは難しいため、ロジックを持つ部分に絞って確かめます。今回は、初版にはなかった `Color(hex:)` のテストも加えます。

```swift
// Tests/DoliceUIKitTests/ThemeTests.swift

import XCTest
import SwiftUI
@testable import DoliceUIKit

final class ThemeTests: XCTestCase {
    func testHexParsingAcceptsHashPrefix() {
        // "#" の有無にかかわらず同じ色になること
        let a = UIColor(Color(hex: "#7B68EE"))
        let b = UIColor(Color(hex: "7B68EE"))
        var (ar, ag, ab, aa): (CGFloat, CGFloat, CGFloat, CGFloat) = (0, 0, 0, 0)
        var (br, bg, bb, ba): (CGFloat, CGFloat, CGFloat, CGFloat) = (0, 0, 0, 0)
        a.getRed(&ar, green: &ag, blue: &ab, alpha: &aa)
        b.getRed(&br, green: &bg, blue: &bb, alpha: &ba)
        XCTAssertEqual(ar, br, accuracy: 0.001)
        XCTAssertEqual(ag, bg, accuracy: 0.001)
        XCTAssertEqual(ab, bb, accuracy: 0.001)
    }

    func testAnimationPresetsExist() {
        // コンパイルが通ること自体が、プリセット定義の確認になる
        _ = Animation.doliceSpring
        _ = Animation.doliceSnap
        _ = Animation.doliceEase
    }
}
```

見た目の回帰を防ぎたい場合は、[swift-snapshot-testing](https://github.com/pointfreeco/swift-snapshot-testing) の導入を検討する価値があります。コンポーネントの描画結果を基準画像と比べ、意図しない変化を CI で止めてくれます。

## 複数アプリへの展開フロー

ライブラリが落ち着いたら、バージョン管理のルールを決めます。タグの付け方と、アプリ側で受け入れる範囲を表にまとめました。

## 実運用で分かった落とし穴

**プレビューがクラッシュする**: SwiftUI のプレビューでは、環境値が自動では渡りません。`#Preview` の中で `.environment(\.appTheme, DefaultAppTheme())` を必ず明示します。

```swift
#Preview {
    ContentCard {
        Text("サンプルカード")
            .padding()
    }
    .environment(\.appTheme, DefaultAppTheme())  // 必須
}
```

**CI でローカルパスが解決できない**: Xcode Cloud や GitHub Actions には、手元の `~/Developer/DoliceUIKit` は存在しません。CI が走るブランチに push する前に、依存を GitHub の URL に切り替える運用が必要です。切り替え忘れを防ぐために、コミット前フックでローカルパスの参照を検出するスクリプトを置いています。Xcode Cloud の設計全体は、[Xcode Cloud での CI/CD](/articles/rork-dev/rork-max-xcode-cloud-cicd-complete-guide)も参考になります。

**バイナリサイズ**: 使われないコードが多いと、バイナリは膨らみます。Release 構成では `DEAD_CODE_STRIPPING` が有効な設定が既定ですが、Rork Max の生成プロジェクトでは、念のため Build Settings で `YES` になっているかを確認しておくと安心です。

## 全体を振り返って

共通UIライブラリは、アプリが1本のうちは「やりすぎ」に見えます。けれども2本目を作り始めた瞬間から、投資は確実に回収されていきます。

この線引きだけは、これからも守っていくつもりです。
