iOS 26 の Liquid Glass 対応を試みたら、それまで完璧に見えていた画面が突然おかしくなった——そういう経験をした方は、意外と多いのではないでしょうか。

Rork Max で iOS アプリを作っている開発者の方から「Liquid Glass に対応しようとしたら、ナビゲーションバーが消えた」「カスタムカラーが効かなくなった」「タブバーがフローティング化してレイアウトがズレた」という声をよく耳にします。

このガイドでは、iOS 26 Liquid Glass 対応後に起きやすい UI 崩れのパターンを整理し、Rork Max を使った具体的な修正手順をまとめました。同じ問題で悩んでいる方のお役に立てれば嬉しいです。

AdMob で月収100万円超を経験した時期の知見から、この問題に普段から向き合ってきた立場で、要点を整理します。

2014年からの個人開発と AdMob 運用の知見を踏まえ、要点だけ整理します。

## iOS 26 Liquid Glass が既存 UI に与える影響

iOS 26 の Liquid Glass は、Apple が長年採用してきたフラットデザインから大きく転換した UI パラダイムです。ガラスのような半透明素材が UI 全体に広がり、ナビゲーションバー・タブバー・シートなどの基本コンポーネントが根本的に変わりました。

Rork Max が生成した SwiftUI コードは iOS 25 以前の挙動を前提にしている部分があるため、iOS 26 でそのまま動かすと想定外の見た目になることがあります。主な変化は次の通りです。

- **ナビゲーションバー**: デフォルトで背景が透明化し、コンテンツが後ろに溶け込む
- **タブバー**: フローティングのピル型に変わり、画面下部のスペースが増える
- **モーダル / シート**: 角丸が強まり、背景のブラーが深くなる
- **カラーシステム**: ダイナミックマテリアルが優先されるため、ハードコードした背景色が期待通りに見えないことがある

## よくある崩れパターン 3 選と修正プロンプト

### ケース 1: ナビゲーションバーの背景色が消えた

```swift
// 以前は有効だったスタイル指定
.toolbarBackground(Color.blue, for: .navigationBar)
.toolbarBackgroundVisibility(.visible, for: .navigationBar)
```

iOS 26 では、Liquid Glass エフェクトがカスタムの `toolbarBackground` より前面に来ます。`toolbarBackgroundVisibility(.visible)` を指定しても、Glass 越しに色が透けて見える状態になることがあります。

**Rork Max への修正プロンプト**:

```
NavigationBar の背景が iOS 26 の Liquid Glass エフェクトで透明になっています。
iOS バージョン分岐を使って対応してください。
iOS 26 以降は、NavigationView の子要素に .background(.regularMaterial) を適用し、
iOS 25 以前は既存の toolbarBackground をそのまま維持してください。
```

### ケース 2: カスタムカラーのコントラストが低下した

Liquid Glass は背景にブラーとガラス質感を重ねるため、暗い背景色の上に薄いテキストを置いたデザインが読みにくくなることがあります。ブランドカラーを前面に出したデザインで特に目立ちます。

**開発時の診断コード**:

```swift
// カスタムカラーが正しく読み込まれているか確認する（デバッグ用）
if UIColor(named: "AppBackground") != nil {
    print("✓ カスタムカラー読み込み済み")
} else {
    print("⚠️ Asset Catalog にカラーが見つかりません — フォールバックを確認してください")
}
```

**Rork Max への修正プロンプト**:

```
iOS 26 の Liquid Glass でテキストのコントラストが低下しています。
以下の対応をお願いします。
1. 全テキスト要素に .foregroundStyle(.primary) を明示的に追加してください
2. カスタム背景色を持つ View に .compositingGroup() を追加し、
   Liquid Glass レイヤーとの合成を正しく処理してください
```

### ケース 3: フローティングタブバーでレイアウトがズレた

iOS 26 のタブバーはフローティング表示になり、画面下部に余白が追加されます。`Spacer()` や固定の `.padding(.bottom)` でタブバーぴったりのレイアウトを組んでいた場合、コンテンツがタブバーと重なったり不自然な空白が生まれたりします。

**Rork Max への修正プロンプト**:

```
iOS 26 のフローティングタブバーでレイアウトが崩れています。
次の対応をお願いします。
1. ScrollView と List に .contentMargins(.bottom, 0) を追加して重なりを解消してください
2. 画面下部に固定されたボタンは、ハードコードしたパディングではなく
   .safeAreaInset(edge: .bottom) を使って再配置してください
```

## Rork Max を使った段階的な修正の進め方

iOS 26 対応は「一度に全部直そうとしない」ことが大切です。あれこれ修正しようとすると、Rork AI が広い範囲を変更してしまい、それまで正常だった部分まで崩れることがあります。

実際に複数の Rork Max アプリで試した中で、うまくいったアプローチをまとめます。

**Step 1: 影響箇所をリストアップする**

まず Rork Max に「iOS 26 の Liquid Glass で影響を受けそなコンポーネントを全てリストアップしてください」と聞いてみてください。NavigationBar・TabBar・カスタムボタンスタイル・モーダルなど、変更が必要な箇所の全体像が把握できます。

**Step 2: iOS 26 シミュレーターで確認する**

Rork Companion は最新 OS の細かい挙動を完全には再現しません。Xcode のシミュレーターで iOS 26 ターゲットを指定し、各画面の状態を実際に目で確認する点が肝心です。

**Step 3: コンポーネントを 1 つずつ修正する**

「ナビゲーションバーだけ直してください」「タブバーのレイアウトだけ直してください」と個別に指定します。スコープを絞ることで、Rork の変更範囲が限定され、意図しない修正が入るリスクを下げられます。

**Step 4: バージョン分岐を必ず入れる**

iOS 26 向けの変更を入れるときは、iOS 25 以前のユーザーへの影響を避けるためにバージョン分岐を追加します。

```swift
// iOS バージョン分岐の基本パターン
if #available(iOS 26.0, *) {
    // iOS 26 以降向けの実装
    contentView
        .background(.regularMaterial)
} else {
    // 従来の実装
    contentView
        .background(Color.white)
}
```

Rork に最初のプロンプトで「iOS 26 対応の変更には必ずバージョン分岐を追加してください」と伝えておくと、以降の修正にも一貫してこのパターンが適用されます。

## iOS 26 対応を早めに進めるメリット

大変な面ばかり書きましたが、Liquid Glass への早期対応にはメリットもあります。

Apple の編集チームは Featured アプリを選定する際に、最新 OS の UI ガイドラインに準拠しているかどうかを見ています。Liquid Glass ネイティブ対応のアプリは、まだ対応していないアプリより審査員の印象が良くなる可能性があります。

また、Liquid Glass は「高品質感」を感じやすいデザインです。競合アプリが未対応の段階で先に対応できれば、App Store のスクリーンショットやプレビュー動画で差別化できます。

## 全体を振り返って

iOS 26 Liquid Glass 対応後によくある UI 崩れは、ナビゲーションバーの透明化・カラーコントラストの低下・フローティングタブバーによるレイアウトズレの 3 パターンです。いずれも Rork Max への修正プロンプトで対応できますが、「一度に全部直す」のではなくコンポーネントごとに進めることが成功の鍵です。

まず Xcode シミュレーターで iOS 26 環境を確認し、どの画面が崩れているかを特定するところから始めてみてください。問題箇所が明確になれば、Rork への修正プロンプトの精度も自然と上がります。
