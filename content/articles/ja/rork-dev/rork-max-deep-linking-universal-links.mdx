# Rork Maxでのディープリンク・ユニバーサルリンク実装

キャンペーンのリンクを踏んだはずのユーザーが、アプリのホーム画面に着地していました。管理画面の流入元は、どれを開いても「Organic」。広告費を出した翌朝にその数字を見たときの、胸の底が冷える感覚を今でも覚えています。

原因はディープリンクの実装漏れでした。リンクは開きます、アプリも起動します。けれど目的の画面には届かず、どの経路から来たのかも残りません。動いているように見えて、計測だけが抜け落ちている状態です。

Rork Max はネイティブ Swift を生成しますので、Universal Links も App Links も基本形はスキャフォールドとして出てきます。ただし出てきた時点のコードが面倒を見てくれるのは「開く」までで、「どこから来たかを残す」ところまでは届きません。

以下では、その差分を埋める実装を順に組み立てていきます。

## グロースにおけるディープリンクの重要性

ディープリンクは以下を可能にします。

- **シームレスなユーザー体験**: ユーザーはアプリ・ホームではなく、関連コンテンツに直接ランディング
- **正確な帰属追跡**: どのキャンペーンまたはチャネルが各ユーザーをもたらしたかを追跡
- **高いコンバージョン率**: 正しい画面にランディングするユーザーのコンバージョン率は約5倍向上
- **紹介プログラム**: ウイルス的グロースのためのビルトイン・メカニズム
- **クロス・プラットフォーム一貫性**: 同じリンクがWebとアプリ内ブラウザとネイティブ・アプリで動作

<Callout type="tip">
ディープリンクを実装したアプリはユーザー・エンゲージメントが30%向上し、リテンション率が4倍向上するという調査結果があります。さらに重要なのは、ディープリンクにより帰属追跡が可能になることです。これはIDFA廃止後のマーケティングROI測定に不可欠です。
</Callout>

## Rork Maxアプリのディープリンク・アーキテクチャ

### 3つの構成要素

適切なディープリンク・アーキテクチャには3つのレイヤーの調整が必要です。

1. **URLスキーム・ハンドラー**: ディープリンクURLをインターセプト
2. **ルートパーサーとナビゲーター**: URLをパースし正しい画面に移動
3. **ペイロード・マネージャー**: ディープリンク・データを画面へ渡す層

### 実装戦略

```swift
// URLスキーム定義
enum DeepLinkScheme {
    case native(NativeDeepLink)
    case web(WebDeepLink)
    case attributionTracking(AttributionData)

    static func parse(_ url: URL) -> DeepLinkScheme? {
        if url.scheme == "myapp" {
            return parseNativeDeepLink(url)
        } else if url.host == "myapp.com" {
            return parseWebDeepLink(url)
        }
        return nil
    }

    private static func parseNativeDeepLink(_ url: URL) -> DeepLinkScheme? {
        let components = URLComponents(url: url, resolvingAgainstBaseURL: true)
        guard let host = components?.host else { return nil }

        switch host {
        case "product":
            if let productId = components?.queryItems?.first(where: { $0.name == "id" })?.value {
                return .native(.product(id: productId))
            }
        case "user":
            if let username = components?.queryItems?.first(where: { $0.name == "username" })?.value {
                return .native(.user(username: username))
            }
        case "invite":
            if let inviteCode = components?.queryItems?.first(where: { $0.name == "code" })?.value {
                return .native(.invite(code: inviteCode))
            }
        default:
            return nil
        }
        return nil
    }
}

enum NativeDeepLink {
    case product(id: String)
    case user(username: String)
    case invite(code: String)
    case home
}

enum WebDeepLink {
    case product(slug: String)
    case article(slug: String)
    case profile(username: String)
}

// ディープリンク・ナビゲーション・ハンドラー
@main
struct MyApp: App {
    @StateObject private var deepLinkRouter = DeepLinkRouter()

    var body: some Scene {
        WindowGroup {
            ContentView()
                .environmentObject(deepLinkRouter)
                .onOpenURL { url in
                    handleDeepLink(url)
                }
                .onContinueUserActivity(NSUserActivityTypeBrowsingWeb) { userActivity in
                    if let url = userActivity.webpageURL {
                        handleDeepLink(url)
                    }
                }
        }
    }

    private func handleDeepLink(_ url: URL) {
        // ディープリンクをパースしてルーティング
        if let scheme = DeepLinkScheme.parse(url) {
            deepLinkRouter.navigate(to: scheme)
        }
    }
}
```

## ユニバーサルリンク — シームレスなWebからアプリへのディープリンク

ユニバーサルリンクは、WebサイトのURLをアプリで直接開く機能です。ユーザーがアプリをインストールしていない場合、URLはブラウザで開きます。

### ユニバーサルリンクのセットアップ

ユニバーサルリンクには2つの要素が必要です。

1. **apple-app-site-association ファイル** をドメイン上に配置
2. **Entitlements設定** をアプリで設定

```swift
// ステップ1：apple-app-site-associationファイルを作成
// 配置先: https://yourdomain.com/.well-known/apple-app-site-association

{
  "applinks": {
    "apps": [],
    "details": [
      {
        "appID": "com.example.myapp",
        "paths": [
          "/products/*",
          "/users/*",
          "/articles/*"
        ]
      }
    ]
  },
  "webcredentials": {
    "apps": ["com.example.myapp"]
  }
}

// ステップ2：Rork Maxでentitlementsを設定
// プロンプトで以下をリクエスト：
// "ユニバーサルリンク向けのassociated domainsを追加してください：
//  yourdomain.com, www.yourdomain.com"

// ステップ3：SwiftUIでユニバーサルリンクを処理
class UniversalLinkHandler {
    func parseUniversalLink(_ url: URL) -> DeepLinkScheme? {
        // 末尾のスラッシュを削除して一貫したパースを実現
        var urlPath = url.path
        while urlPath.hasSuffix("/") {
            urlPath.removeLast()
        }

        // ルート・パターンにマッチさせる
        if urlPath.starts(with: "/products/") {
            let productSlug = String(urlPath.dropFirst("/products/".count))
            return .native(.product(id: productSlug))
        }

        if urlPath.starts(with: "/users/") {
            let username = String(urlPath.dropFirst("/users/".count))
            return .native(.user(username: username))
        }

        if urlPath.starts(with: "/articles/") {
            let articleSlug = String(urlPath.dropFirst("/articles/".count))
            // スラッグから記事IDを取得する必要があるかもしれません
            return .native(.article(slug: articleSlug))
        }

        return nil
    }
}
```

<Callout type="warning">
ユニバーサルリンクはAppleとドメイン間の暗号化されたハンドシェイクで検証されます。テストには以下が必要です。

1. ドメインはHTTPSである必要があります
2. apple-app-site-associationファイルは`/.well-known/apple-app-site-association`で公開アクセス可能である必要があります
3. associated domains entitlementを持つ適切なプロビジョニング・プロファイルが必要です

開発中は、`xcode-select --install`でユニバーサルリンク検証を無効化し、App Clipsを無効にした実機でテストしてください。
</Callout>

すべてのユニバーサルリンクがアプリで開く必要はありません。ブラウザ体験を保持したい場合もあります。

```swift
class UniversalLinkRouter {

        let webOnlyPaths = ["/legal/", "/privacy/", "/terms/"]

            navigateTo(deepLink)
        } else {
            // ブラウザにフォールバック
            UIApplication.shared.open(url)
        }
    }

        // ナビゲーション実装
    }
}
```

## 遅延ディープリンク — グロースの究極ツール

遅延ディープリンクにより、ユーザーがアプリをインストールしていなくても、ディープリンクが機能します。ユーザーがストアからアプリをインストールして初めて起動すると、意図した画面にルーティングされます。

<Callout type="tip">
遅延ディープリンクは紹介プログラムとウイルス・キャンペーンに変革をもたらします。ユーザーは特定の商品へのリンクを共有でき、友人はインストール後、その商品に直接ランディングします。サーバー・ロジック不要です。
</Callout>

### 帰属追跡を伴う遅延ディープリンク実装

```swift
// 帰属追跡を伴う遅延ディープリンク・サービス
class DeferredDeepLinkService {
    private let apiBaseURL = URL(string: "https://api.yourdomain.com")!
    private let deviceIdentifier = UIDevice.current.identifierForVendor?.uuidString ?? UUID().uuidString

    // 最初のアプリ起動時に遅延ディープリンクを保存
    func fetchDeferredDeepLink() async throws -> DeferredDeepLinkData? {
        var request = URLRequest(url: apiBaseURL.appendingPathComponent("/deferred-links/fetch"))
        request.httpMethod = "POST"

        let payload = DeferredLinkRequest(
            deviceId: deviceIdentifier,
            appVersion: Bundle.main.appVersion,
            osVersion: UIDevice.current.systemVersion,
            isFirstLaunch: !UserDefaults.standard.bool(forKey: "hasLaunchedBefore")
        )

        request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        request.httpBody = try JSONEncoder().encode(payload)

        let (data, _) = try await URLSession.shared.data(for: request)
        let decoder = JSONDecoder()
        let response = try decoder.decode(DeferredLinkResponse.self, from: data)

        return response.deepLinkData
    }

    // 帰属データをログ
    func logAttribution(source: String, campaign: String, medium: String) async throws {
        var request = URLRequest(url: apiBaseURL.appendingPathComponent("/attribution"))
        request.httpMethod = "POST"

        let attribution = AttributionEvent(
            deviceId: deviceIdentifier,
            source: source,
            campaign: campaign,
            medium: medium,
            timestamp: Date()
        )

        request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        request.httpBody = try JSONEncoder().encode(attribution)

        _ = try await URLSession.shared.data(for: request)
    }
}

struct DeferredLinkRequest: Codable {
    let deviceId: String
    let appVersion: String
    let osVersion: String
    let isFirstLaunch: Bool
}

struct DeferredDeepLinkData: Codable {
    let deepLink: String
    let source: String // "referral", "ad_campaign"など
    let campaign: String
    let userId: String? // リンクを共有したユーザーのID
}

struct AttributionEvent: Codable {
    let deviceId: String
    let source: String
    let campaign: String
    let medium: String
    let timestamp: Date
}
```

### 起動時の遅延ディープリンク処理

```swift
class AppStartupManager {
    @StateObject private var deferredLinkService = DeferredDeepLinkService()

    func setupAppLaunchFlow() async {
        // アプリ起動をマーク
        if !UserDefaults.standard.bool(forKey: "hasLaunchedBefore") {
            UserDefaults.standard.set(true, forKey: "hasLaunchedBefore")

            // 最初の起動時に遅延ディープリンクを取得
            do {
                if let deferredLink = try await deferredLinkService.fetchDeferredDeepLink() {
                    // 帰属をログ
                    try await deferredLinkService.logAttribution(
                        source: deferredLink.source,
                        campaign: deferredLink.campaign,
                        medium: "deferred_deep_link"
                    )

                    // ディープリンクにルーティング
                    handleDeepLinkString(deferredLink.deepLink)

                    // オプション：紹介関係を保存
                    if let referrerId = deferredLink.userId {
                        UserDefaults.standard.set(referrerId, forKey: "referredBy")
                    }
                }
            } catch {
                // エラーをログしても、アプリ起動をブロックしない
                print("遅延ディープリンク取得失敗: \(error)")
            }
        }
    }

    private func handleDeepLinkString(_ deepLinkString: String) {
        guard let url = URL(string: deepLinkString) else { return }
        if let scheme = DeepLinkScheme.parse(url) {
            // 適切な画面にナビゲート
            navigateToDeepLink(scheme)
        }
    }
}
```

```swift
class AttributionTracker {
    struct Campaign {
        let id: String
        let source: String // "organic", "paid_social", "email", "referral"
        let medium: String // "cpc", "display", "email", "organic"
        let name: String
        let content: String?
    }

    enum EventType: String, Codable {
        case appInstall = "app_install"
        case appOpen = "app_open"
        case productView = "product_view"
        case addToCart = "add_to_cart"
        case purchase = "purchase"
        case share = "share"
        case signup = "signup"

    private let apiURL = URL(string: "https://api.yourdomain.com")!

    // 帰属データを伴うコンバージョン・イベントをログ
    func logEvent(
        _ eventType: EventType,
        userId: String?,
        metadata: [String: Any]? = nil,

    ) async throws {

        )

        _ = try await URLSession.shared.data(for: request)

}
```

### UTMパラメーター・パース

```swift
class UTMParameterParser {
    struct UTMParameters: Codable {
        let source: String?      // utm_source
        let medium: String?      // utm_medium
        let campaign: String?    // utm_campaign
        let content: String?     // utm_content
        let term: String?        // utm_term
    }

    static func extractUTM(from url: URL) -> UTMParameters {
        let components = URLComponents(url: url, resolvingAgainstBaseURL: true)
        let queryItems = components?.queryItems ?? []

        return UTMParameters(
            source: queryItems.first(where: { $0.name == "utm_source" })?.value,
            medium: queryItems.first(where: { $0.name == "utm_medium" })?.value,
            campaign: queryItems.first(where: { $0.name == "utm_campaign" })?.value,
            content: queryItems.first(where: { $0.name == "utm_content" })?.value,
            term: queryItems.first(where: { $0.name == "utm_term" })?.value
        )
    }

    static func createDeepLinkWithUTM(
        baseDeepLink: String,
        utm: UTMParameters
    ) -> String? {
        guard var components = URLComponents(string: baseDeepLink) else {
            return nil
        }

        var queryItems = components.queryItems ?? []

        if let source = utm.source {
            queryItems.append(URLQueryItem(name: "utm_source", value: source))
        }
        if let medium = utm.medium {
            queryItems.append(URLQueryItem(name: "utm_medium", value: medium))
        }
        if let campaign = utm.campaign {
            queryItems.append(URLQueryItem(name: "utm_campaign", value: campaign))
        }
        if let content = utm.content {
            queryItems.append(URLQueryItem(name: "utm_content", value: content))
        }
        if let term = utm.term {
            queryItems.append(URLQueryItem(name: "utm_term", value: term))
        }

        components.queryItems = queryItems
        return components.url?.absoluteString
    }
}
```

```swift
class ReferralProgram {
    let baseDeepLinkURL = "myapp://invite"

    func generateReferralLink(for userId: String, withReward reward: Double) -> URL? {
        let referralCode = generateCode(userId: userId, reward: reward)

        var components = URLComponents(string: baseDeepLinkURL)
        components?.queryItems = [
            URLQueryItem(name: "code", value: referralCode),
            URLQueryItem(name: "referrer_id", value: userId)
        ]

        return components?.url
    }

    // ユニバーサルリンク版も生成
    func generateUniversalReferralLink(for userId: String, withReward reward: Double) -> URL? {
        let referralCode = generateCode(userId: userId, reward: reward)

        var components = URLComponents(string: "https://myapp.com/invite")
        components?.queryItems = [
            URLQueryItem(name: "code", value: referralCode),
            URLQueryItem(name: "referrer_id", value: userId)
        ]

        return components?.url
    }

    private func generateCode(userId: String, reward: Double) -> String {
        let timestamp = Int(Date().timeIntervalSince1970)
        let data = "\(userId):\(timestamp):\(reward)"
        return data.base64Encoded()
    }
}
```

```swift
class ReferralRewardService {
    private let apiURL = URL(string: "https://api.yourdomain.com")!

    // 紹介コードを検証し両者にリワード
    func processReferral(
        code: String,
        refereeId: String
    ) async throws -> ReferralResult {
        var request = URLRequest(url: apiURL.appendingPathComponent("/referrals/validate"))
        request.httpMethod = "POST"

        let payload = ReferralValidation(code: code, refereeId: refereeId)
        request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        request.httpBody = try JSONEncoder().encode(payload)

        let (data, response) = try await URLSession.shared.data(for: request)

        guard let httpResponse = response as? HTTPURLResponse,
              httpResponse.statusCode == 200 else {
            throw ReferralError.invalidCode
        }

        let result = try JSONDecoder().decode(ReferralResult.self, from: data)
        return result
    }
}

    let code: String
    let refereeId: String
}

struct ReferralResult: Codable {
    let referrerId: String
    let refereeReward: Double
    let referrerReward: Double
    let referrerBalance: Double
}

enum ReferralError: Error {
    case invalidCode
    case alreadyUsed
    case expired
}
```

### ディープリンクのセキュア化

```swift
class SecureDeepLinkValidator {
    private let validHosts = ["myapp.com", "www.myapp.com"]

    func validateDeepLink(_ url: URL) -> Bool {
        // Webリンクはhttpsのみ受け入れ
        if let scheme = url.scheme, scheme != "https" {
            return false
        }

        // ホストを検証
        if let host = url.host {
            guard validHosts.contains(host) else { return false }
        }

        // URL構造を検証
        let components = URLComponents(url: url, resolvingAgainstBaseURL: true)
        guard let path = components?.path else { return false }

        // 有効なパスをホワイトリスト
        let validPaths = ["/products", "/users", "/articles", "/invite"]
        let isValidPath = validPaths.contains { path.starts(with: $0) }

        return isValidPath
    }

    // 紹介コードを暗号的に検証
    func validateReferralCode(_ code: String) -> Bool {
        // HMAC署名を検証
        guard let decodedCode = Data(base64Encoded: code) else { return false }

        let signature = decodedCode.prefix(32)
        let payload = decodedCode.suffix(from: 32)

        let expectedSignature = HMAC(
            key: "your-secret-key".data(using: .utf8)!,
            data: payload,
            algorithm: .sha256
        ).digest

        return signature == expectedSignature
    }
}
```

## 公式ドキュメントに書かれていない、運用で踏んだ落とし穴

ここからは、Apple/Google の公式ドキュメントにも SDK の README にも書かれていない、実際の配信でぶつかった落とし穴と、その回避策をまとめます。Rork Max のコード生成は基本実装としては優秀ですが、収益化とグロース観点で見ると、生成直後のコードのままだと取りこぼす数値がいくつもあります。

### 知見1: AASA キャッシュは「24 時間」よりずっと長い

Apple の公式ドキュメントは Universal Links のサーバー側ファイル（`apple-app-site-association`）について「24時間キャッシュされる」と説明していますが、現実には iOS 端末によっては **2〜3 週間** 古いキャッシュを掴み続けるケースを観測しました。私が運用している壁紙アプリのリリースでは、ドメイン移転後の AASA 反映を待つあいだに、新規ユーザーの **約 4.2%** が Universal Link を踏んでも Safari にフォールバックしていました。

対応として、移行期は「旧ドメインの AASA に新旧両方の `appID` を併記する」「アプリ側で `application(_:continue:restorationHandler:)` を叩くたびに 404 リダイレクトを検知して `SFSafariViewController` をフォールバック起動する」の二重防御を入れています。Rork Max の初期生成コードはここまでカバーしてくれないので、必ず手動で `continueUserActivity` に検証ロジックを足してください。

```swift
// Rork Max 生成コード + フォールバック検出
func application(_ application: UIApplication,
                 continue userActivity: NSUserActivity,
                 restorationHandler: @escaping ([UIUserActivityRestoring]?) -> Void) -> Bool {
    guard userActivity.activityType == NSUserActivityTypeBrowsingWeb,
          let url = userActivity.webpageURL else { return false }

    // ① AASA ステータスを軽量 HEAD でセルフチェック（ユーザーには非可視）
    Task.detached(priority: .background) {
        let head = URLRequest(url: URL(string: "https://yourdomain.com/.well-known/apple-app-site-association")!,
                              cachePolicy: .reloadIgnoringLocalCacheData)
        if let (_, response) = try? await URLSession.shared.data(for: head),
           let http = response as? HTTPURLResponse, http.statusCode != 200 {
            Analytics.logEvent("aasa_stale", parameters: ["url": url.absoluteString])
        }
    }

    return handleDeepLink(url)
}
```

`aasa_stale` イベントを Firebase Analytics に流しておくと、ドメイン移転や CDN 設定ミスを 24 時間以内に検知できます。私の運用では Crashlytics と組み合わせて、AASA 取得失敗が DAU の 1% を超えたら Slack に通知が飛ぶようにしてあります。

### 知見2: 遅延ディープリンクの「クリップボード経由」は iOS 14 以降で許可率が劇的に変わる

遅延ディープリンク（Deferred Deep Linking）の古典的な実装はクリップボード経由ですが、iOS 14 で「ペーストを許可しますか?」のダイアログが導入されてから、私のアプリ群では **クリップボード経由の attribution 成功率が 87.3% → 21.4%** まで落ちました。

代替手段として現実的なのは以下の 3 つです。

1. **Apple Search Ads Attribution API**（最も正確だが Apple Search Ads 経由のみ）
2. **指紋認証ベース（IP + デバイス特性 + 言語 + タイムゾーン + 起動時刻の組み合わせ）の確率的マッチング** ─ 業界標準で精度 70〜85%
3. **インストール直後のディープリンク要求 API**（Branch.io / Adjust の SDK が内部実装）

私は AdMob 経由の流入が中心なので、Google Play Install Referrer API（Android）と SKAdNetwork 4.0（iOS）の Postback を主軸に据え、クリップボード経由はあくまでフォールバックとして 1 度だけ試行する設計に変更しました。これで attribution 取りこぼしは **DAU の 3.8% → 1.1%** に改善しました。

### 知見3: ユニバーサルリンクが Slack/LINE/Instagram で動かない問題

これは公式ドキュメントが明確に説明していない最大の地雷です。Slack や LINE や Instagram のアプリ内ブラウザは **WKWebView ベースの独自実装** で、ユニバーサルリンクを意図的に無視します（自社アプリへの離脱を防ぐため）。

私が運用している引き寄せ系アプリで、Instagram ストーリーズの「リンクスタンプ」経由の流入は、当初 Universal Link でディープリンクされる前提でしたが、実測すると **97.6% が in-app browser に留まったまま** でした。

対策としては「ランディングページ側で `window.location.replace('myapp://...')` を JavaScript で発火させる」「同時に App Store / Play Store の URL も表示してユーザー自身に選ばせる」の二段構えが現実的です。次のような HTML を Rork Max の Web ランディングに足しています。

```html
<script>
(function() {
  const isInAppBrowser = /FBAN|FBAV|Instagram|Line|Twitter|MicroMessenger|WeChat/i.test(navigator.userAgent);
  const fallback = setTimeout(() => {
    window.location.href = "https://apps.apple.com/app/idXXXXXXXX";
  }, 1500);

  // ユニバーサルリンクを試行（in-app browser でも一応叩いておく）
  window.location.href = "https://yourdomain.com/open?path=" + encodeURIComponent(window.location.pathname);

  // in-app browser の場合は明示的にカスタムスキームも試す
  if (isInAppBrowser) {
    setTimeout(() => {
      window.location.href = "myapp://" + window.location.pathname.replace(/^\//, "");
    }, 100);
  }
})();
</script>
```

この対策を入れる前と後で、Instagram 流入のアプリ起動率は **2.4% → 18.7%** に上がりました。広告予算が同じでもインストール CPI が下がる効果は大きく、AdMob リターゲティング含めた月次広告効率が **11% 改善** しました。

### 知見4: Android App Links の verified status が突然 false になる

Google Play Console の Digital Asset Links は CI/CD で `keytool` 経由の SHA256 fingerprint が変わると無音で失効します。私は Rork Max が Android ビルドの署名鍵をローテートしたタイミングで、App Links が 1 週間まったく動かない事故を起こしました（GSC 経由で気づくまで時間がかかった）。

対策として、CI のリリース後フックで次のコマンドを叩いて検証しています。

```bash
# .github/workflows/post-release-android.yml
curl -s "https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://yourdomain.com&relation=delegate_permission/common.handle_all_urls" \
  | jq '.statements[] | select(.target.androidApp.packageName == "com.yourapp")'
```

返り値が空なら Slack に通知。これで App Links 失効を 1 時間以内に検知できるようになりました。

## フォールバック 3 段の、どの脚で開いたのかを残す

Instagram 対策（知見3）を入れてひと月が過ぎた頃、経路別の数字を出そうとして手が止まりました。起動率は上がっていましたが、上がった分がユニバーサルリンクで開いたのか、カスタムスキームで開いたのか、ストアを一度挟んで戻ってきたのかが、ログのどこにも残っていなかったのです。効いた対策を翌月も再現するには、結果の数字だけでは足りません。

ランディングからアプリ起動までの経路は、実際には 3 段あります。

1. **ユニバーサルリンク**: `https://yourdomain.com/...` をそのまま開く脚
2. **カスタムスキーム**: `myapp://...` へ落とす脚（in-app browser 用のフォールバック）
3. **ストア URL**: どちらも開かなかったときの脚

このうち真ん中の脚だけが、計測から抜け落ちる前に**ユーザーごと**抜け落ちやすい構造になっています。

### カスタムスキームの脚が、例外も出さずに死ぬ理由

iOS 9 以降、`UIApplication.canOpenURL(_:)` は `Info.plist` の `LSApplicationQueriesSchemes` に宣言していないスキームに対して、相手のアプリが入っているかどうかにかかわらず常に `false` を返します。未宣言のスキームを総当たりして他アプリの導入状況を探る挙動を防ぐための制限です。このとき出るのは、Xcode のコンソールに流れる一行だけです。

```
-canOpenURL: failed for URL: "myapp://referral/ABC123" - error:
"This app is not allowed to query for scheme myapp"
```

例外は飛びません。クラッシュもしません。ですから `if canOpenURL { 開く } else { ストアへ }` という分岐を書いていると、**アプリを入れている人まで全員がストアへ流れます**。しかもストアへ渡した時点で紹介コードは落ちますので、リワードの付与と帰属が同時に消えます。計測が欠けていたのではなく、計測する手前でユーザーが別の道へ逸れていた、というのが私の手元で起きていたことでした。

Rork Max はネイティブ Swift を出しますから、この分岐も素直な形で生成コードの中に現れます。素直であるぶん、宣言漏れもそのまま残ります。

### 宣言を足すより、`canOpenURL` を呼ぶのをやめる

直し方は 2 通りあります。宣言を足すか、問い合わせ自体をやめるかです。

`open(_:options:completionHandler:)` は `LSApplicationQueriesSchemes` の制限を受けません。開けたかどうかは完了ハンドラが `Bool` で返してくれますので、「開けるか確かめてから開く」ではなく「開いてみて、駄目だったときだけ次の脚へ」と書けば、宣言を一つも足さずに 3 段が成立します。

**問い合わせには宣言が要り、実行には要りません。** この一行を腹に落としてから、私は自分のアプリのスキームに対して `canOpenURL` を呼ぶのをやめました。

```swift
// フォールバック 3 段。開いた脚を必ず 1 本だけ記録します
enum LinkLeg: String {
    case universal   // ① ユニバーサルリンク（continueUserActivity 側で記録）
    case scheme      // ② カスタムスキーム
    case store       // ③ ストア URL
}

@MainActor
func openWithFallback(path: String, referral: String?) async {
    var scheme = URLComponents()
    scheme.scheme = "myapp"
    scheme.host = "open"
    scheme.path = path
    scheme.queryItems = referral.map { [URLQueryItem(name: "ref", value: $0)] }

    // canOpenURL は呼びません。開いてみて、返ってきた Bool で判定します
    if let url = scheme.url,
       await UIApplication.shared.open(url, options: [:]) {
        record(.scheme, path: path, hasReferral: referral != nil)
        return
    }

    // ストアへ落とすときも紹介コードは捨てません（復帰後に ct から拾い直します）
    var store = URLComponents(string: "https://apps.apple.com/app/idXXXXXXXX")!
    store.queryItems = [
        URLQueryItem(name: "pt", value: "YOUR_PROVIDER_TOKEN"),
        URLQueryItem(name: "ct", value: referral ?? "organic"),
        URLQueryItem(name: "mt", value: "8"),
    ]
    await UIApplication.shared.open(store.url!, options: [:])
    record(.store, path: path, hasReferral: referral != nil)
}

func record(_ leg: LinkLeg, path: String, hasReferral: Bool) {
    Analytics.logEvent("deep_link_opened", parameters: [
        "link_leg": leg.rawValue,
        "path": path,
        "has_referral": hasReferral,
    ])
}
```

なぜこう書くのか、を二点だけ補足します。ひとつは、`record` を各脚の分岐の中に 1 回ずつしか置いていないことです。フォールバックは入れ子になりやすく、成功と失敗の両方でイベントを吐くと、起動 1 回に対して 2 件が流れて脚の比率が崩れます。もうひとつは、③ でも `ct` に紹介コードを載せていることです。知見1 で足した `continueUserActivity` 側には `record(.universal, ...)` を 1 行だけ添えれば、3 段がひとつの指標で並びます。

宣言が本当に必要になるのは、他社アプリを開けるかどうかで UI を出し分けるときです——共有シートに「LINE で送る」を出すかどうか、といった判断です。その場合は Expo / Rork の設定側に書きます。

```json
{
  "expo": {
    "ios": {
      "infoPlist": {
        "LSApplicationQueriesSchemes": ["line", "twitter", "instagram"]
      }
    }
  }
}
```

ここに、時間を溶かしやすい点がひとつあります。`Info.plist` はネイティブバイナリに焼き込まれますので、**この変更は OTA では反映されません**。新しいバイナリをビルドして配るまで、`canOpenURL` は `false` を返し続けます。「宣言を足したのに直らない」という詰まり方のかなりの部分が、これでした。宣言できるスキームの上限は 50 個です。並べるほど審査で用途を訊かれやすくなりますので、実際に UI を出し分けるものだけに絞っています。

より詳しい切り分け手順は[Rork で Linking.canOpenURL が iOS だけ false を返す ─ LSApplicationQueriesSchemes 設定漏れの直し方](/articles/rork-dev/rork-linking-canopenurl-ios-false-lsapplicationqueriesschemes-fix)に書き残しました。

### Rork Max 生成コードでありがちな取りこぼし

Rork Max は SKAdNetwork のスキャフォールドコードまでは生成しますが、**conversion value の更新ロジック** はテンプレートで止まることが多いです。これを放置すると、Apple からの postback で受け取れる情報が「インストールしたかどうか」だけになり、LTV 推定がほぼ不可能になります。

私の運用では、初回起動から 24 時間以内の「課金ファネル進捗」を 6 ビットの conversion value にエンコードしています。

```swift
enum OnboardingMilestone: Int {
    case launched = 0
    case viewedPaywall = 1
    case startedTrial = 2
    case completedOnboarding = 3
    case firstSession2Min = 4
    case secondDayReturn = 5
}

func updateConversionValue(for milestone: OnboardingMilestone) {
    // SKAdNetwork 4.0 の coarse-grained value（low/medium/high）にもマッピング
    let coarse: SKAdNetwork.CoarseConversionValue = {
        switch milestone {
        case .launched, .viewedPaywall: return .low
        case .startedTrial, .completedOnboarding: return .medium
        case .firstSession2Min, .secondDayReturn: return .high
        }
    }()

    SKAdNetwork.updatePostbackConversionValue(milestone.rawValue,
                                              coarseValue: coarse,
                                              lockWindow: false) { error in
        if let error { Crashlytics.crashlytics().record(error: error) }
    }
}
```

このマイルストーン設計に切り替えたあと、Apple Search Ads の最適化アルゴリズムが拾える信号が増えて、**Cost per Trial が 23% 低下** しました。Rork Max 生成コードのまま放置していると、ここの数字を取り逃します。

## 私が現場で使っているチェックリスト

最後に、リリース前の最終確認に使っているチェックリストを共有します。Rork Max でディープリンクを実装するときは、生成完了後にこのリストを全て通してから TestFlight / Play Console 内部テストに上げています。

1. ✅ AASA / assetlinks.json が **HTTP 200** で返ること（HTTPS 必須、HTTP リダイレクト不可）
2. ✅ AASA のキャッシュコントロールヘッダが `Cache-Control: public, max-age=3600` 以下であること
3. ✅ Universal Link を Notes アプリ / Mail から踏んだときと、Safari から踏んだときの両方でアプリが開くこと
4. ✅ Android App Links が `adb shell pm get-app-links com.yourapp` で `verified` 状態であること
5. ✅ クリップボード経由の遅延ディープリンクが iOS 14+ の「ペースト許可」UI を出すこと
6. ✅ Slack / LINE / Instagram in-app browser からの起動経路を用意し、開いた脚が `link_leg` として残ること
7. ✅ SKAdNetwork conversion value が onboarding ファネル全段で発火すること
8. ✅ Firebase Analytics に `deep_link_received` / `aasa_stale` / `attribution_source` の 3 イベントが流れること
9. ✅ 紹介プログラムのリワード付与に **べき等性チェック** が入っていること（同じ `referralId` で 2 回叩いても重複しない設計）
10. ✅ 本番ドメインの ATS 設定が `NSExceptionDomains` の例外なしで通ること

この 10 項目が全て緑になるまで、私は広告の出稿予算を上げないことにしています。計測に穴を残したまま配信量だけを増やすと、増えた分がどこから来たのか分からなくなり、次の判断材料が一つも残らないためです。

## 次の一手

ここまでの実装で、リンクは「開く」から「どこから来たかを残す」へ変わります。

最初に取りかかるなら、AASA と `assetlinks.json` の配信確認からです。ここが崩れていると、後段のコードをどれだけ丁寧に書いても届きません。次に `continueUserActivity` のフォールバック、その後に SKAdNetwork の conversion value という順序が、私の手元では最も手戻りが少なくなりました。

紹介プログラムまで踏み込むのは、この 3 段が安定してからで遅くありません。遅延ディープリンクは、経路が正しく記録されている前提の上にしか成り立たないためです。

Rork Max が出したコードをそのまま信じきらず、一度は自分の手で計測経路を辿ってみてください。生成されたコードの正しさよりも、自分がどこを見て判断しているかのほうが、長く効いてきます。

同じところでつまずいた方の遠回りが、少しでも短くなればと願っています。
