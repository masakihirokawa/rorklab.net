Rork Max に最初のプロンプトを渡したとき、「ワークアウトトラッカーを作って。エクササイズ、セット、レップス付き」と一行だけ書いたことがあります。返ってきたのは、動きはするけれど、どこにでもある見た目のアプリでした。画面の遷移も、空のときの表示も、すべて AI の推測です。直す依頼を重ねるうちに、最初から書き直したほうが早かったと気づいたのは、数回やり取りしたあとでした。

最初にお伝えしたいのは、**プロンプトは仕様書というより、AI に渡す「ユーザーの一日」だ**ということです。書き直しを繰り返して残った10個の線引きを、弱い例と強い例で並べてまいります。なお、Rork Max が内部でどのモデルを使うかは更新されていくため、ここでは触れません。書き方の話だけに絞ります。

## プロンプトが効く理由

生成の途中で、AI はナビゲーションの構造、データの持ち方、配色、アニメーション、エラー時の振る舞いを、数えきれないほど決めています。私たちが渡せる手がかりは、ほぼプロンプトだけです。書かれていない部分は、無難な既定値で埋められます。

ですから、修正の回数を減らす近道は、後から直す依頼を上手にすることよりも、最初の一通で「決めてほしくないこと」を先に書いておくことでした。

## コツ1: 機能ではなく、ユーザーの流れを書く

機能の名前を並べても、AI はつなぎ方を知りません。アプリを開いてから閉じるまでに何が見えて、何を押すのかを、順に書きます。

弱い例です。

```
ワークアウトトラッカーアプリを作って。エクササイズ、セット、レップス機能付き。
```

強い例です。

```
ワークアウトトラッカーアプリを作成してください。アプリを開くと
今日のワークアウトプランがカード形式で表示されます。カードを
タップするとセットとレップスがチェックボックス付きで展開されます。
フローティングの「+」ボタンでカスタムエクササイズを追加できます。
全セット完了後にお祝いアニメーションが再生され、ワークアウト
サマリーがボトムタブの履歴画面に保存されます。
```

流れを書くと、画面と画面のつながりが一本の筋として伝わります。

## コツ2: 見た目は、最初に数字で決める

デザインを指定しないと、既定の見た目になります。私が失敗したのは「落ち着いた雰囲気で」とだけ書いたときで、落ち着きの解釈が毎回変わりました。

```
ダークテーマを使用。主背景はディープネイビー(#1A1B2E)。
操作できる要素のアクセントはブルー(#4A90D9)、テキストは
ソフトホワイト(#F0F0F5)。見出しは SF Pro Rounded、本文は
SF Pro Text。カードは角丸16ptで、すりガラス風の効果を付ける。
```

色は HEX、角丸は pt、フォントは名前まで書きます。曖昧な形容詞を、数字に置き換えるイメージです。

## コツ3: ナビゲーションを言い切る

画面のつながり方を AI に推測させると、遷移の不整合が起きやすくなります。

```
4つのタブバーを使用: ホーム(家アイコン)、検索(虫眼鏡)、
お気に入り(ハート)、プロフィール(人物)。ホームタブは
NavigationStack で詳細へ掘り下げる。検索タブは上部に検索バー、
その下にフィルターのチップを置く。
```

## コツ4: 空の状態とエラーの状態を書く

実際のアプリは、データが無いとき、通信が切れたとき、思わぬ入力が来たときに、本当の出来が出ます。

```
レシピ一覧が空のときは、イラストと「まだレシピがありません。+ を
タップして最初の一つを追加しましょう」を表示。通信に失敗したら
「読み込めませんでした。接続を確認して再試行してください」と
再試行ボタンを出す。読み込み中はカードに合わせたスケルトン表示。
```

ここを書き忘れると、実機で最初に開いた瞬間、真っ白な画面と向き合うことになります。

## コツ5: 大きなアプリは、四回に分けて頼む

一度にすべてを書くより、段階に分けたほうが確実でした。

1. 一回目: 主要な画面とナビゲーション
2. 二回目: データの保存と状態管理
3. 三回目: アニメーションと仕上げ
4. 四回目: HealthKit や ARKit など、ネイティブ機能の追加

各回は前回の結果の上に積み重なります。**一度に頼むのは一つの層だけ。** この線引きを守るようにしてから、やり直しがはるかに減りました。

## コツ6: Apple のフレームワーク名を、そのまま書く

Rork Max はネイティブの Swift を生成するので、API 名で頼めます。

```
一覧と詳細の遷移に SwiftUI の .matchedGeometryEffect を使う。
ボタンのタップには UIImpactFeedbackGenerator で触覚フィードバックを
付ける。タイマーのカウントダウンは Live Activity で Dynamic Island に出す。
```

名前を出すと、似た別の方法に逸れる余地が減ります。ただし、存在しない API 名を書くと、AI が辻褄を合わせようとして迷走することがあります。名前は、公式のドキュメントで確かめてから書いています。

## コツ7: データモデルを、型まで書く

構造のあるデータを扱うなら、モデルを先に渡します。

```
データモデル:
- Recipe: title(String)、ingredients(Ingredient の配列)、
  steps(String の配列)、prepTime(Int・分)、
  difficulty(列挙型: easy/medium/hard)、isFavorite(Bool)
- Ingredient: name(String)、quantity(Double)、unit(String)
- MealPlan: date(Date)、meals(朝・昼・夜を Recipe に結ぶ辞書)
```

これを省くと、あとで項目を足すたびに、保存済みのデータとの整合が崩れます。

## コツ8: 近い見た目の例を、そっと添える

気に入っている画面があれば、名前を出して構いません。

```
習慣トラッカーは、GitHub のコントリビューショングラフのような
連続記録のカレンダーにする。完了した日は緑、未達成は灰色で、
濃淡で強さを示す。週の表示は Apple のヘルスケアのリングに似せる。
```

言葉で長く説明するより、一行の参照のほうが、ずっと正確に伝わります。

## コツ9: 動きを秒数まで書く

動きを任せきりにすると、試作品のような手触りになります。

```
タスクを完了したら、チェックボックスがスプリングアニメーション
(0.4秒、わずかなバウンス)で塗りつぶされる。カードは0.3秒の
ease-in-out で「完了」の区画へ移る。完了時に .sensoryFeedback(.success) を使う。
```

## コツ10: 実機に入れて、指で確かめる

QR コードを読み取って iPhone に入れられるので、生成のたびに実機で触ります。タップできる範囲、スクロールの重さ、アニメーションの滑らかさ、文字の読みやすさは、シミュレーターでは気づきにくい部分です。

観察は、次の依頼にそのまま使います。「UI をもっと良くして」ではなく、「下のタブのアイコンが小さい。タップできる範囲を 44×44pt 以上にして」と書くほうが、はるかに通ります。

## 個人開発の目で見直して分かったこと

私は個人開発で壁紙アプリを長く運用しています。ストアの説明文やレビュー返信、多言語の表記を毎日のように触っていると、利用者が「何に困って、どこで手が止まるか」には敏感になります。Rork Max に渡すプロンプトを書くときも、結局はこの目線に戻ってきました。

たとえば壁紙アプリなら、「一覧を開く」「気に入った一枚を選ぶ」「保存する」「端末の壁紙に設定する」という一本の流れが先にあります。機能名を並べるより、この流れを一文ずつ書いたほうが、AI の返す画面の順番が自然になりました。逆に、保存に失敗したときの表示や、通信がない場所での一覧の空き方を書き忘れると、実機で真っ先に気づくのは自分自身です。胃が痛くなるのは、公開してからレビューで指摘される場合でした。

もう一つは、依頼の分け方です。見た目を整える依頼と、データの持ち方を変える依頼を同じ回に混ぜると、どちらの原因で崩れたのか分からなくなります。一回に一つの層だけ。個人で全部を見る立場だからこそ、切り分けやすい頼み方がいちばん効くのだと思います。

## 叩き台のテンプレート

手が止まったときは、次の形から埋めています。

```
[アプリの種類]アプリを[想定する人]向けに作成してください。

## 主な機能
[3〜5個。ユーザーの流れを添えて]

## 見た目
[配色、タイポグラフィ、コンポーネントの形]

## ナビゲーション
[タブの構成や遷移]

## データ
[主なモデルと関係]

## ネイティブ機能
[使う Apple のフレームワーク]

## 空・エラー・読み込み
[それぞれの表示]
```

## 試す順番と、守っている線引き

まずは手元のアプリで、コツ1とコツ4の二つだけを書き足して、もう一度生成してみていただければと思います。流れと空の状態は、書く手間のわりに結果が大きく変わる部分です。

**決めてほしくないことは、AI の推測に任せず、先に書く。** この線引きだけは、急いでいる日でも崩さないようにしています。
