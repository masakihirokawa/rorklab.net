Rork Max でアプリを作るのはずいぶん速くなりましたが、App Store の審査プロセスは AI が生成したコードかどうかを問わず、同じ基準で評価されます。そして、初めて申請する人が引っかかるポイントは、かなりはっきりしたパターンがあります。

このガイドでは、Rork Max で作成したアプリを App Store に公開するまでの流れと、よくある審査却下の理由・対処法を実践的にまとめました。

## App Store 審査の基本を理解する

Apple の審査チームは、申請されたアプリを以下の観点で評価します。

**安全性（Safety）**
- 有害なコンテンツがないか
- ユーザーのプライバシーが適切に扱われているか

**パフォーマンス（Performance）**
- クラッシュせずに動作するか
- バッテリーやメモリを過剰に使用していないか

**ビジネス（Business）**
- 課金フローが Apple のガイドラインに準拠しているか
- 機能の説明が正確か

**デザイン（Design）**
- Apple の Human Interface Guidelines に沿っているか
- ユーザビリティが十分か

**法律（Legal）**
- 知的財産権の侵害がないか
- プライバシーポリシーが適切か

Rork Max で生成されたコードがそのままでは引っかかりやすいのは、主にパフォーマンスとデザインの項目です。

## よくある却下理由と対処法

### 却下理由1: クラッシュ・バグ（最多）

App Store 審査で最も多い却下理由は、審査員がアプリを操作した際のクラッシュです。

**提出前の必須チェックリスト**

```
□ iPhone の最小サポートバージョン（iOS 16以上を推奨）でテストした
□ ネットワークがない状態（機内モード）でアプリを起動してテストした
□ ログインなしで使える機能はゲストでも動作確認した
□ すべての画面を手動でタップして確認した
□ 入力フォームに空文字・特殊文字・非常に長い文字列を入力してテストした
□ アプリをバックグラウンド → フォアグラウンドに戻した後も正常に動作するか確認した
```

Rork Max にこのチェックリストを渡してバグを直してもらうのが効率的です。

```
「以下のシナリオでアプリが正しく動作するか確認して、問題があれば修正してください：
1. ネットワークがない状態でアプリを起動する
2. ログインせずにすべての画面を操作する
3. フォームに空文字を送信する
4. アプリをバックグラウンドにして5分後にフォアグラウンドに戻す
5. デバイスの言語を英語に変更してアプリを開く」
```

### 却下理由2: プライバシーポリシーがない・不適切

カメラ・マイク・位置情報・写真・連絡先などの機密情報にアクセスする場合、プライバシーポリシーが必須です。

**プライバシーポリシーの必須要件**

```
✅ Webページとして公開されている（App Store にURLを入力する）
✅ アプリ名と開発者名が明記されている
✅ 収集するデータの種類が具体的に記載されている
✅ データの使用目的が説明されている
✅ データの共有先（サードパーティ）が記載されている
✅ データの保持期間が記載されている
✅ ユーザーがデータ削除を要求できる手段が説明されている
✅ 連絡先（メールアドレス等）が記載されている
```

プライバシーポリシーは Rork 内で生成することも、Notion や GitHub Pages で公開することもできます。重要なのは「アクセス可能な URL に公開されていること」です。

**情報収集の申告（App Privacy）**

App Store Connect の「App Privacy」セクションで、アプリが収集するデータを正確に申告する必要があります。よく見落とされるのは以下です。

```
よく申告漏れがあるデータ:
- クラッシュログ・診断データ（自動収集している場合）
- ユーザーID（Firebase Authentication など）
- デバイス識別子
- 使用状況データ（どの画面を見たか等）
```

不正確な申告は審査通過後に削除要求や警告の原因になります。

### 却下理由3: メタデータと実際の機能の不一致

**タイトルと説明文**

App Store のタイトル（30文字以内）と説明文（4,000文字以内）は、実際のアプリ機能と正確に一致している必要があります。

```
✅ 機能を正確に説明しているか
✅ 使用していない機能・サービスへの言及がないか
✅ 競合他社の名前・商標が含まれていないか
✅ 「最高」「ナンバーワン」等の根拠のない表現を使っていないか
```

**スクリーンショット**

スクリーンショットは実際のアプリ画面である必要があります。審査員はスクリーンショットと実際のアプリを照合します。

```
iPhone スクリーンショット要件:
- 6.7インチ（iPhone 15 Plus等）: 1290×2796 px
- 6.5インチ（iPhone 15 Pro Max等）: 1284×2778 px または 1242×2688 px
- 必要なサイズのスクリーンショットが揃っているか確認する

最低限: 6.7インチか6.5インチのどちらかがあれば代用可
最大: 10枚まで
```

### 却下理由4: コンテンツレーティングの不一致

アプリの年齢制限を実際のコンテンツより低く設定すると却下されます。

```
年齢レーティングのガイド:
4+ : 暴力・性表現・ホラー・薬物・ギャンブル要素が一切ない
9+ : 軽微な暴力・ホラー表現（カートゥーン程度）
12+: リアルなまたは激しい暴力・恋愛表現・性的示唆
17+: 成人向け暴力・性的内容・レアル過激コンテンツ
```

### 却下理由5: Apple ガイドラインへの非準拠

Rork Max が生成したコードに含まれやすい非準拠パターンです。

**Web ブラウザを独自実装している場合**

アプリ内でウェブコンテンツを表示する場合、`SFSafariViewController` または `WKWebView` を使う必要があります。独自のURLナビゲーションをウェブブラウザとして実装することは許可されていません。

**課金がある場合**

デジタルコンテンツ・サービスへの課金は必ず Apple の In-App Purchase（IAP）を使う必要があります。外部決済サービスへの誘導は原則禁止です（一部例外あり）。

```
「課金機能を StoreKit 2 を使った In-App Purchase に実装してください。
 サブスクリプションプランは月額プランと年額プランの2種類を用意してください。
 復元購入機能も実装してください」
```

## 審査申請前の最終チェック

```
メタデータ:
□ アプリ名（30文字以内）
□ サブタイトル（30文字以内）
□ 説明文（4,000文字以内）—— 実際の機能と一致しているか
□ キーワード（100文字以内）—— カンマ区切り
□ プロモーションテキスト（170文字以内）
□ サポートURL（アクセス可能なWebページ）
□ プライバシーポリシーURL（アクセス可能なWebページ）

スクリーンショット:
□ 6.7インチまたは6.5インチのスクリーンショット（最低1枚）
□ iPad対応の場合: 12.9インチのスクリーンショット
□ スクリーンショットが実際の画面と一致しているか

プライバシー:
□ App Privacy の申告が正確か
□ カメラ・位置情報等の使用許可の説明文が適切か（NSPhotoLibraryUsageDescription 等）

機能テスト:
□ 審査員用デモアカウントを用意したか（ログインが必要な場合）
□ すべての主要機能を実機でテストしたか
□ クラッシュが0件か確認したか
```

## 却下された場合の対応

審査で却下された場合、Rejection メールに具体的な理由が記載されています。

**対応手順**

1. Rejection メールの理由を読む
2. App Review Board にコメントを送る（不明点の質問も可能）
3. 問題を修正してアプリを再申請する

修正が完了したら Rork Max に却下理由とともに修正を依頼します。

```
「App Store 審査で以下の理由で却下されました。対応してください：

却下理由:
Guideline 5.1.1 - Data Collection and Storage
Your app collects user's name without clearly disclosing what this data is used for.

対処:
ユーザーの名前を収集する際に、その使用目的を明示するダイアログを表示してください。
また、アカウント削除機能も画面内に追加してください」
```

---

Rork Max でアプリを作る速さと、App Store 審査を通過する確実さは別の話です。申請前のチェックリストを丁寧にこなして、初回から審査を通過できる状態で提出することが、結局最も速い公開への道です。

まずプライバシーポリシーを作ることから始めてください。これがないと申請フォーム自体が完成しません。Notion の無料プランで十分なので、今日中に公開 URL を用意しておきましょう。

## 審査通過後の運用 — 評価とアップデート

App Store に公開されてからが本当のスタートです。審査を通過した後の運用についても触れておきます。

### ユーザーレビューへの対応

App Store のレビューは、アプリの評価（星の数）に直接影響します。評価が下がると検索順位にも影響するため、早期のネガティブレビューへの対応は重要です。

**レビューへの返信ポリシー**

```
✅ すべてのレビューに72時間以内に返信する（特にネガティブなもの）
✅ 具体的な問題報告には修正予定を伝える
✅ ポジティブなレビューには感謝の言葉を伝える
✅ 個人情報には言及しない
```

返信はすべてのユーザーが見ることができます。礼儀正しく、問題解決に積極的な姿勢を見せることが大切です。

**クラッシュレポートの確認**

App Store Connect の「Crashes」セクションで、ユーザーから報告されたクラッシュを確認できます。

```
「App Store Connect のクラッシュレポートに以下のエラーが報告されています。
 修正してください：
 
 EXC_BAD_ACCESS (SIGSEGV) at ProductDetailViewController.swift:45
 
 このエラーは商品詳細画面を素早く前後に移動した際に発生しているようです」
```

### アップデートのベストプラクティス

アップデートも審査が必要です。小さな修正でも審査に数日かかる場合があります。

**バージョン管理の方針**

```
バージョン番号の付け方（例）:
1.0.0 — 初回リリース
1.0.1 — バグ修正のみ
1.1.0 — 小さな新機能追加
2.0.0 — 大きなUI変更・主要機能の追加
```

**審査の高速化**

アップデートで「高速審査（Expedited Review）」をリクエストすることができます。重大なバグ修正や緊急のセキュリティアップデートの場合に使用してください。ただし、頻繁に使うと却下されることがあります。

### フィーチャーされるための準備

App Storeの「おすすめ（Feature）」に選ばれると一気にダウンロード数が増えます。フィーチャーされやすいアプリの特徴を知っておくと、開発の方向性が変わります。

```
フィーチャーされやすいアプリの特徴:
- Apple の最新機能（ウィジェット・Live Activities・Dynamic Island等）を使っている
- アクセシビリティ（VoiceOver等）に対応している
- ローカライズ（多言語対応）されている
- デザインが Apple の HIG に準拠している
- 独自のニッチなユーティリティを提供している
```

Rork Max を使って Apple の最新 API に対応する場合は、以下のようにプロンプトで明示してください。

```
「iOS 17以上のウィジェット機能（WidgetKit）を使って、
 ホーム画面に今日のタスク数を表示するウィジェットを追加してください。
 Small・Medium・Large の3サイズに対応してください」
```

## ASO（App Store 最適化）でダウンロードを増やす

審査を通過しただけではダウンロードは増えません。App Store 検索で見つけてもらうための最適化（ASO）も必要です。

### キーワード戦略

App Store のキーワードフィールド（100文字）は、検索順位に直接影響します。

**効果的なキーワードの選び方**

```
✅ 競合の少ない具体的なキーワードを選ぶ（ロングテール）
✅ タイトルや説明文に既に含まれているキーワードは省略する
✅ カンマで区切る（スペースは不要）
✅ 日本語と英語を混在させてよい

❌ 競合他社の名前を使う
❌ 関係のないキーワードを詰め込む
❌ 「アプリ」「ゲーム」等の汎用語を使う（効果が薄い）
```

**キーワードリサーチの方法**

App Store の検索窓にキーワードを入力して、サジェストされる関連キーワードをメモします。人が実際に検索している言葉をそのまま使うことが重要です。

### スクリーンショットの最適化

スクリーンショットはアプリの「顔」です。最初の3枚が最も重要で、ユーザーの70%以上はここで判断します。

**効果的なスクリーンショットの作り方**

```
1枚目: アプリの最も魅力的な機能を見せる（「これ何？」の答え）
2枚目: 2番目に重要な機能または使い方のメリット
3枚目: 社会的証明（レビュー数・ユーザー数等）または機能一覧

各スクリーンショットに:
- 短いキャッチコピー（上部または下部）
- 実際のアプリ画面
- デバイスフレームの表示（任意、清潔感が出る）
```

Rork Max でスクリーンショット用の画面を最適化することも可能です。

```
「App Store のスクリーンショット用に、ホーム画面を整えてください。
 実際のデータではなくサンプルデータを表示して、
 アプリの機能がわかりやすく見えるようにしてください。
 背景は白を基調にして、フォントサイズを少し大きくしてください」
```

### レビュー数を増やす

評価数が少ないと、良い評価でも信頼性が低く見られます。適切なタイミングでレビューを依頼することが大切です。

```
「アプリ内でユーザーにレビューを依頼するダイアログを実装してください。
 StoreKit の requestReview() を使い、以下のタイミングで表示してください：
 - アプリを5回以上起動した後
 - 主要機能を3回以上完了した後
 - 前回のレビュー依頼から60日以上経過した後
 （上記のすべての条件が満たされた時のみ表示する）」
```

Apple のガイドラインにより、1年間に最大3回までレビューダイアログを表示できます。

---

App Store 公開は「ゴール」ではなく「スタートライン」です。公開後のレビュー対応・アップデート・ASO・ユーザー増加の施策を継続することで、じわじわとダウンロード数が伸びていきます。

最初の1週間は積極的にレビューを集める努力をしてください。初期のレビュー数と評価は、その後の検索順位に大きく影響します。友人・知人・SNS のフォロワーに使ってもらい、感想を聞きながら素早くアップデートを繰り返す——この小さなループが、長期的なアプリの成長につながります。
