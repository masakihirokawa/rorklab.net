壁紙アプリの設定画面に日本語フォントを入れた日のことです。実機で起動し直すたびに、ほんの一瞬だけ見慣れたシステム書体が顔を出し、そのあとで目的のフォントに切り替わりました。録画を止めて一コマずつ送って、ようやくその一瞬を確かめられたほどの短さです。それでも、一度気づいてしまうと、起動のたびに目がそこへ吸い寄せられてしまいました。

Web で言う FOIT（Flash of Invisible Text）や FOUT（Flash of Unstyled Text）と同じ現象が、モバイルアプリの起動時にも起きます。Rork のプロンプトに「Noto Sans JP を使ってください」と書いても、読み込みのタイミングまで指定しなければ、この一瞬は残りやすいようです。

最初にお伝えしたいのは、**フォントが読み込まれるまでスプラッシュ画面を手動で保持する**という、地味な対処がいちばん確実だということです。症状の見分け方から順に、書き残します。

## この「一瞬のチラつき」は何が起きているのか

Rork が生成するアプリは Expo + React Native の構成です。JavaScript の評価とネイティブ描画のあいだには、どうしてもラグが生まれます。カスタムフォントの場合、ざっくり次の順で処理が進みます。

1. ネイティブ層がスプラッシュ画面を表示する
2. JavaScript バンドルが読み込まれ、React ツリーが評価される
3. `useFonts` フックがフォントファイルを非同期で読み込み始める
4. React のルートコンポーネントが描画される
5. フォントの読み込みが完了し、テキストが再レンダリングされる

問題は **4 と 5 のあいだ**にあります。フォントの準備が整う前にテキストが描画されると、iOS なら San Francisco、Android なら Roboto で一瞬だけ表示され、そのあとカスタムフォントに差し替わるのです。ユーザーの目には、画面が一瞬瞬いたように映ります。

`fontFamily` をプロンプトで指示するだけでは、この差は埋まりません。描画のタイミングそのものを、こちらで握る必要があります。

## 解決の全体像 — スプラッシュを手動で閉じる

Expo のデフォルトでは、スプラッシュ画面は React のルートがマウントされた瞬間に自動で閉じます。これを、フォントの準備が終わってから手動で閉じる方式に切り替えます。

```bash
# Rork プロジェクトのルートで実行
npx expo install expo-font expo-splash-screen
```

Rork のチャットで「expo-splash-screen を使って、フォント読み込みの完了まで待機する実装に書き換えてください」と頼めば、次の形に近いコードが返ってきます。ただ、細部の堅牢さまで AI に任せてしまい、あとで痛い目を見たことがあります。生成されたコードは、必ず自分の目で読み直すようにしています。

## 最小の実装例 — _layout.tsx に集約する

Expo Router を使う構成なら、読み込みは `app/_layout.tsx` にまとめるのが素直です。フォント読み込み中はスプラッシュを維持し、完了かエラーの時点で手動で閉じます。

```tsx
// app/_layout.tsx
import { Stack } from "expo-router";
import { useFonts } from "expo-font";
import * as SplashScreen from "expo-splash-screen";
import { useEffect } from "react";
import { View } from "react-native";

// 1. スプラッシュの自動非表示を止める
//    これがないと、React のマウント直後にスプラッシュが消える
SplashScreen.preventAutoHideAsync().catch(() => {
  // 二重呼び出しや WebView 環境では無視してよい
});

export default function RootLayout() {
  // 2. カスタムフォントを登録する
  const [fontsLoaded, fontError] = useFonts({
    "NotoSansJP-Regular": require("../assets/fonts/NotoSansJP-Regular.ttf"),
    "NotoSansJP-Bold": require("../assets/fonts/NotoSansJP-Bold.ttf"),
  });

  // 3. 準備完了かエラーの時点でスプラッシュを閉じる
  useEffect(() => {
    if (fontsLoaded || fontError) {
      SplashScreen.hideAsync();
    }
  }, [fontsLoaded, fontError]);

  // 4. 準備ができるまで null を返し、描画しない
  if (!fontsLoaded && !fontError) {
    return null;
  }

  return (
    <View style={{ flex: 1 }}>
      <Stack screenOptions={{ headerShown: false }} />
    </View>
  );
}
```

要になるのは **4 の「準備できるまで `null` を返す」** 部分です。最初の描画を遅らせることで、システムフォントがのぞく隙間をなくしています。`fontError` を条件に入れているのは、フォントファイルが壊れていてもスプラッシュで固まらず、画面へ進めるようにするためです。

### 期待する動作

- 起動時：スプラッシュが以前よりわずかに長く出ます（体感ではフォント読み込み分に数百ミリ秒ほど足されます。端末とフォントの大きさで変わります）
- スプラッシュが消えた瞬間：最初の画面がカスタムフォントで描かれています
- フォントの読み込みに失敗した場合：スプラッシュは閉じ、システムフォントで表示されます。クラッシュはしません

## もうひとつの道 — ビルド時にフォントを埋め込む

ここまでは、実行時に読み込む方式です。Expo には、`expo-font` の config plugin でフォントをネイティブのビルドに埋め込む方法もあります。

```json
{
  "expo": {
    "plugins": [
      [
        "expo-font",
        {
          "fonts": [
            "./assets/fonts/NotoSansJP-Regular.ttf",
            "./assets/fonts/NotoSansJP-Bold.ttf"
          ]
        }
      ]
    ]
  }
}
```

埋め込んだフォントは起動時点で端末側に載っているため、非同期の読み込みを待つ必要が小さくなります。ただし、反映には development build や `prebuild` を通した再ビルドが要り、Expo Go では確認できません。また、`fontFamily` に書く名前の決まり方も `useFonts` とは異なります。対応する SDK のバージョンや指定の細かい作法は変わっていくので、導入前に [公式ドキュメント](https://docs.expo.dev/versions/latest/sdk/font/) で現在の書き方をご確認ください。

私は、Expo Go で素早く確かめたい段階では `useFonts` の方式を使い、リリースが近づいたら埋め込みに寄せるかどうかを検討する、という分け方にしています。両方を残したまま使い分けても、困ることはありませんでした。

## つまずきやすいポイントと対処

### 1. `require` のパスを間違える

`assets/fonts/` に置いたつもりが、実際は `assets/font/` だった、という typo は Metro のバンドル時にエラーとなり、起動が止まります。`Unable to resolve module` と出たら、パスを素直に見直します。

詰まる原因でいちばん多かったのは、ファイル名のハイフンとアンダースコアの食い違い（`Noto-Sans-JP` と `NotoSansJP`）でした。Google Fonts から落とした `NotoSansJP-Regular.ttf` の名前をそのまま使い、`useFonts` のキーと揃えておくのが安全です。

### 2. `fontFamily` にファイル名を書いてしまう

`<Text style={{ fontFamily: "NotoSansJP-Regular.ttf" }}>` のように、拡張子まで書いてしまう間違いです。正しいのは、`useFonts` に渡したキーの文字列です。

```tsx
<Text style={{ fontFamily: "NotoSansJP-Regular", fontSize: 16 }}>
  こんにちは、カスタムフォントの世界へ
</Text>
```

Rork に日本語で指示すると、拡張子つきのコードが返ることがあります。生成のあとで `grep -n "\.ttf\"" app/` を一度かけておくと、実機に載る前に気づけます。

### 3. 古いフォントのまま表示される

フォントを差し替えたのに、シミュレータでは前の書体のまま、という症状です。ほとんどはキャッシュが原因でした。次の順で試しています。

- Metro のキャッシュを消す：`npx expo start --clear`
- シミュレータからアプリを削除して、入れ直す
- Bare workflow なら `ios/build` と `android/build` を消して再ビルドする

### 4. スプラッシュが永遠に消えない

`useFonts` が `[false, undefined]` のまま動かない状態です。多くの場合は、パスが解決できずに `expo-font` が内部でエラーを出しているのに、こちらの条件では拾えていません。開発中だけ、どちらの経路で抜けたかをログで確かめます。

```tsx
useEffect(() => {
  if (fontsLoaded) console.log("[Font] loaded OK");
  if (fontError) console.log("[Font] error:", fontError);
  if (fontsLoaded || fontError) {
    SplashScreen.hideAsync();
  }
}, [fontsLoaded, fontError]);
```

### 5. 開発ビルドでは正しいのに、EAS のビルドだけシステムフォントに戻る

開発中は狙った書体なのに、EAS で作ったバイナリだけシステムフォントに戻ることがあります。確認する順番は次のとおりです。

- フォントファイルが `assets/fonts/` ではなく、独自のパスに置かれていないか
- `app.json` や `app.config.js` の `assetBundlePatterns` が、フォントのフォルダを除外していないか
- `.gitignore` に `assets/fonts/*.ttf` が入り、CI のビルド環境にフォントが存在しないのではないか

自分のプロジェクトで、`.gitignore` にフォントを入れたまま半日を溶かしたことがあります。胃が痛くなるような不具合ではなく、ただただ地味に時間を食う種類でした。`git ls-files assets/fonts/` で手元にリストが出るかを、最初に確かめます。

## Rork のプロンプトで指示するときのコツ

次の 4 点を 1 つのプロンプトに入れると、上のパターンに近いコードが出てきやすいと感じています。

- 使いたいフォントファミリー名と weight（例：Noto Sans JP の Regular と Bold）
- フォントファイルの置き場所（例：`assets/fonts/`）
- `expo-splash-screen` で、読み込み完了まで待機したいこと
- `_layout.tsx` に集約してほしいこと

手元の雛形はこのような形です。

> Noto Sans JP の Regular と Bold を `assets/fonts/` に置きました。`app/_layout.tsx` で `useFonts` を使って読み込み、`expo-splash-screen` で完了までスプラッシュを維持してください。読み込み前は `null` を返して描画を遅らせ、FOUT を防ぎたいです。

気に入らない結果が返ってきたら、「`fontError` も条件に含めてください」のように差分だけを短く足します。一度に全部を伝え直すより、足りないところを小さく足していくほうが、私の場合は結果が安定しました。

## Android で気をつけたいこと

Android は端末ごとの差が大きく、独自の ROM を載せた一部の機種では `fontFamily` の解決が安定しないと聞くことがあります。私の手元ではそこまで追い込んだ検証はできていませんが、Text をラップする共通コンポーネントを作っておくと、書体の指定が一か所にまとまります。

```tsx
import { Text, TextProps } from "react-native";

export function AppText(props: TextProps) {
  return (
    <Text
      allowFontScaling={true}
      {...props}
      style={[
        { fontFamily: "NotoSansJP-Regular", color: "#222" },
        props.style,
      ]}
    />
  );
}
```

全画面で `<Text>` を直接使わず `<AppText>` を通しておけば、あとでフォントを替えたくなったときも修正は一か所で済みます。

## CJK フォントのバンドルサイズを抑える

Noto Sans JP は美しい書体ですが、Regular 単体でも数 MB あります。Regular と Bold の両方を同梱すると、インストールサイズへの影響は無視できません。正確なサイズは配布元のファイルで変わるため、手元のファイルで一度測っておきます。

**グリフのサブセット化**：使う文字が限られているアプリなら、`fonttools` の `pyftsubset` で必要なグリフだけに絞れます。

```bash
pip install fonttools
pyftsubset NotoSansJP-Regular.ttf \
  --unicodes-file=used_unicodes.txt \
  --output-file=NotoSansJP-Regular.subset.ttf
```

ただし、UI の文言を足すたびにサブセットを作り直す必要があります。文言が頻繁に変わるアプリには向きません。

**遅延読み込み**：たまにしか開かない画面のフォントは、起動後に URL から読み込む手もあります。`Font.loadAsync` に `{ Name: { uri: "https://..." } }` の形で渡せますが、その画面では短い読み込み待ちが生じます。

## 私が落ち着いた小さなお作法

フォント周りで、守っておくと未来の自分が楽になる線引きを、次の 4 つにまとめています。

- フォントは `assets/fonts/` に平置きにする（サブフォルダを作らない）
- weight は Regular と Bold の 2 種類に絞る
- `Text` は最初から `AppText` で包んでおく
- 読み込みのロジックは `_layout.tsx` の一か所に集約する

**フォントは一か所で受け、スプラッシュを閉じるのも一か所にします。** 各画面で `useFonts` を呼び始めると、ある日どこかでガードを忘れます。この線引きだけは、急いでいる日でも崩さないようにしています。
