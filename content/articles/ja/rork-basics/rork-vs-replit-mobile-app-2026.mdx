## 二つのタブを開いたまま、手が止まった夜

壁紙アプリの新しい設定画面を試作しようとして、Rork と Replit をブラウザのタブに並べたまま、1時間ほど手が止まったことがあります。どちらのトップページにも「話しかければアプリができる」と書いてあり、見出しだけでは違いが見えなかったのです。

あれから両方とも中身が大きく変わりました。とくに2026年11月の時点では、**同じ「モバイルアプリ」でも、二つはまったく別の言語でアプリを作っています。** Rork は iPhone を Swift、Android を Kotlin で、Replit は Expo（React Native）で作ります。この違いが、無料でどこまで試せるか、ストアへどう出すか、あとで乗り換えられるかを、すべて左右します。

結論を先にお伝えします。**iPhone と Android のストアに出すことが本命なら Rork、Web やサーバーの処理まで同じ場所で育てたいなら Replit** です。ただし、どちらで始めても「あとで丸ごと持っていけばいい」とは考えないほうが安全です。その理由と、乗り換える前に自分のプロジェクトの中身を確かめる方法を、順に書き残します。

料金と画面名は2026年11月26日に各社の公式ページで確認した内容です。申し込む前に、もう一度公式の表示を見ていただければ幸いです。

一つずつ選ぶ理由を言い切ると、こうなります。**SwiftUI や Kotlin のネイティブなコードが欲しいなら Rork、1つのコードで iPhone と Android と Web をまとめて持ちたいなら Replit** です。その中間で迷う方のために、以下の節を用意しました。

## 無料で試せる範囲が、思っていたより狭くなっています

以前の版のこの記事では「Rork は無料でも1日5回まで試せる」と書いておりました。いまは事情が違います。Rork の公式の料金ページには、**Free プランはデザインモードだけで、ビルドモード（実際に動くコードを作る段階）は有料プランから**、と明記されています。

デザインモードでは画面と見た目の提案までが見られます。プレビューで触れる動くアプリにするには、Rork Max（月$20から）が要ります。Max の段階は $20・$200・$500・$900・$1,800 とクレジットの量で分かれていて、機能はどの段階でも同じです。

Replit のほうも変わりました。公式ドキュメントの Starter プランのページには、**2026年11月の時点で新しく登録する方は Starter を選べず、代わりに Core の3日間の無料体験が用意されている**、と書かれています。エディタ内の iOS Simulator と Android Emulator も、Core 以上のプランが対象です。

つまり、どちらも「無料のまま公開まで」は通れません。試すなら、**Rork は無料のデザインモードで画面を固めてから$20の段階へ、Replit は3日間の体験で動くところまで一気に確かめる**、という使い方になります。Rork のクレジットの減り方は「[Rorkの料金プランを正直に比較する：無料とRork Max（月$20〜）の違い](/articles/rork-basics/rork-pricing-plan-honest-comparison-2026)」に詳しく書きました。

## ストアに出すまでの道のりを並べる

ストア公開は、二つの違いがいちばん手触りとして出る場所です。どちらも Apple Developer Program（年会費が要る開発者登録）への加入が前提で、ここは避けられません。

Rork は、公開メニューから App Store と Google Play の両方を扱います。Android については、App Bundle（Play に上げるファイル）への署名から Play への送信まで Rork がまとめて行う、と公式の Android ページにあります。新しい個人の Play アカウントでは、12人のテスターで14日間のクローズドテストが必要という Google 側の条件も、Rork のドキュメントにそのまま書かれています。

Replit は、Publishing タブの「Start publishing to the App Store」から、Expo の「Launch」という流れがエディタの中に開きます。Expo のプロジェクト名を決め、Apple のアカウントでサインインし、アプリ名とバンドル ID を決めると、Replit が証明書を整えてクラウドでビルドし、TestFlight の審査へ送ります。公式チュートリアルは、**バンドル ID は最初のビルドのあと変えられない**と念を押しています。

## よくある誤解を三つ、ほどいておきます

**一つ目は「Rork は React Native（Expo）のツール」という理解です。** 以前はそうでしたが、いまの Rork は新しいプロジェクトを Expo では作りません。公式の比較ページでは、iPhone は Swift、Android は Kotlin、Web は React と書かれています。すでに持っている Expo のプロジェクトは引き続きビルドも公開もできます。この切り替えの影響は「[Rork の新規作成から Expo が消えました。手元のプロジェクトを続けるか、SwiftUI へ作り直すか](/articles/rork-basics/rork-expo-no-longer-new-keep-or-rebuild-swiftui)」で扱いました。

**二つ目は「Replit にはストアへ出す仕組みがない」という理解です。** これも古くなりました。いまの Replit には「Mobile app」という作成の種類があり、TestFlight と App Store への手順が公式ドキュメントに用意されています。ただ、中身は Expo の仕組みの上に乗っているので、Expo のプロジェクト名やスラッグを決める場面が途中で出てきます。

**三つ目は「GitHub に書き出せば、もう片方へそのまま移せる」という理解です。** 二つは作る言語が違いますので、Rork の Swift のコードを Replit の Expo のプロジェクトとして読み込むことはできません。逆に Replit の Expo のコードを Rork に読み込むと、Rork はそれを読んで Swift と Kotlin で作り直します。Rork の公式の移行ガイドも「1対1の再現は目標ではない」と書いています。

## 乗り換える前に、書き出した中身を確かめる

2026年11月25日の Rork の更新で、**GitHub に同期したりダウンロードしたりしたプロジェクトが、Rork の外でも動くようになりました。** iPhone のプロジェクトには Rork の公開アドレスが設定ファイルに入り、Android のプロジェクトもそのままコンパイルできます。一方で、パスワードや秘密鍵は書き出しに含まれません。

ここで一度、私はつまずいたことがあります。以前、Replit で作った画面を Rork へ持ち込もうとしたとき、コードは動くはずだと思い込んでいて、画面が真っ白のままになった原因が環境変数の読み込みにあると気づくまで、半日ほどかかりました。コードより先に、**「このプロジェクトは何でできていて、何が書き出しから抜けているか」**を見ておけば、あの半日は要らなかったのかもしれません。そう気づいたのは、原因が設定の側にあると分かった、その日の夕方でした。

それ以来、書き出したフォルダをまず次のスクリプトにかけるようにしています。Expo なのか Swift なのか Kotlin なのかを判定し、乗り換え先で何が要るかと、秘密らしい値がどこにあるかを並べます。

```bash
#!/usr/bin/env bash
# 使い方: bash stack-check.sh <プロジェクトのフォルダ>
# 書き出したプロジェクトが何でできているか、乗り換え先で何が要るかを表示します
set -u
DIR="${1:-.}"
[ -d "$DIR" ] || { echo "フォルダが見つかりません: $DIR"; exit 2; }
cd "$DIR"

has() { find . -path ./node_modules -prune -o "$@" -print -quit 2>/dev/null | grep -q .; }

echo "== 中身の判定: $DIR =="
STACK=""
if [ -f package.json ] && grep -q '"expo"' package.json; then
  STACK="expo"; echo "Expo（React Native）: package.json に expo があります"
fi
if has -name '*.xcodeproj'; then
  STACK="${STACK} swift"; echo "Swift（Xcode プロジェクト）: $(find . -name '*.xcodeproj' -print -quit)"
fi
if has \( -name 'build.gradle.kts' -o -name 'build.gradle' \); then
  STACK="${STACK} kotlin"; echo "Android（Gradle）: $(find . -path ./node_modules -prune -o \( -name 'build.gradle.kts' -o -name 'build.gradle' \) -print -quit)"
fi
[ -z "$STACK" ] && echo "判定できません（package.json・.xcodeproj・build.gradle のどれもありません）"

echo "== 乗り換え先で要るもの =="
case "$STACK" in
  *expo*) echo "Replit: Mobile app と同じ Expo なので、コードを持ち込める見込みがあります"
          echo "Rork : GitHub から読み込むと Swift / Kotlin で作り直されます（同じコードにはなりません）" ;;
esac
case "$STACK" in
  *swift*|*kotlin*) echo "Xcode / Android Studio: そのまま開けます（iPhone はアプリのフォルダで xed .）"
                    echo "Replit: Mobile app は Expo なので、画面と仕様を渡して作り直しになります" ;;
esac

echo "== 書き出しに含まれない値（自分で入れ直すもの）=="
HITS=$(grep -rIlE '(SECRET|API_KEY|PRIVATE_KEY|SERVICE_ROLE)' . \
  --exclude-dir=node_modules --exclude-dir=.git 2>/dev/null | head -20)
if [ -n "$HITS" ]; then echo "$HITS" | sed 's/^/要確認: /'; else echo "秘密らしい名前の値は見つかりません"; fi
ls -a | grep -E '^\.env' | sed 's/^/環境ファイル: /' || true
```

試しに、iPhone と Android のフォルダを持つプロジェクト（Rork から書き出した形を模したもの）と、`.env` を持つ Expo のプロジェクト（Replit 側を模したもの）を用意して、Linux の bash 5 で実行しました。出力はそのまま次のとおりです。

```text
== 中身の判定: rork-export ==
Swift（Xcode プロジェクト）: ./ios/Wall.xcodeproj
Android（Gradle）: ./android/app/build.gradle.kts
== 乗り換え先で要るもの ==
Xcode / Android Studio: そのまま開けます（iPhone はアプリのフォルダで xed .）
Replit: Mobile app は Expo なので、画面と仕様を渡して作り直しになります
== 書き出しに含まれない値（自分で入れ直すもの）==
秘密らしい名前の値は見つかりません

== 中身の判定: replit-app ==
Expo（React Native）: package.json に expo があります
== 乗り換え先で要るもの ==
Replit: Mobile app と同じ Expo なので、コードを持ち込める見込みがあります
Rork : GitHub から読み込むと Swift / Kotlin で作り直されます（同じコードにはなりません）
== 書き出しに含まれない値（自分で入れ直すもの）==
要確認: ./.env
環境ファイル: .env
```

なぜ言語の判定を最初に置くのかというと、そこで「持ち込み」か「作り直し」かが決まり、かかる手間が一桁変わるからです。秘密の値を最後に並べるのは、11月25日の更新でも書き出しに含まれないと公式に書かれている部分で、乗り換え先で最初に止まるのがここだからです。実際の Rork の書き出しでフォルダ名が上の例と違っても、`.xcodeproj` と `build.gradle.kts` を探すだけなので判定は変わりません。キーの書き方の点検は「[Rork が書いたコードに鍵が直書きされていないか、40行ほどのスクリプトで一度だけ確かめます](/articles/rork-basics/rork-exported-code-hardcoded-api-key-scan-script)」が詳しいです。

## どちらを選ぶか — 場面ごとの線引き

ここまでを、私なりの線引きに落とします。

- **iPhone の機能を深く使うアプリ**（ウィジェット、Apple Watch、ゲームなど）を考えているなら Rork です。Swift のコードがそのまま手元に残り、11月25日の更新からは Xcode で `xed .` を打てば開ける形で書き出せます
- **Web 版とモバイル版を同じコードで持ちたい**、あるいはサーバーの処理を自分で細かく書きたいなら Replit です。Expo のコードなので、React に慣れた方なら読み解きやすいはずです
- **まだ決めきれない方**は、Rork の無料のデザインモードで画面を固め、その画面の説明を Replit の3日間の体験にも渡して、どちらが自分の手を止めないかを比べるのがいちばん安上がりです

一方で、受託や長く運用するアプリでは、もう一つの観点が効いてきます。あとで別の開発者が引き継ぐとき、Swift と Kotlin の2つのコードを読める人を探すのか、Expo の1つのコードを読める人を探すのか、という違いです。どちらが正しいということはなく、**引き継ぐ人の顔を思い浮かべて、その人が読めるほうを選ぶ**のが、私にとっていちばん後悔の少ない決め方でした。

## 次に詰まる一歩 — 書き出したあとの最初の Git

どちらを選んでも、乗り換えや手元での修正を考え始めると、最初に当たるのは「書き出したフォルダを Git で管理するときに、何を入れてはいけないか」です。秘密の値を一度でも履歴に入れると、あとから消すのは手間がかかります。手順は「[Rork のコードをエクスポートしたら、git init より先に .gitignore を用意します](/articles/rork-basics/rork-export-gitignore-before-git-init)」に書きました。

**道具は、公開する場所と引き継ぐ人から逆算して選びます。** この順番だけは、どんなに新しい機能が出ても守るようにしています。まずは手元のプロジェクトを上のスクリプトにかけて、「持ち込み」なのか「作り直し」なのかを確かめるところから始めていただければと思います。
