11月20日の午後、いつものように Rork のプロジェクトを開くと、サイドバーにあったはずの「Connectors」が見当たりませんでした。代わりに並んでいたのは「Plugins」という見慣れない名前です。つないでおいた GitHub が外れてしまったのではないかと、一瞬だけ手が止まりました。

確かめてみると、何も外れていませんでした。名前と置き場所の見え方が変わっただけで、つないでいたものはそのまま残っています。一方で、今回の更新で Google Docs や Google Drive をつなげるようになり、私の作業の段取りはひとつ変わりそうです。

最初にお伝えしたいのは、Plugins は「アプリに入る機能」ではなく、「Rork が作業中に読みにいく先」だということです。ここを取り違えないだけで、つなぐ前に考えることがずいぶん減ります。

## 11月19日に変わったこと

Rork の公式チェンジログ（[Changelog](https://rork.com/changelog)）の 11月19日の項には、次のように書かれています。

- Connectors から Plugins への改名（置き場所はサイドバーとチャットの「+」メニューで、以前と同じ）
- 接続済みのサービスは、接続されたままです
- 一覧の最初に、Gmail・Notion・Supabase・GitHub・RevenueCat などのよく使われるサービス
- 各カードに、どのアカウントでつないでいるかの表示
- 再サインインが必要なものや、使える操作が変わったものには、カード上の知らせ
- Gmail・Google Calendar・Google Drive・Google Docs・Google Sheets・Slack・Zoom の 7 つを全員に追加
- チャット上部の「?」ボタン（side chat）は廃止。質問はメインのチャットへ

追加された 7 つについては「Plugins でつないでから、チャットで Rork に読ませたり、変更を頼んだりする」という使い方が案内されています。つまり読み手は Rork であって、皆さまが作っているアプリではありません。

## アプリから Sheets を読みたいときは、別の道です

ここが私自身、最初に混同しかけたところでした。どちらも「Sheets をつなぐ」と言えてしまうので、同じところで迷う方もいらっしゃるかもしれません。家計簿アプリの集計を Google Sheets に書き出したい、という話と、Plugins で Sheets をつなぐ話は、まったく別の作業です。

FAQ では、Sheets や Notion との連携は「チャットで頼めば、API キーを求められ、正確さのために API ドキュメントが要ることもある」と説明されています。Plugins でつないだ私の Google アカウントが、そのまま利用者のスマートフォンから使われるわけではないのです。

## 名前が変わった日に、カードを二か所だけ見ます

Plugins を開いたら、つないでいるカードを一枚ずつ見て、次の二つを確かめます。所要時間は数分です。

1. **つないでいるアカウント**: 今回からカードに表示されるようになりました。個人開発の作業用と、普段のメール用とで Google アカウントを分けている方は、ここで取り違えに気づけます
2. **再サインインや、操作の変更の知らせ**: カードに出ていれば、その日のうちに入り直しておきます。作業の途中で読めなくなるより、ずっと穏やかです

私はここで、Google のアカウントを作業用のひとつに揃えることにしました。Rork に読ませたいのは仕様メモだけで、受信箱や予定表まで見せる理由はありません。

## 仕様メモを読ませる段取り

以前の私は、画面ごとの決めごとを長い文章にしてチャットへ貼りつけておりました。三回目の依頼あたりで、どの版を貼ったのか自分でも分からなくなり、同じ指示を二度出していたこともあります。結果は芳しくありませんでした。

いまは次の順番にしています。

1. Google Docs に、見出しを固定した仕様メモを一つ作ります（画面・データ・決めたこと・まだ決めていないこと）
2. Plugins で Google Docs をつなぎます
3. 作り始める前に、そのメモを読ませて「要約を返すだけ」を頼みます
4. 返ってきた要約と自分のメモを見比べ、ずれがあればメモのほうを直します
5. ずれが無くなってから、一画面だけ作ってもらいます

3 番目の依頼は、毎回ほぼ同じ型にしています。

```text
Google Docs の「家計簿アプリ 仕様メモ v3」を読んでください。
まだコードは書かないでください。

次の4つを、箇条書きで返してください。
1. 画面の一覧（画面名と、その画面でできること）
2. 保存するデータと、その型（金額は整数の円、など）
3. 「決めたこと」の節に書かれている約束
4. 「まだ決めていないこと」の節にある項目

メモに書かれていないことは、推測で埋めずに「記載なし」としてください。
```

この型で効いているのは、最後の一文と「まだコードは書かないでください」の二つです。要約の段階で推測が混ざると、それがそのまま最初の画面に入ってしまいます。読み返しを一往復はさむだけで、「メモにはそう書いていなかった」という食い違いを、コードになる前に拾えるのです。

金額や日付の扱いのように、あとから直すのが重い約束をメモのどこに置くかは、[家計簿アプリの最初の指示で、あとから効く3つの一行](/articles/rork-basics/kakeibo-first-prompt-yen-integer-local-month-input-normalize-three-checks)にも書き残しました。

**読ませるのは仕様の一冊だけ、ずれを直すのはメモの側。** この線引きにしてから、チャットに貼る文章はほんの少しになりました。

## 「変更も頼める」ことは、いったん脇に置いています

チェンジログには、つないだサービスに対して Rork に変更を頼めることも書かれています。便利そうではありますが、私は仕様メモについては読むことだけに留めています。

理由は単純で、仕様メモは私が判断を書き残す場所だからです。AI が要約し、私が直す——この向きが逆になると、どれが自分の決めたことなのか、あとで辿れなくなります。もし書き換えを試すなら、元のメモを複製した写しで、と決めております。

もう一つ、side chat が無くなったので、「このコードは何をしているのか」といった質問もメインのチャットに並ぶようになります。作業の依頼と質問が混ざって読みにくくなるようでしたら、質問の頭に「質問だけです。変更はしないでください」と一行添えるのが、いまのところ私には合っています。

プレビューで期待どおりに動かなかったときに、もう一度同じ依頼を重ねる前に見る場所は、[一覧が空なのにエラーが出ないときの Logs パネル](/articles/rork-basics/rork-list-empty-no-error-ask-for-logs-before-fix-request)にまとめてあります。また、プランを見直す前に手元へ残しておく手順は[プラン変更の前に、取り直したコードを組み直せるか確かめる](/articles/rork-basics/rork-export-rebuild-check-before-plan-change)で触れました。

## 次にすること

まずは Plugins を開き、つないでいるカードのアカウント表示を一枚ずつ見てください。そのうえで、作りかけのアプリの仕様を Google Docs に一枚だけ書き、「要約を返すだけ」の依頼から始めていただければと思います。私もその一往復から、次の画面に取りかかるつもりです。
