## 2位：Rork で AdMob を実装したとき、12年の運用経験を持つ私が感じた3つの違和感と1つの驚き

AdMob 月収ピーク150万円超・累計5,000万DLを経験した開発者として、Rork で実際に AdMob を組み込んだときの率直な評価を書いた記事です。

[Rork で AdMob を実装したとき、12年の運用経験を持つ私が感じた3つの違和感と1つの驚き](/articles/rork-business/rork-admob-implementation-honest-review-12years-ex)

**3つの違和感:**
1. 広告ユニットIDの管理が自動化されていないため、12年の手作業と変わらない部分がある
2. バナー広告の配置ロジックが自動生成では最適化されず、eCPMへの影響が無視できない
3. メディエーション設定は Rork の範疇外で、引き続き手動作業が発生する

**1つの驚き:**
- 初期セットアップのコード生成速度は予想を大きく上回った。1時間かかっていた初期実装が15分で終わった

「驚き」のほうが記事の中で最も多くの方に反応していただきました。期待値を正直に書いた記事が、かえって信頼を生むことがあると感じています。

壁紙・癒し系アプリを個人で12年運営し、累計5,000万DLを超えた視点から、Rork での壁紙アプリ試作を通じて見えてきたことを記録した記事です。

[5,000万DLのアプリ事業を運営する私が、Rorkで壁紙アプリを試作して気づいたこと](/articles/rork-business/rork-indie-dev-50million-dl-wallpaper-prototype-re)

**試作で気づいたこと:**
- カテゴリ表示やグリッドレイアウトの基本UIは、驚くほど速く形になった
- 画像の遅延読み込みやキャッシュ管理は、Rork 生成コードではデフォルトで最適化されていない
- ユーザーが「壁紙アプリに何を求めるか」を理解していないと、生成されたUIは使いにくくなる

```swift
// expo-imageを使った遅延読み込み（Rork生成コードに追加）

const WallpaperCard = ({ uri, placeholder }: Props) => (
  <Image
    source={{ uri }}
    placeholder={placeholder}

    transition={200}
    style={styles.image}
  />
);
```

技術的な生成品質だけでなく、「作り手がドメイン知識を持っているかどうか」が Rork の活用精度を左右するという発見が、特に反響を呼びました。

## 4位：Rorkで作る引き寄せ・運勢系アプリ — 累計5,000万DLから学んだ日替わり配信とリテンション設計

占い・引き寄せ・運勢系アプリは初日のDLは取れても、3日で離脱されやすいジャンルです。10年以上このカテゴリでアプリを運営してきた経験から、Rork での実装パターンとリテンション設計を解説した記事です。

[Rorkで作る引き寄せ・運勢系アプリ — 累計5,000万DLから学んだ日替わり配信とリテンション設計](/articles/rork-business/rork-fortune-manifestation-app-daily-content-reten)

**リテンションを高める設計の核心:**
- 日替わりコンテンツは「毎朝開くべき理由」を作る最も確実な方法
- プッシュ通知のタイミングは朝7〜8時・夜21〜22時に集中させる（ユーザーの日常動線に合わせる）
- ホーム画面ウィジェットは、DAUを20〜30%押し上げる経験的な実績がある

1997年に独学でプログラミングを始めてから、「ユーザーが毎日戻ってきたくなるアプリを作る」ことを一貫したテーマにしてきました。技術が変わっても、その問いの答えは変わらないと感じています。日替わりコンテンツの設計では、単に「毎日更新すること」より「その日ならではの文脈」を持たせることが重要です。月・火・水の流れや旧暦の節気に連動するコンテンツは、ユーザーに「今日のために開いた」という感覚を与え、習慣化を促します。この感覚的な設計の積み重ねが、長期的なリテンションを支えてきました。

## 5位：Rork アプリのユーザーレビューを AI に読ませたら、次に作るべき機能が3分で見えてきた

App Store・Google Play のレビューを Claude API で自動分析し、次の開発優先度を導き出す仕組みを Rork アプリに構築した記事です。

[Rork アプリのユーザーレビューを AI に読ませたら、次に作るべき機能が3分で見えてきた](/articles/rork-business/rork-ai-user-feedback-analysis-system-guide)

```python
# レビュー感情分析の基本パターン
import anthropic

client = anthropic.Anthropic()

def analyze_reviews(reviews: list[str]) -> dict:
    prompt = f"""以下のApp Storeレビューを分析して、
    1. 最も多い不満点TOP3
    2. 最も多い要望機能TOP3
    3. 次スプリントの優先実装推奨
    をJSONで返してください。
    
    レビュー:
    {chr(10).join(reviews[:50])}"""
    
    response = client.messages.create(
        model="claude-haiku-4-5-20251001",
        max_tokens=1024,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.content[0].text
```

累計5,000万DLのアプリを運営する中で、レビューを読んで機能を改善するサイクルは欠かせませんでした。AIで自動化することで、月1回だった分析を毎週実施できるようになった変化は大きかったです。
