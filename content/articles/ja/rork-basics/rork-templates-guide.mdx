最初のアプリを Rork で作ろうとすると、白紙のプロンプト欄を前にして「何を書けば動くものになるのか」が分からず手が止まりがちです。私自身、2014年から個人開発を続けてきましたが、新しいツールに触れるたびに最初の一歩でつまずいてきました。Rork のテンプレートは、その「最初の一歩」を肩代わりしてくれる仕組みです。

## Rork テンプレートとは

Rork は多数の**アプリテンプレート**を提供しており、よくある種類のアプリを短時間で作り始めることができます。ゼロからプロンプトを書かなくても、テンプレートを選んでカスタマイズするだけで、画面遷移やデータ保存まで含んだ動くプロトタイプが手に入ります。

テンプレートの価値は「コードが省ける」ことよりも、「どういう構造でアプリを組めばいいか」の見本がそのまま動く形で得られることにあります。初めての方ほど、この見本の効果が大きいと感じています。

## 利用可能なテンプレート

Rork では以下のカテゴリのテンプレートが用意されています。

**生産性・ビジネス**:
- To-Do リストアプリ
- 経費管理アプリ
- タイムトラッカー
- ノートアプリ

**ソーシャル・コミュニティ**:
- チャットアプリ
- SNS フィード
- イベント管理

**ヘルスケア・フィットネス**:
- ワークアウトトラッカー
- 食事記録アプリ
- 習慣管理

**Eコマース・予約**:
- オンラインショップ
- 予約管理システム
- レストランメニュー

## テンプレートの使い方

### 1. テンプレートを選ぶ

Rork のプロジェクト作成画面で「テンプレートから始める」を選択し、用途に近いテンプレートを選びます。作りたいものと完全に一致していなくても構いません。後述しますが、構造が近ければ十分に出発点になります。

### 2. 基本情報を入力

テンプレートを選んだら、アプリ名と簡単な説明を入力します。Rork が選択したテンプレートをベースにコードを生成します。

### 3. プロンプトでカスタマイズ

生成されたアプリに対して、プロンプトで追加・変更を指示していきます。

```
「色テーマをブルーに変更してください」
「カテゴリフィルターを追加してください」
「ダークモードに対応させてください」
```

## テンプレートを使うメリット

**時間の節約**: 基本的な CRUD 操作やナビゲーション構造がすでに実装されているため、土台作りに費やす時間を丸ごと省けます。

**ベストプラクティスが適用済み**: テンプレートには Rork 推奨のコード構造・ライブラリが使用されており、後から拡張しやすい設計になっています。

**実装済み機能**: 認証フロー、データ永続化、基本的な UI コンポーネントなどが含まれているテンプレートも多く、自分で配線する手間が減ります。

## テンプレートかゼロからか — 私の判断基準

公式の説明だけだと「一般的なアプリならテンプレート、独自性が必要ならゼロから」という整理になりがちですが、実際に手を動かすと、その境界はもう少し曖昧です。私は次のように考えています。

一般的なアプリタイプで、まず動くものを早く触りたいときはテンプレートが向いています。独自の UI やロジックが中心になるアプリは、テンプレートの前提が逆に足かせになることもあるため、ゼロから組んだ方が早い場合があります。そして初めてのアプリ開発であれば、たとえ最終的に作りたいものと違っても、まずテンプレートで「動くアプリの中身」を一度見ておくことを強くおすすめします。学習目的なら、テンプレートを分解して読むのもゼロから書くのも、どちらも良い教材になります。

## テンプレートから始めて「自分のアプリ」にするまで

ここからは、私が実際に運営している壁紙アプリを Rork で作り直したときの話です。累計 5,000 万ダウンロードを超える画像系アプリをいくつか運用していますが、その一つのプロトタイプを、あえて「ノートアプリ」テンプレートから始めてみました。

意外に思われるかもしれませんが、壁紙アプリの中身は「一覧をグリッドで並べ、タップして詳細を開き、お気に入りを保存する」という構造で、ノートアプリの一覧・詳細・保存の骨格とほとんど同じだったからです。ぴったりのテンプレートが無くても、**画面構造が近いものを選べば出発点になる**、というのが最初の学びでした。

そこから「自分のアプリ」にするために、私が真っ先に指示したのはデータ層の差し替えでした。テンプレートの多くは端末内の保存（AsyncStorage など）を前提に作られていますが、壁紙アプリは配信する画像をサーバー側で差し替えたいので、リモートから一覧を取得する形に変える必要があります。

```
「保存先を端末内ストレージから、外部 API（JSON 形式の画像リスト）取得に変更してください。
 取得失敗時はキャッシュした前回の一覧を表示するフォールバックも入れてください」
```

次に削ったのが認証フローです。私の壁紙アプリは広告収益で運営しており、ログインを求めない設計にしています。テンプレートに最初から入っていたサインイン画面は、そのまま残すとユーザーの離脱を招くため、「認証を外して、初回起動から一覧が見える導線にしてください」と指示して取り除きました。

この「構造の近いテンプレートを土台にして、データ層と不要なフローだけを入れ替える」という進め方は、ゼロからプロンプトを積み上げるより明らかに速く、しかも崩れにくいと感じています。土台が一度きちんと動いている状態から差分で変えていくので、どこで壊れたかも追いやすいのです。

## 最後に

テンプレートは「最初の一歩」を肩代わりしてくれますが、そこから先の「自分のアプリらしさ」は、データ層・不要なフローの取捨選択・細部の手触りで決まっていきます。まずはテンプレートで動くものを一つ作り、気になった箇所を一つだけ差し替えてみてください。その一回が、ツールへの理解を一番大きく進めてくれるはずです。お読みいただきありがとうございました。
