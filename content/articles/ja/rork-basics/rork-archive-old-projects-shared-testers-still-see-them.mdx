11月23日の朝、Rork のプロジェクト一覧を上から下まで眺めて、しばらく手が止まりました。壁紙アプリの新しい一覧画面を試すために複製したもの、オンボーディングの文言だけを差し替えたもの、カテゴリの絞り込みを一晩だけ試したもの——名前の似たプロジェクトが、本番に近いものと同じ高さで並んでいたのです。

今日開きたいものを探すたびに、名前の末尾を一つずつ読んでいました。小さな手間ですが、毎朝となると胃のあたりが少し重くなります。かといって削除してしまうと、あの晩に何を試したのかを二度と見返せません。

ちょうど前日、Rork のチェンジログにプロジェクトのアーカイブが入りました。最初にお伝えしたいのは、**アーカイブは自分の一覧を軽くするための操作で、共有した相手の一覧までは片づけてくれない**ということです。ここを知らずに使うと、テスターの方の画面に古い試作が残り続けます。

## 11月22日に入ったこと

公式の [Changelog](https://rork.com/changelog) の 11月22日の項には、次のように書かれています。

- プロジェクトのメニュー、または右クリックから「Archive」を選ぶとアーカイブできます
- 直後に「Undo」の案内が出るので、押し間違えてもその場で戻せます
- アーカイブしたプロジェクトは一覧から外れ、何も削除されません
- プロジェクトページの新しい「Archived」フィルターに移り、「Unarchive」で一覧に戻せます
- アーカイブは自分にだけ効きます。共有している相手には、そのまま見えています

最後の一行が、今回いちばん大事なところだと私は受け取りました。消えたように見えるのは自分の一覧だけで、プロジェクトそのものも、共有の関係も、何も変わっていません。

## 散らかる理由は、複製がよい習慣だからです

Rork の公式ガイド「[When to clone your Rork project](https://rork.com/guides/clone-rork-project)」は、危ない変更を試す前や、生成のやり直しが堂々巡りになったときに、プロジェクトを複製してから進めることを勧めています。私もこの習慣に何度も救われてきました。

一方で、複製を守るほど一覧は長くなります。試した結果を本体に取り込んだあとも、複製はそのまま残るからです。片づけが必要になるのは、手順を守っている証拠でもあるのだと思います。

以前の私は、この長い一覧を「いつか削除する」と放っておきました。結果は芳しくありませんでした。半年ほどたってから試作を見返そうとしたとき、どれが最後に動いた版なのか、名前だけでは判断できなかったのです。

## 三つに分けてから、手を動かします

いまは片づける前に、プロジェクトを三つの箱に分けています。

<table>
<thead><tr><th>箱</th><th>入れるもの</th><th>理由</th></tr></thead>
<tbody>
<tr><td>残す</td><td>ストアに出ているもの・この30日に開いたもの</td><td>毎日の作業で開くため、一覧の上に置いておきたい</td></tr>
<tr><td>アーカイブ</td><td>30日以上開いておらず、誰とも共有していない試作や複製</td><td>消えずに戻せるので、迷ったらこちらで十分</td></tr>
<tr><td>先に共有を見直す</td><td>30日以上開いていないが、誰かと共有している試作</td><td>自分がアーカイブしても、相手の一覧には残る</td></tr>
</tbody>
</table>

30日という区切りは、私のアプリの更新の間隔から決めた目安です。皆さまの作業の周期に合わせて、14日でも60日でも構いません。

ストアに出ているものを「残す」に入れているのは、私自身の線引きです。チェンジログには、アーカイブが公開中のアプリにどう関わるかは書かれていません。一覧から外れることと、ストアから外れることは別の話のはずですが、確かめていない以上、毎日見張るものは手元に置いておくことにしました。

## 一覧を書き出して、仕分けを先に決めます

Rork の画面を見ながら一つずつ判断すると、途中で迷いが出ます。そこで、プロジェクト名・最後に開いた日・共有している相手・ストアに出ているかを、手で小さな CSV に書き出してから決めるようにしました。書き出すのは数分です。

```text
name,last_opened,shared_with,on_store
wallpaper-grid-v2,2026-11-20,,yes
wallpaper-grid-v2 (clone),2026-10-02,,no
onboarding-test,2026-09-14,tester@example.com,no
category-filter-try,2026-08-30,,no
healing-timer,2026-11-18,,no
```

この CSV を読み、上の表の三つの箱に振り分けるだけのスクリプトです。Python 3 が入っていれば、追加のライブラリなしで動きます。

```python
import csv
import sys
from datetime import date

TODAY = date.fromisoformat(sys.argv[2]) if len(sys.argv) > 2 else date.today()
QUIET_DAYS = 30  # この日数より長く開いていなければ、片づけの候補にする

def decide(row):
    last = date.fromisoformat(row["last_opened"])
    idle = (TODAY - last).days
    shared = row["shared_with"].strip()
    if row["on_store"].strip().lower() == "yes":
        return idle, "残す", "ストアに出ているものは一覧に置いておく"
    if idle < QUIET_DAYS:
        return idle, "残す", "まだ手を動かしている"
    if shared:
        return idle, "先に共有を見直す", f"{shared} の一覧には残るため"
    return idle, "アーカイブ", "戻せる片づけで十分"

with open(sys.argv[1], newline="", encoding="utf-8") as f:
    rows = list(csv.DictReader(f))

for row in sorted(rows, key=lambda r: r["last_opened"]):
    idle, verdict, reason = decide(row)
    print(f"{verdict:<10} {idle:>4}日  {row['name']}  （{reason}）")
```

`python3 sort_projects.py projects.csv 2026-11-23` と日付を渡して実行すると、次のように出ました。

```text
アーカイブ        85日  category-filter-try  （戻せる片づけで十分）
先に共有を見直す     70日  onboarding-test  （tester@example.com の一覧には残るため）
アーカイブ        52日  wallpaper-grid-v2 (clone)  （戻せる片づけで十分）
残す            5日  healing-timer  （まだ手を動かしている）
残す            3日  wallpaper-grid-v2  （ストアに出ているものは一覧に置いておく）
```

判断の順番を「ストア → 最近開いたか → 共有しているか」にしているのは、取り違えたときに困る順だからです。公開中のものを誤ってしまい込むのがいちばん痛く、共有の見直し漏れはその次、試作のアーカイブは間違えても Unarchive で戻せます。日付を引数で渡せるようにしたのは、同じ CSV で「来月の今日なら、どれが候補になるか」を先に眺めるためです。

## アーカイブする手順と、終えたあとに一度だけ確かめること

仕分けが済んだら、「アーカイブ」の箱に入ったものだけを Rork で片づけます。

1. プロジェクトページで対象のプロジェクトを右クリックするか、プロジェクトのメニューを開きます
2. 「Archive」を選びます
3. 「Undo」の案内が出ているあいだに、名前を見直します。似た名前の本体を選んでいたら、ここで戻します
4. 全部終えたら「Archived」フィルターを開き、入ったものが CSV の「アーカイブ」の行と一致しているかを数えます

4 番目は、私が一度失敗してから足した手順です。複製の名前は本体とほとんど同じなので、本体のほうを片づけてしまっていたことがありました。消えてはいないので Unarchive で戻せましたが、気づくまでのあいだ、毎朝の作業の入口が一つ見えなくなっていたのです。

**片づけは戻せる操作から始め、戻せない操作は最後に一つずつ行います。** この順番にしてから、一覧を整える日の気の重さがずいぶん軽くなりました。

## 共有している試作は、相手の画面のことを先に考えます

「先に共有を見直す」に入ったものは、アーカイブしても相手の一覧からは消えません。テスターの方にとっては、終わったはずの試作が、いつまでも最新のもののような顔で並び続けることになります。

私はこの箱に入ったものについて、相手の方に「この試作は終わりました」とひと言お伝えしてから、自分の側をアーカイブするようにしています。共有を外すかどうかは、相手がまだ見返したいかどうかで決めます。自分の一覧の都合だけで、相手の手元から急に消すことは避けたいのです。

テスターとのやりとりの段取りは、[Google Play のテスター 12 人のうち 1 人が抜けた朝の記事](/articles/rork-basics/google-play-12-testers-one-drops-out-14-days-restart-or-not)にも書き残しています。

## 削除を考えるのは、書き出しを済ませてから

アーカイブで足りないと感じる日が来るとしたら、プランを変える前や、プロジェクトを手放すと決めたときだと思います。そのときは削除の前に、コードを取り出して Rork の外で組み直せるかを確かめておくと安心です。手順は [プラン変更の前に、取り直したコードが Rork の外で組み直せるか確かめる記事](/articles/rork-basics/rork-export-rebuild-check-before-plan-change)にまとめています。

まずは今日、一覧を手で CSV に書き出し、「共有している相手がいるか」の列だけでも埋めてみていただければと思います。私の一覧では、その列を埋めた時点で、アーカイブの前に連絡すべき方が一人いると分かりました。
