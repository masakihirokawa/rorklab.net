火曜は、先週一週間の記事を振り返る日にしています。今週は「Android の ANR 率が上がったとき何をするか」という運用の悩みから、「起動時間を予算として管理する」という設計の話まで、私が6本のアプリを並行運用しながら実際にぶつかった課題が並びました。検索流入と読者の反応をもとに、特に手応えのあった5本を選んでいます。

順位は厳密な数値ではなく、「今週これを読むと役立つ」という私の判断です。同じ場面でつまずいている方が、必要な1本にすぐ辿り着けることを目指しています。

## 第1位：ANR率が上がったときのReact Native設計

今週いちばん読まれたのは[Android Vitals の ANR 率が上がったとき — メインスレッドを止めない React Native 設計ノート](/articles/rork-dev/rork-android-anr-main-thread-react-native-production-notes)でした。ANR（応答なし）はメインスレッドが一定時間ブロックされると発生します。重い処理をどうメインスレッドから逃がすか、私が本番で実際に効いた対処をまとめています。

```js
// 重い同期処理を1フレーム遅らせてメインスレッドの詰まりを避ける
import { InteractionManager } from "react-native";

InteractionManager.runAfterInteractions(() => {
  // アニメーションや遷移が落ち着いてから重い初期化を実行
  initHeavyModules();
});
```

すべてを起動直後に走らせないこと。表示に関係ない初期化を後ろ倒しにするだけで、ANR率は目に見えて下がりました。 Android Vitals の数値は改善が反映されるまで時間がかかるので、焦らず一つずつ潰していくのが結局の近道でした。

## 第2位：ビルドが JavaScript heap out of memory で落ちる

2位は[Metro・EASのビルドが『JavaScript heap out of memory』で落ちるときの対処](/articles/rork-dev/rork-metro-eas-javascript-heap-out-of-memory-fix)です。アプリが育つとビルド時のメモリが足りなくなり、CIが突然落ち始めます。Node のヒープ上限を引き上げる対処と、そもそも依存を整理する根本対処の両面でまとめました。 私の場合、`NODE_OPTIONS=--max-old-space-size` で一時的に凌ぎつつ、使っていない依存とソースマップ生成を見直すことで、ヒープを上げ続けなくても通るようになりました。対症療法と根本対処を分けて考えるのが大事です。

## 第3位：Google Playの署名キーエラー

トラブルシューティングから[Rorkアプリを Google Play にアップロードできない署名キーエラーの直し方](/articles/app-dev/rork-google-play-upload-signing-key-mismatch-fix)が上位に入りました。「別のキーで署名されています」というエラーは、Play App Signing と手元のアップロードキーの関係を整理すると解決します。リリース直前に出ると焦るので、仕組みを先に押さえておくと安心です。 私は新しいアプリを出すたびにここで一度立ち止まるので、アップロードキーと署名鍵の対応関係をメモに残しておくようにしています。

## 第4位：起動時間を「予算」として管理する

設計寄りの記事では[起動時間を『予算』として管理する — 6本のアプリでSDK初期化を後ろ倒しにした設計記録](/articles/rork-dev/rork-startup-time-budget-deferred-sdk-init-six-apps)が伸びました。起動にかけてよい時間を「予算」と決め、その範囲に収まるようSDK初期化を後ろ倒しにした6本ぶんの記録です。広告・解析・課金のSDKを全部起動時に初期化すると、体感の重さに直結します。 必要になった瞬間まで初期化を遅らせるだけで、6本とも起動の体感がはっきり軽くなりました。

## 第5位：壁紙アプリのApp Storeローカライズ

5位は[壁紙アプリの App Store ローカライズを多言語で運用して見えた所感](/articles/rork-business/app-store-connect-localization-wallpaper-apps-multilocale-notes)でした。メタデータをただ翻訳するだけでは現地で読まれません。各言語圏での「読まれ方」を整える視点での実体験です。累計5,000万ダウンロードの多くは海外からで、ここを整えるかどうかで流入が変わります。 同じスクリーンショットでも、現地の言葉で「何ができるアプリか」が一目で伝わるかどうかで、コンバージョンは大きく変わると感じています。

## 今週を振り返って

今週の5本に共通していたのは、「起動と動作の体感を、後回しにせず設計で守る」という姿勢でした。メインスレッドを空ける、起動時間に予算を引く、初期化を後ろ倒しにする。どれも派手な機能追加ではありませんが、ユーザーが最初に触れる数秒を整えることが、評価にもリテンションにも効いてきます。 個人開発では一人で全部を見るからこそ、こうした地味な土台づくりが効いてくると感じています。
