Rork を使い始めると、「プロンプトを送ったのに意図した通りに変わらない」「プレビューで動いていたのに実機で崩れた」「APIを繋いだはずなのにエラーになる」といった壁に当たります。

初めてノーコード AI ツールを使う方には特に、「自分がやり方を間違えているのか、ツールの問題なのか」の判断が難しいことが多いです。よくあるトラブルとその対処法を10個まとめました。

## 1. プロンプトが効かない — 意図した変更が起きない

最もよくある詰まりポイントです。Rork は AI がプロンプトを解釈してコードを生成するため、プロンプトの書き方次第で結果が大きく変わります。

**よくある原因: プロンプトが曖昧すぎる**

```
❌ 「ボタンをきれいにしてください」
❌ 「この画面を改善してください」

✅ 「ホーム画面の左下にある青い丸いボタンのサイズを少し大きくして、角を丸くしてください」
✅ 「送信ボタンの背景色を #3B82F6 に変更し、テキストを白にしてください」
```

変更したい要素、現在の状態、望む状態——この3つをできるだけ具体的に書くと、意図した変更が起きやすくなります。

**対処: スクリーンショットと組み合わせる**

テキストだけで説明しにくい場合は、スクリーンショットやデザインの参考画像を添付して「この部分をこのように変えてください」と指示すると精度が上がります。

## 2. ビルドが失敗する

```
Build failed: Unable to compile app
```

**原因1: プロジェクトの状態が壊れている**

Rork のリフレッシュボタン（🔄）でプロジェクトの状態をリセットしてみてください。複数の変更を連続して試みた後に状態が壊れることがあります。

**原因2: 前の変更が中途半端な状態になっている**

「変更を元に戻す（Undo）」機能で直前のプロンプトを取り消し、より小さな単位で再試行してください。大きな変更を一度にお願いするより、段階的に試す方がビルド失敗が起きにくくなります。

**原因3: Rork サーバーの問題**

数分待ってから再試行すると解決することもあります。

## 3. プレビューと実機で見た目が違う

プレビューでは正しく表示されるのに、実機やシミュレーターで見るとレイアウトが崩れるケースです。

**よくある原因: 画面サイズの違い**

Rork のプレビューは特定の画面サイズを想定しているため、別のデバイスサイズで見ると崩れることがあります。

```
「iPhone 16 Pro のサイズ（393×852 pt）でも正しく表示されるように
 レイアウトを調整してください」
```

デバイスサイズを明示してプロンプトを送ると、より適切なレイアウトを生成してもらえます。

**よくある原因: セーフエリアの扱い**

画面の端（ノッチ・ダイナミックアイランド・ホームインジケーター周辺）に要素が重なっている場合です。

```
「すべてのコンテンツが Safe Area の内側に収まるようにしてください。
 特に上部のナビゲーションバーとホームインジケーターの領域を確保してください」
```

## 4. API 連携でエラーになる

外部 API を接続した際に `Error: Network request failed` や `401 Unauthorized` が出るケースです。

**チェック1: API キーが正しく設定されているか**

Rork の Environment Variables（環境変数）に API キーを設定しているか確認してください。コードの中に API キーを直接書き込む形にすると、変更のたびに再入力が必要になる上にセキュリティリスクもあります。

**チェック2: CORS エラーの場合**

```
Access to fetch at '...' from origin '...' has been blocked by CORS policy
```

ブラウザプレビューで API を呼ぶと CORS エラーになることがあります。実機またはシミュレーターでテストするか、Rork のサーバーサイド関数を使って API を呼ぶ形に変更してください。

**チェック3: API エンドポイントの形式を確認する**

```
「APIを呼び出す際は以下の設定を使ってください：
 エンドポイント: https://api.example.com/v1/data
 メソッド: GET
 ヘッダー: Authorization: Bearer [環境変数名]
 レスポンス形式: JSON」
```

API の仕様を具体的にプロンプトに含めると、正しい実装を生成しやすくなります。

## 5. 画面遷移が動かない

ボタンを押しても画面が切り替わらない、あるいは戻るボタンが機能しないケースです。

```
「ホーム画面の「詳細を見る」ボタンを押すと、Detail Screen に遷移するようにしてください。
 戻る場合はナビゲーションバーの戻るボタンで元の画面に戻れるようにしてください。
 遷移にはスライドアニメーションを使ってください」
```

遷移先の画面名と、どのボタンからの遷移かを明示することがポイントです。

## 6. データが保存されない・消える

フォームに入力したデータがアプリを再起動すると消えてしまうケースです。

**原因: ローカル永続化の設定がない**

```
「入力したユーザー名とメールアドレスをアプリを閉じても保存されるようにしてください。
 AsyncStorage を使って端末にデータを永続化してください」
```

Rork はデフォルトでは画面を閉じるとデータが消えます。永続化が必要な場合は明示してください。

バックエンドとの連携が必要な場合は、Supabase や Firebase との接続もプロンプトで依頼できます。

## 7. 画像が表示されない

外部URLの画像を表示しようとして表示されない場合です。

**チェック1: HTTP vs HTTPS**

`http://` の画像 URL は iOS アプリではセキュリティ上表示されません。`https://` の URL に変更してください。

**チェック2: 画像の縦横比が崩れている**

```
「プロフィール画像を 80×80 の正円で表示してください。
 画像は中央でクロップし、縦横比を保ちながら収めてください」
```

## 8. リスト表示が遅い・スクロールがカクカクする

データの多いリストでスクロールがカクカクする場合です。

```
「商品リストを FlatList コンポーネントで実装してください。
 各アイテムのレンダリングを最適化して、スムーズなスクロールを実現してください。
 1000件以上のデータでも動作するよう、仮想化を有効にしてください」
```

大量のデータを表示する場合は、FlatList の最適化を明示的にお願いすることが大切です。

## 9. プッシュ通知が届かない

プッシュ通知の設定をしたはずなのに届かないケースです。

**最初の確認: デバイスの通知許可**

アプリが通知の許可を正しくリクエストしているか確認してください。

```
「アプリ起動時に通知の許可ダイアログを表示してください。
 許可された場合はデバイストークンを取得してコンソールに表示してください」
```

トークンが取得できていれば、通知サービス側の問題です。トークン自体が取得できていない場合は、権限リクエストのコードを見直します。

## 10. アプリが突然クラッシュする

特定の操作でアプリが落ちる場合、エラーメッセージをそのまま Rork に渡すのが最も効果的です。

```
「以下のエラーが発生しています。原因を特定して修正してください：

TypeError: Cannot read property 'map' of undefined
  at ProductList (ProductList.js:23)
  
再現手順：
1. ホーム画面を開く
2. 商品カテゴリを選択する
3. リストが表示されるはずの場所でクラッシュする」
```

エラーメッセージ＋再現手順をセットで渡すことで、的確な修正ができます。

---

トラブルの9割は「プロンプトをより具体的にする」「エラーメッセージをそのまま渡す」「段階的に変更を試みる」のいずれかで解決できます。

詰まったときは一度立ち止まって、「自分のプロンプトは具体的に状況を説明できているか」を確認してみてください。
