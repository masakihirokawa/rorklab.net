スタンプカードのアプリを作っていたとき、QR コードではなく物理的なタグにかざすだけで来店を記録したい、という相談を受けました。カメラを起動してコードを合わせる動作は、店頭の数秒では意外と煩わしい。NFC タグなら、かざすだけで終わります。

Rork Max は Swift アプリを生成してくれますが、Core NFC のように Apple の許可（Entitlement）が絡む機能は、生成コードだけでは動きません。署名まわりと plist の設定を手で整えないと、ビルドは通っても実機でセッションが即座に閉じます。ここでは私自身が個人開発で組み込んだ順序で、つまずいた箇所まで含めて書きます。

## まず Entitlement と Info.plist を整える

コードより先に設定です。ここが抜けていると、後のコードがどれだけ正しくても動きません。必要なのは次の3点です。

1. Apple Developer のアプリ ID で Near Field Communication Tag Reading の機能を有効化する。
2. プロジェクトに `.entitlements` を追加し、`com.apple.developer.nfc.readersession.formats` に `NDEF` を入れる。
3. Info.plist に `NFCReaderUsageDescription` を入れ、なぜ NFC を使うのかを日本語で書く。

3 番目の説明文は審査で見られます。「タグを読み取ります」だけだと曖昧で、リジェクトの種になります。私は「来店ポイントを記録するため、レジ横の NFC タグを読み取ります」のように、利用場面が分かる文面にしています。

```xml
<!-- App.entitlements -->
<key>com.apple.developer.nfc.readersession.formats</key>
<array>
    <string>NDEF</string>
</array>
```

## NDEF 読み取りセッションを書く

設定が済んだら、読み取り本体です。`NFCNDEFReaderSession` を持つ小さなリーダークラスを作り、Rork Max が生成した画面から呼び出せるようにします。

```swift
import CoreNFC

final class TagReader: NSObject, ObservableObject, NFCNDEFReaderSessionDelegate {
    @Published var lastPayload: String?
    private var session: NFCNDEFReaderSession?

    func begin() {
        guard NFCNDEFReaderSession.readingAvailable else {
            print("NFC not available on this device")
            return
        }
        session = NFCNDEFReaderSession(
            delegate: self,
            queue: nil,
            invalidateAfterFirstRead: true
        )
        session?.alertMessage = "タグをiPhoneの上部に近づけてください"
        session?.begin()
    }

    func readerSession(_ session: NFCNDEFReaderSession,
                       didDetectNDEFs messages: [NFCNDEFMessage]) {
        guard let record = messages.first?.records.first else { return }
        let text = decodeText(from: record) ?? "(empty)"
        DispatchQueue.main.async { self.lastPayload = text }
    }

    func readerSession(_ session: NFCNDEFReaderSession,
                       didInvalidateWithError error: Error) {
        // ユーザーキャンセルや読み取り失敗もここに来る
        print("session invalidated: \(error.localizedDescription)")
    }
}
```

`invalidateAfterFirstRead: true` にすると、1枚読んだ時点でセッションが閉じます。連続でタグを読みたい場合は `false` にして、自分で `invalidate()` を呼ぶ設計にします。スタンプカードのように一度に1枚なら `true` が素直です。

## NDEF レコードを文字列に戻す

NDEF のテキストレコードは、先頭1バイトに言語コードの長さが入った形式です。ここを知らずに `payload` をそのまま文字列化すると、先頭にゴミが混ざります。

```swift
func decodeText(from record: NFCNDEFPayload) -> String? {
    guard record.typeNameFormat == .nfcWellKnown,
          record.type == Data([0x54]) else { return nil } // 'T'
    let payload = record.payload
    guard let status = payload.first else { return nil }
    let langLength = Int(status & 0x3F)
    let textData = payload.dropFirst(1 + langLength)
    return String(data: textData, encoding: .utf8)
}
```

URL レコード（type が `0x55`）の場合は、先頭1バイトが `https://www.` などの接頭辞コードになっています。テキストと URL でデコードが分岐する点は、最初に把握しておくと無駄な調査を避けられます。

## 本番で詰まった点とその対処

実機に出してから気づいた、説明書には書かれていない挙動を挙げます。

iPhone のアンテナは本体上部にあります。多くのユーザーは画面中央をタグに当てようとして読み取れません。`alertMessage` に「上部を近づけて」と明記するだけで、私の手元では読み取り失敗の問い合わせが目に見えて減りました。

シミュレータでは Core NFC は一切動きません。`readingAvailable` が常に false を返すため、開発初期から実機を1台確保しておく必要があります。

バックグラウンドのタグ読み取り（アプリを起動せず、かざすだけで反応する仕組み）は、Universal Link を仕込んだ専用フォーマットが必要で、`NFCNDEFReaderSession` とは別物です。要件として「アプリを開かずに」と言われたら、ここを取り違えないよう注意します。

ユーザーがキャンセルしたときも `didInvalidateWithError` に来ます。エラーコードを見ずに「読み取り失敗」と表示すると、わざと閉じた人にエラーを見せることになります。`NFCReaderError.readerSessionInvalidationErrorUserCanceled` を判定し、その場合は何も出さないのが本番での対処です。

## タグの選定と書き込みの実務

読み取りの実装が固まると、次は「どのタグを使うか」という現実的な選定に移ります。市販の NFC タグは規格がいくつもありますが、汎用のスタンプ用途であれば NTAG213 や NTAG215 が無難です。容量が小さいぶん安価で、テキストや短い URL を書き込むには十分でした。私の場合は店舗ごとに識別子を書き込んだ NTAG213 を配り、1枚あたりの単価を数十円に抑えています。

書き込みは読み取りの逆方向です。`NFCNDEFReaderSession` でも `connect` 経由でタグに `writeNDEF` を投げられますが、量産時に iPhone で1枚ずつ書くのは現実的ではありません。私は専用の書き込みアプリで一括処理し、アプリ側は読み取り専用に割り切っています。役割を分けたことで、本番アプリの権限が読み取りだけに収まり、審査での説明もシンプルになりました。

信頼性の面では、タグを金属面に直接貼ると読み取り率が落ちます。これは電波が金属に吸われるためで、金属対応タグ（裏面にフェライト層を持つもの）を選ぶか、間に数ミリの非金属を挟むだけで改善します。レジ横の金属什器に貼って読めない、という問い合わせの大半は、この設置条件が原因でした。物理的な貼り付け面まで含めて検証して初めて、実運用に耐える状態になります。

## どこを Rork Max に任せ、どこを手で書くか

私の判断では、NFC の読み取りロジックそのものは手で書きます。Entitlement とデコード処理は仕様が固く、生成と手直しの往復より、最初から正しく書いたほうが速いからです。一方で、読み取り結果を表示する画面や、スタンプが貯まる演出のような UI は Rork Max に下書きさせ、そこから整えています。

NFC は派手な機能ではありませんが、店頭やイベントのような「その場で一瞬」の体験に強く効きます。広告で言えば AdMob のような収益の柱とは別の軸で、リピート率という形でじわじわ返ってきます。物理世界とアプリをひと当てでつなぐ手触りは、一度組み込むと手放せなくなりました。

タグひと当てで物理世界とアプリがつながる手応えを、ぜひ一度試してみてください。
