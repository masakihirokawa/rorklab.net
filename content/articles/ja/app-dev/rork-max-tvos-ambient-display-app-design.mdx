居間のテレビに、自分の壁紙アプリの絵がそのまま流れていたら——そう思ったのは、iPhone 向けの壁紙アプリを個人開発で何年か運用してきて、ふと大きな画面で見たくなったときでした。Apple TV は普段ノーコードやクロスプラットフォームの話題から外れがちですが、Rork Max がネイティブ Swift を生成するようになって、ようやく現実的な選択肢になりました。

tvOS は iPhone とは作法がかなり違います。タッチがなく、指で触れない代わりにフォーカスという概念で操作します。常時点けっぱなしにされる前提もあり、消費電力や焼き付きへの配慮も要ります。ここでは、静かな映像をただ流し続ける「アンビエント表示アプリ」を題材に、Rork Max の生成コードへ手を入れていく流れを追います。

## なぜ Apple TV を Rork Max で作るのか

標準の Rork は React Native（Expo）でクロスプラットフォームに作りますが、tvOS の本領であるフォーカスエンジンや Top Shelf、AVPlayer の低レベル制御は、ネイティブ Swift でないと素直に届きません。Rork Max は iPhone・iPad・Apple Watch・Apple TV・Vision Pro 向けにネイティブ Swift を生成するため、Apple TV を狙うならこちらが土台になります。

私自身の使い分けは単純です。素早く iOS と Android を同時に出したいときは React Native 版、Apple のハードウェアや OS 統合に踏み込みたいときは Rork Max。Apple TV は後者の典型で、クロスプラットフォームのうまみがそもそも存在しません。なお Rork Max は月 $200、標準の Rork は無料で始められ有料は月 $25 からと、価格差は小さくありません。2クリックで App Store に出せる手軽さを含め、Rork Max でしか届かない領域でこそ、この $200 を活かしたいところです。

Rork Max に「Apple TV 向けに、フルスクリーンで映像をループ再生し続けるアンビエントアプリを作って」と頼むと、SwiftUI ベースの雛形が返ってきます。ただしそのままでは「再生はするが継ぎ目で一瞬黒くなる」「フォーカスが想定外に動く」といった粗が残ります。ここから先が手作業の領域です。

## 継ぎ目のない映像ループを組む

最初に直面するのが、ループの継ぎ目です。`AVPlayer` に同じ動画を `seek(to: .zero)` で巻き戻す素朴な実装だと、巻き戻しのたびにわずかな黒フレームが挟まります。テレビの大画面では、この一瞬がはっきり気になります。

解決策は `AVQueuePlayer` と `AVPlayerLooper` の組み合わせです。これは内部で次の再生アイテムを先読みしておき、切れ目なく繋いでくれます。

```swift
import AVFoundation
import SwiftUI

final class AmbientPlayerModel: ObservableObject {
    let player: AVQueuePlayer
    private var looper: AVPlayerLooper?

    init(resourceName: String) {
        guard let url = Bundle.main.url(forResource: resourceName, withExtension: "mp4") else {
            self.player = AVQueuePlayer()
            return
        }
        let item = AVPlayerItem(url: url)
        let queue = AVQueuePlayer()
        // AVPlayerLooper が継ぎ目のループを担う
        self.looper = AVPlayerLooper(player: queue, templateItem: item)
        self.player = queue
        queue.isMuted = true
        queue.actionAtItemEnd = .advance
    }

    func start() { player.play() }
    func stop() { player.pause() }
}
```

ポイントは `AVPlayerLooper` をプロパティとして保持し続けることです。ローカル変数にすると解放されてループが止まります。Rork Max の初期生成ではここがローカル変数になっていることが多く、私は毎回プロパティへ昇格させています。ループが突然止まるときは、まずここを疑うのが近道です。見落としやすい注意点だと感じています。

SwiftUI 側は `VideoPlayer` を使わず、`AVPlayerLayer` を薄くラップした方が制御しやすいです。`VideoPlayer` は再生コントロールの UI を抱えてしまい、アンビエント用途では邪魔になります。

```swift
struct PlayerLayerView: UIViewRepresentable {
    let player: AVQueuePlayer

    func makeUIView(context: Context) -> PlayerUIView {
        let view = PlayerUIView()
        view.playerLayer.player = player
        view.playerLayer.videoGravity = .resizeAspectFill
        return view
    }
    func updateUIView(_ uiView: PlayerUIView, context: Context) {}
}

final class PlayerUIView: UIView {
    override class var layerClass: AnyClass { AVPlayerLayer.self }
    var playerLayer: AVPlayerLayer { layer as! AVPlayerLayer }
}
```

`videoGravity` を `.resizeAspectFill` にしておくと、テレビの比率に合わせて余白なく敷き詰められます。私の壁紙素材は縦横比がまちまちなので、ここを `.resizeAspect` にすると左右に黒帯が出てしまい、アンビエントの没入感が削がれました。

## フォーカスエンジンと付き合う

tvOS の操作はすべてフォーカスを通します。何も操作要素がない画面でも、リモコンを触ると Apple TV は「次にフォーカスする先」を探します。アンビエント表示では基本的にフォーカス対象を置かず、画面をただ見せたいので、明示的にフォーカス可能な要素を最小化します。

ただし設定画面への入り口だけは必要です。私は画面下端にうっすらとしたボタンを一つ置き、リモコンの再生/一時停止ボタンで表示を切り替える形に落ち着きました。

```swift
struct AmbientRootView: View {
    @StateObject private var model = AmbientPlayerModel(resourceName: "loop_main")
    @State private var showsControls = false

    var body: some View {
        ZStack(alignment: .bottom) {
            PlayerLayerView(player: model.player)
                .ignoresSafeArea()

            if showsControls {
                Button("表示する作品を選ぶ") { /* 設定へ */ }
                    .padding(.bottom, 60)
            }
        }
        .onAppear { model.start() }
        .onPlayPauseCommand { showsControls.toggle() }
    }
}
```

`onPlayPauseCommand` は tvOS 固有で、Siri Remote の再生/一時停止ボタンに反応します。常時何かを表示しているアプリでは、こうした「隠れた入り口」を一つ用意しておくと、画面を汚さずに操作性を保てます。

## Top Shelf で起動前から体験を始める

Apple TV のホーム最上段、フォーカスを当てたときに大きく広がる帯が Top Shelf です。ここに作品のサムネイルを並べると、アプリを起動する前から世界観が伝わります。アンビエント系のアプリでは、この最初の数秒の印象がそのまま継続利用につながると感じています。

Top Shelf は本体とは別の App Extension として実装します。Rork Max に拡張ターゲットの追加を頼んだうえで、`TVTopShelfContentProvider` を返す部分を手で詰めます。

```swift
import TVServices

final class ContentProvider: TVTopShelfContentProvider {
    override func loadTopShelfContent() async -> TVTopShelfContent? {
        let items = AmbientCatalog.featured.map { piece -> TVTopShelfSectionedItem in
            let item = TVTopShelfSectionedItem(identifier: piece.id)
            item.title = piece.title
            item.setImageURL(piece.thumbnailURL, for: .screenScale1x)
            item.setImageURL(piece.thumbnailURL2x, for: .screenScale2x)
            item.displayAction = TVTopShelfAction(url: piece.deepLink)
            return item
        }
        let section = TVTopShelfItemCollection(items: items)
        section.title = "今日のアンビエント"
        return TVTopShelfSectionedContent(sections: [section])
    }
}
```

`displayAction` に差し込むディープリンクは、本体側の `onOpenURL` で受け取り、該当の映像へ直接遷移させます。Top Shelf から起動して、選んだ作品がそのまま全画面で流れ始める——この一連の流れが滑らかだと、リモコンを置いてもらえます。

## 常時表示と省電力のせめぎ合い

アンビエントアプリの宿命は、点けっぱなしにされることです。tvOS はアイドルが続くと標準のスクリーンセーバへ移行しようとしますが、自前で映像を流し続けたい場合は `isIdleTimerDisabled` 相当の制御が要ります。ただ、これを無制限に行うと「いつまでも消えない」アプリになり、ユーザーの電気代にも跳ね返ります。

私は折衷案として、連続再生に上限時間を設け、一定時間が過ぎたら静かにフェードアウトして標準のスリープに委ねる設計にしました。下の表は、運用しながら調整した目安です。

<table>
  <thead>
    <tr><th>設定項目</th><th>初期値</th><th>調整後</th><th>理由</th></tr>
  </thead>
  <tbody>
    <tr><td>連続再生の上限</td><td>無制限</td><td>4時間</td><td>消し忘れ対策と省電力の折衷</td></tr>
    <tr><td>映像ビットレート</td><td>20 Mbps</td><td>8〜10 Mbps</td><td>大画面でも体感差が小さく発熱を抑制</td></tr>
    <tr><td>フェード時間</td><td>なし</td><td>3秒</td><td>急に消えると唐突なので緩やかに</td></tr>
  </tbody>
</table>

ビットレートは特に効きました。テレビの視聴距離だと 20 Mbps と 10 Mbps の違いはほとんど分かりませんが、本体の発熱とファイルサイズは目に見えて変わります。アンビエント用途は派手さより静けさが価値なので、ここは思い切って削っても損なわれません。私の運用でも、ビットレートを下げることをお勧めします。

## 次の一歩

まずは小さく動かすのが近道です。

1. 手元の素材を一本、`AVQueuePlayer` と `AVPlayerLooper` でループさせ、テレビにつないで継ぎ目を自分の目で確認します。
2. Top Shelf 拡張を足し、ホーム最上段からの起動を試します。
3. 連続再生の上限とフェードを入れ、点けっぱなしでも安心できる挙動に整えます。

黒フレームが消えた瞬間に、この作り方の意味が腑に落ちると思います。居間に置ける静かな一画面が、少しずつ形になっていきます。

私もまだ調整を重ねている途中ですが、大きな画面で自分の作品が静かに流れている光景には、iPhone とは違う手応えがあります。同じように個人開発で作品を別の場所へ届けたい方の参考になれば幸いです。
