メモ機能のあるアプリを運用していると、ある時期から同じ要望が繰り返し届くようになりました。「書いた内容を PDF で送りたい」。私自身、最初は共有シートにテキストを流すだけで十分だと考えていたのですが、仕事の記録として使ってくださっている方にとって、体裁の整った PDF はテキストの代わりにならない「成果物」なのだと気づかされました。

Rork Max はネイティブ Swift を生成するため、OS に同梱されている PDFKit をそのまま使えます。表示・検索・書き出しまで依存ライブラリの追加なしで完結する、という点が React Native 構成との最も大きな違いです。以下、PDF の表示から書き出し、パスワード保護、共有シート連携までを、動くコードで順に組み上げていきます。

## なぜ Rork Max（ネイティブ Swift）で PDF を扱うのか

React Native 版の Rork で PDF を扱う場合、選択肢はサードパーティ製ライブラリか WebView 表示、生成側は expo-print のような HTML 経由のブリッジになります。動くことは動くのですが、依存の保守と表現の細かい制御に限界がありました。

個人開発では「依存を増やさないこと」自体が保守コストの削減です。PDF まわりを OS 標準の枠組みに寄せられるのは、ネイティブ生成を選ぶ実利のひとつだと考えています。

Rork Max へのプロンプトは、次のような一文から始めるのが実用的でした。

```text
保存済みのメモを PDF として表示・書き出しできる画面を追加してください。
表示は PDFKit の PDFView、書き出しは UIGraphicsPDFRenderer を使い、
共有シートから送れるようにしてください。
```

生成されたコードを前提に、以下では各部品の要点と、手を入れるべき箇所を順に見ていきます。

## PDFView で表示する — SwiftUI に載せる最小構成

PDFKit の中心は `PDFView` です。UIKit のビューなので、SwiftUI からは `UIViewRepresentable` で包みます。

```swift
import SwiftUI
import PDFKit

struct PDFViewer: UIViewRepresentable {
    let url: URL

    func makeUIView(context: Context) -> PDFView {
        let view = PDFView()
        view.autoScales = true                 // 画面幅に合わせて自動スケール
        view.displayMode = .singlePageContinuous
        view.usePageViewController(true)       // ページ単位のスワイプ感
        view.document = PDFDocument(url: url)
        return view
    }

    func updateUIView(_ uiView: PDFView, context: Context) {
        if uiView.document?.documentURL != url {
            uiView.document = PDFDocument(url: url)
        }
    }
}
```

最初のつまずきどころは `autoScales` です。指定を忘れると PDF が原寸で描画され、画面の隅に豆粒のような表示になります。生成コードに含まれていないことがあるため、表示が小さい場合はまずここを確認してください。

`PDFDocument(url:)` はページを遅延読み込みするため、数百ページの PDF でも初期表示は軽快です。一方で `Data` に全読みしてから `PDFDocument(data:)` に渡す実装は、大きなファイルでメモリを一気に消費します。ローカルファイルなら URL 初期化を使うことをお勧めします。

## 検索とサムネイルを足す — 「読む」体験の底上げ

表示だけなら WebView でも近いことはできますが、PDFKit の価値は検索とサムネイルが数行で付くことです。

```swift
// キーワード検索して最初の一致へジャンプ
if let document = pdfView.document {
    let matches = document.findString("請求書", withOptions: .caseInsensitive)
    if let first = matches.first {
        pdfView.go(to: first)
        pdfView.setCurrentSelection(first, animate: true)
    }
}
```

サムネイル一覧は `PDFThumbnailView` を `PDFView` に接続するだけです。

```swift
let thumbnail = PDFThumbnailView()
thumbnail.pdfView = pdfView          // 接続すると選択が同期する
thumbnail.thumbnailSize = CGSize(width: 44, height: 60)
thumbnail.layoutMode = .horizontal
```

ページ数の多い資料を扱うアプリでは、この2つがあるかどうかで「読める」体験が大きく変わります。取り込み側の設計は [ユーザー自身の画像を「ファイル」アプリから取り込む実装](/articles/rork-dev/rork-document-picker-files-app-security-scoped-url-import) で扱ったセキュリティスコープ付き URL の考え方がそのまま使えます。

## PDF を作る（1）UIGraphicsPDFRenderer — ページを自分で組む

書き出しの本命は `UIGraphicsPDFRenderer` です。ページサイズを決め、描画クロージャの中に文字や図を配置していきます。複数ページの分割も自分で制御できます。

```swift
import UIKit

func exportNotesPDF(title: String, body: String) -> URL {
    let pageRect = CGRect(x: 0, y: 0, width: 595.2, height: 841.8) // A4 (72dpi)
    let renderer = UIGraphicsPDFRenderer(bounds: pageRect)
    let url = FileManager.default.temporaryDirectory
        .appendingPathComponent("notes-\(Int(Date().timeIntervalSince1970)).pdf")

    let titleAttrs: [NSAttributedString.Key: Any] = [
        .font: UIFont.systemFont(ofSize: 20, weight: .bold)
    ]
    let bodyAttrs: [NSAttributedString.Key: Any] = [
        .font: UIFont.systemFont(ofSize: 12),
        .paragraphStyle: NSParagraphStyle.default
    ]

    try? renderer.writePDF(to: url) { context in
        context.beginPage()
        title.draw(in: CGRect(x: 48, y: 48, width: 499, height: 40),
                   withAttributes: titleAttrs)

        let bodyText = NSAttributedString(string: body, attributes: bodyAttrs)
        let framesetter = CTFramesetterCreateWithAttributedString(bodyText)
        var currentRange = CFRange(location: 0, length: 0)
        var firstPage = true

        repeat {
            if !firstPage { context.beginPage() }
            let top: CGFloat = firstPage ? 100 : 48
            let textRect = CGRect(x: 48, y: top, width: 499,
                                  height: pageRect.height - top - 48)
            let path = CGPath(rect: textRect, transform: nil)
            let frame = CTFramesetterCreateFrame(framesetter, currentRange, path, nil)

            // Core Text は左下原点なので上下反転してから描く
            let cg = context.cgContext
            cg.saveGState()
            cg.translateBy(x: 0, y: pageRect.height)
            cg.scaleBy(x: 1, y: -1)
            CTFrameDraw(frame, cg)
            cg.restoreGState()

            let visible = CTFrameGetVisibleStringRange(frame)
            currentRange.location += visible.length
            firstPage = false
        } while currentRange.location < bodyText.length
    }
    return url
}
```

要点は3つです。第一に、ページ分割は `CTFrameGetVisibleStringRange` で「描けた文字数」を取り、残りを次ページへ回すループで実現します。第二に、Core Text は座標系が左下原点のため、上下反転してから描画しないと文字が逆さまになります。第三に、日本語はシステムフォント指定でそのまま埋め込まれるため、フォントの同梱作業は不要です。

## PDF を作る（2）ImageRenderer — SwiftUI ビューをそのまま1ページに

iOS 16 以降なら、SwiftUI の `ImageRenderer` でビューをそのまま PDF にできます。レイアウトを SwiftUI で組んだ画面をそのまま「紙」にする発想です。

```swift
import SwiftUI

@MainActor
func exportViewAsPDF<V: View>(_ view: V, size: CGSize) -> URL {
    let url = FileManager.default.temporaryDirectory
        .appendingPathComponent("summary.pdf")
    let renderer = ImageRenderer(content: view.frame(width: size.width,
                                                     height: size.height))
    renderer.proposedSize = .init(size)

    renderer.render { rendered, draw in
        var box = CGRect(origin: .zero, size: rendered)
        guard let context = CGContext(url as CFURL, mediaBox: &box, nil) else { return }
        context.beginPDFPage(nil)
        draw(context)
        context.endPDFPage()
        context.closePDF()
    }
    return url
}
```

ただし ImageRenderer には明確な限界があります。ページ分割の概念がなく、長いコンテンツは1枚の縦長ページになります。私の場合、使い分けの基準は次のとおりです。

1. 月次サマリーやレシートのような「1画面で完結する帳票」→ ImageRenderer。実装が数行で済み、デザインの修正も SwiftUI 側だけで完結します。
2. メモや議事録のような「長さが読めないテキスト」→ UIGraphicsPDFRenderer。ページ分割を自分で持てることが決定打です。
3. 既存 PDF への注釈・結合 → PDFKit の `PDFAnnotation` と `PDFDocument.insert(_:at:)`。手書き注釈まで踏み込むなら [PencilKit の手書きノート実装](/articles/rork-dev/rork-pencilkit-apple-pencil-handwriting-note-app-guide) と組み合わせる構成になります。

## パスワード保護と共有シート — 書き出しの出口を整える

仕事の記録を書き出す用途では、パスワード付き書き出しの要望が一定数あります。`PDFDocument.write(to:withOptions:)` に暗号化オプションを渡すだけです。

```swift
if let document = PDFDocument(url: exportedURL) {
    let protectedURL = FileManager.default.temporaryDirectory
        .appendingPathComponent("protected.pdf")
    document.write(to: protectedURL, withOptions: [
        .userPasswordOption: userPassword,    // 閲覧用
        .ownerPasswordOption: ownerPassword   // 権限変更用（別の値にする）
    ])
}
```

共有は SwiftUI の `ShareLink` に URL を渡せば共有シートが開きます。書き出した一時ファイルは `temporaryDirectory` に置き、共有完了後か次回起動時に掃除する運用にしておくと、ストレージを圧迫しません。アプリ内で開く導線を先に見せたい場合は、[Quick Look をアプリから安全に呼ぶ設計](/articles/app-dev/rork-expo-quick-look-in-app-file-preview-qlpreviewcontroller-design) で書いたプレビュー画面を挟むと、送る前に確認できる安心感が出ます。

## 本番で踏んだ落とし穴

私はこの順につまずきました。同じ回り道を避けていただければ幸いです。

1. **ImageRenderer の解像度**: 既定の `scale` は 1.0 のため、そのままだと印刷時にぼやけます。画像として使う場合は `renderer.scale = displayScale` を指定してください（PDF 描画の場合はベクターで出るテキストは影響を受けませんが、埋め込み画像には効きます）。
2. **`write(to:)` の暗号化はコピーに効く**: すでに開いている `PDFDocument` のプロパティは変わりません。保護版は必ず別 URL に書き出し、元ファイルの扱い（削除するか残すか）を決めておきます。
3. **`documentURL` での差分判定**: `updateUIView` で毎回 `document` を差し替えると表示位置がリセットされます。URL 比較で変更時のみ差し替えるのが安全です。
4. **共有シートに出るファイル名**: `temporaryDirectory` 直下のファイル名がそのまま相手に見えます。`notes-1751522400.pdf` のような機械的な名前ではなく、日付やタイトルを含めた名前を付けると、受け取った側の印象がまったく違います。

書き出し機能を載せたバージョンを配信した週から、レビュー欄の「PDF で送れないのか」という声は止まりました。配信から2週間の計測では、書き出しの利用は DAU の約8%で安定し、書き出しを使った利用者の翌週残存は使っていない層より明確に高い、という結果になりました。地味な機能ですが、アプリの外に「成果物」として出ていくファイルは、それ自体が小さな広告にもなります。

## 次のアクション

まずは手元のアプリのデータを1件、`UIGraphicsPDFRenderer` で A4 一枚に書き出すところから始めてみてください。ページ分割やパスワードは後からで構いません。「アプリの中の情報が、体裁の整った紙になって外に出る」体験を最短で確認できれば、その先にどの機能を足すべきかは、利用者の反応が教えてくれます。
