写真ライブラリから壁紙の素材を選ぶ画面と、QR コードを読み取る画面。その二つを持つアプリの設定を見直していた夕方のことでした。画像の選択にはカメラを使わないので、`expo-image-picker` の設定に `cameraPermission: false` と書いておけば、余計な権限がひとつ減ってすっきりする——私はそう考えておりました。

ところが、この書き方には落とし穴があります。11 月 14 日に Expo の Issue（[#53507](https://github.com/expo/expo/issues/53507)）として報告された内容を読み、プラグインのソースを辿ってみると、`false` は「画像の選択ではカメラを使わない」という意味では働いていませんでした。**アプリ全体からカメラの権限を消す**という意味で働くのです。

最初にお伝えしたいのは、一つの設定値が、別のパッケージの権限まで書き換えることがある、という点です。気づかないまま審査に出すと、iOS ではカメラを開いた瞬間にアプリが落ちます。

## 何が起きているのか

報告者の再現手順は、空のプロジェクトに `expo-camera` と `expo-image-picker` を入れ、`app.json` に次の順で書くだけです。

```json
"plugins": [
  ["expo-image-picker", { "photosPermission": "Pick a photo.", "cameraPermission": false }],
  ["expo-camera", { "cameraPermission": "Scan QR codes." }]
]
```

この状態で `npx expo prebuild --clean` を実行すると、次のようになると報告されています（expo 58.0.25・expo-image-picker 58.0.10・expo-camera 58.0.14、SDK 57 でも同じ）。

- iOS: `Info.plist` から `NSCameraUsageDescription` が消え、`expo-camera` 側に書いた「Scan QR codes.」も残りません
- Android: `AndroidManifest.xml` の `android.permission.CAMERA` に `tools:node="remove"` が付き、どのパッケージが足しても消される状態になります
- 実機・シミュレータ: `CameraView` を開いた瞬間に、用途の説明がないという理由でクラッシュします

ドキュメントの説明は「`false` を渡すと Android で CAMERA 権限がブロックされます」という Android だけの書き方です。iOS の説明文まで消えるとは読み取れません。私自身、最初はそう読んでおりました。

## ソースを読むと、理由はとても単純でした

iOS 側は、`@expo/config-plugins` の `applyPermissions` という関数が担っています。中身は 20 行ほどで、要点は次の分岐です。

```ts
if (permissions[permission] === false) {
  delete infoPlist[permission];
} else {
  infoPlist[permission] = permissions[permission] || infoPlist[permission] || description;
}
```

`false` なら、そのキーを `Info.plist` から消します。ほかのプラグインがすでに書いた値かどうかは確かめません。一方で文字列を渡した場合は、既存の値があれば残す書き方になっています。つまり**文字列は足し算、`false` は引き算**として振る舞うのです。

Android 側は、`expo-image-picker` のプラグインがコメントでこう明言しています。「ユーザーが権限を `false` にしたら、どのパッケージも追加できないようにブロックする」。こちらは設計どおりの動きで、`withBlockedPermissions` が CAMERA を塞ぎます。

なお、報告者が試したプラグインの並び順は一通りだけだと、Expo 側の自動トリアージにも書かれています。並び順を入れ替えれば助かる場合があるかもしれませんが、私はそこに頼らない方を選びました。順番に意味を持たせた設定は、半年後の自分が必ず崩すからです。

## 直し方: false をやめて、同じ説明文を両方に書きます

報告者の回避策は、両方のプラグインに同じ `cameraPermission` の文字列を渡すことでした。これがいちばん素直だと思います。

```json
"plugins": [
  ["expo-image-picker", {
    "photosPermission": "壁紙に使う写真を選ぶために、写真ライブラリを読み込みます。",
    "cameraPermission": "QR コードを読み取るためにカメラを使います。"
  }],
  ["expo-camera", {
    "cameraPermission": "QR コードを読み取るためにカメラを使います。"
  }]
]
```

どちらのプラグインが後から書いても、同じ文が残ります。画像の選択でカメラを起動しないのであれば、ピッカー側に説明文があっても困ることはありません。

逆に、アプリのどこでもカメラを使わないと決めているなら、そのときこそ `false` の出番です。Android で CAMERA を確実に塞げるのは、ほかの SDK が勝手に権限を足してくる場面では心強い動きでもあります。要するに、**`false` は「この機能で使わない」ではなく「このアプリで使わせない」と読む**——私はこの線引きで書き分けることにしました。

権限の説明文そのものの書き方は、[用途の説明が不十分として差し戻されたときの書き直し](/articles/app-dev/rork-app-store-insufficient-purpose-strings-rejection-rewrite)に、使っていない説明文が増える側の問題は [plugins が空でも Info.plist に説明文が並んだ記録](/articles/rork-basics/expo-sdk58-unused-usage-description-info-plist-prebuild-audit)にまとめております。今回はその逆向き、必要な説明文が消える側のお話です。

## 提出前に、使う権限と突き合わせるスクリプト

設定を直しても、プラグインを一つ足せば同じことは起こりえます。そこで、prebuild の結果を「アプリが本当に使う権限の一覧」と突き合わせる小さなスクリプトを用意しました。Python の標準ライブラリだけで動きます。

何を解決するかというと、「消えている」「既定の英語文のまま」「Android で塞がれている」の三つを、ビルドを実機に入れる前に一度に見つけることです。

```python
#!/usr/bin/env python3
"""prebuild 後の権限を、アプリが本当に使う一覧と突き合わせる。
使い方: python3 check_permissions.py  （プロジェクトのルートで実行）"""
import glob
import plistlib
import sys
import xml.etree.ElementTree as ET

# アプリが実際に使う権限を、ここに手で書く（iOS のキー, Android の権限）
REQUIRED = [
    ("NSCameraUsageDescription", "android.permission.CAMERA"),
    ("NSPhotoLibraryUsageDescription", None),
]
DEFAULT_PREFIX = "Allow $(PRODUCT_NAME)"  # 既定の英語文は審査で弱い
ANDROID_NS = "{http://schemas.android.com/apk/res/android}name"
TOOLS_NODE = "{http://schemas.android.com/tools}node"

problems = []

plists = [p for p in glob.glob("ios/*/Info.plist") if "Pods" not in p]
if not plists:
    sys.exit("ios/*/Info.plist が見つかりません。先に npx expo prebuild --clean を実行してください")
with open(plists[0], "rb") as f:
    info = plistlib.load(f)

manifest = "android/app/src/main/AndroidManifest.xml"
granted, removed = set(), set()
try:
    for el in ET.parse(manifest).getroot().iter("uses-permission"):
        name = el.get(ANDROID_NS)
        # tools:node="remove" は「どのパッケージが足しても消す」という指定
        (removed if el.get(TOOLS_NODE) == "remove" else granted).add(name)
except FileNotFoundError:
    print(f"注意: {manifest} が無いので Android は確かめません")

for ios_key, android_perm in REQUIRED:
    text = info.get(ios_key)
    if text is None:
        problems.append(f"iOS: {ios_key} がありません（開いた瞬間に落ちます）")
    elif text.startswith(DEFAULT_PREFIX):
        problems.append(f"iOS: {ios_key} が既定の英語文のままです: {text}")
    if android_perm and android_perm in removed:
        problems.append(f"Android: {android_perm} が tools:node=\"remove\" で消されています")
    elif android_perm and granted and android_perm not in granted:
        problems.append(f"Android: {android_perm} がマニフェストにありません")

for p in problems:
    print("NG", p)
print("OK すべて揃っています" if not problems else f"{len(problems)} 件を直してから提出します")
sys.exit(1 if problems else 0)
```

プロジェクトのルートで `npx expo prebuild --clean` のあとに実行します。ダミーの `Info.plist` とマニフェストを用意して、カメラの説明文を消し、CAMERA に `tools:node="remove"` を付けた状態で試したところ、出力は次のとおりでした。

```text
NG iOS: NSCameraUsageDescription がありません（開いた瞬間に落ちます）
NG Android: android.permission.CAMERA が tools:node="remove" で消されています
2 件を直してから提出します
```

説明文を戻して `remove` を外すと「OK すべて揃っています」に変わり、終了コードも 1 から 0 になります。CI の手順に一行足しておけば、終了コードで止められます。

なぜ `REQUIRED` を手書きにしているかというと、「どの権限を使うか」はコードから自動で拾うより、自分で書き出した方が判断の記録として残るからです。AI にアプリを組んでもらうことが増えた分、ここだけは人の手で決めるようにしております。

## Rork で作ったアプリで確かめるときの順番

Rork から書き出したプロジェクトでも、手順は変わりません。

1. `app.json`（または `app.config.ts`）の `plugins` を開き、`false` が書かれている箇所を探します
2. その権限を、アプリのほかの画面やパッケージが使っていないかを確かめます
3. 使っているなら `false` を説明文の文字列に置き換えます
4. `npx expo prebuild --clean` を実行し、上のスクリプトを走らせます
5. iOS ではカメラを開く画面を、一度だけでも実際に触ってから提出します

5 番目を省くと、スクリプトの `REQUIRED` に書き漏らした権限には気づけません。機械の検査は、自分で書いた一覧の範囲しか守ってくれないのです。

## 結び

この Issue はまだ開いたままで、将来は prebuild の時点で警告が出るようになるかもしれません。それでも、`false` が引き算として働くこと自体は、iOS でも Android でも当面は変わらないと見ております。

まずはお手元の `app.json` で `Permission": false` を検索してみていただければと思います。一つも見つからなければ、それがいちばんの安心です。
