# Migrating Your Rork App to Claude 4

If you've built a Rork app with Claude API integration, you've probably been wondering whether it's time to move to Claude 4. With claude-sonnet-4-6 now generally available and new capabilities like Extended Thinking added to the mix, the answer is increasingly yes.

The good news: migration is straightforward. The catch: just swapping the model string leaves a lot of the new performance on the table. This guide walks through a complete migration from Claude 3.x to Claude 4 in a Rork project — what changed, what to update, and how to take advantage of the new features.

## What's New in Claude 4

Before diving into code changes, here's what you're actually getting from the upgrade.

**New model identifiers**

The naming convention changed for Claude 4. You'll need to update every place in your code that references a model string.

```javascript
// Before (Claude 3.x)
model: "claude-3-5-sonnet-20241022"

// After (Claude 4)
model: "claude-sonnet-4-6"      // Balanced — most use cases
model: "claude-opus-4-6"        // Highest capability
model: "claude-haiku-4-5-20251001"  // Lightweight, high-frequency tasks
```

**Extended Thinking**

The headline feature for Claude 4 is Extended Thinking — the model's ability to reason through a problem before giving a final answer. The thinking process is returned as a separate content block you can optionally display to users.

This matters most when your app needs decisions that should be explainable: legal questions, medical context, financial planning, or complex multi-step reasoning. For these use cases, Extended Thinking noticeably improves answer quality and reduces confident-sounding errors.

**200K token context window**

claude-sonnet-4-6 supports up to 200K tokens of context. For most chat apps this won't make a difference, but it opens up use cases where you want to pass in long documents or maintain very extended conversation histories.

**Adjusted rate limits**

claude-haiku-4-5-20251001 in particular has relaxed rate limits compared to previous Haiku versions, making it more practical for features that fire on every keystroke or generate real-time completions.

## Three Steps to Complete the Migration

### Step 1: Centralize your model references

The first structural improvement to make alongside upgrading is to stop hard-coding model strings everywhere. Pull them into a single configuration file.

```javascript
// utils/claude.js
export const CLAUDE_MODELS = {
  // Fast, cheap: chat replies, classification, tagging
  fast: "claude-haiku-4-5-20251001",
  // Balanced: main conversational AI, content generation
  balanced: "claude-sonnet-4-6",
  // Highest accuracy: legal/medical/complex reasoning
  advanced: "claude-opus-4-6",
};
```

This pattern pays off every time Anthropic releases a new model — you update one file rather than hunting through your entire codebase.

### Step 2: Set explicit max_tokens values

With Claude 4, it's best practice to always specify `max_tokens` explicitly. The model can produce longer, more thorough answers, and undefined behavior around truncation is easier to debug when the limit is explicit.

```javascript
const response = await client.messages.create({
  model: CLAUDE_MODELS.balanced,
  max_tokens: 1024,  // Adjust per use case
  messages: conversationHistory,
  system: systemPrompt,
});
```

A practical starting point: 512–1024 for conversational replies, 2048–4096 for content generation or analysis tasks.

### Step 3: Review streaming event handling

If you've implemented streaming responses, verify your event handling code against the current SDK. The recommended pattern for React Native environments is the text stream helper:

```javascript
const stream = await client.messages
  .stream({
    model: CLAUDE_MODELS.balanced,
    max_tokens: 1024,
    messages,
  })
  .on("text", (text) => {
    setPartialResponse((prev) => prev + text);
  });

const finalMessage = await stream.finalMessage();
```

The `.on("text", ...)` callback is simpler and more reliable in React Native than manually parsing `content_block_delta` events.

## Implementing Extended Thinking

Extended Thinking is opt-in — you won't accidentally enable it, and adding it is a deliberate choice for specific features.

```javascript
const response = await client.messages.create({
  model: "claude-sonnet-4-6",
  max_tokens: 16000,
  thinking: {
    type: "enabled",
    budget_tokens: 10000,  // Max tokens for reasoning (costs extra)
  },
  messages: [
    {
      role: "user",
      content: userMessage,
    },
  ],
});

// Process the response blocks
for (const block of response.content) {
  if (block.type === "thinking") {
    // Optional: display reasoning to the user for transparency
    console.log("Reasoning:", block.thinking);
  } else if (block.type === "text") {
    setResponse(block.text);
  }
}
```

A few things to know before turning it on:

- `budget_tokens` adds to your total token cost. At 10,000 budget tokens, you're paying for the thinking process in addition to the final answer.
- Responses are slower — the model is doing more work before replying. If you enable this for a live chat interface, users will notice the latency increase.
- Start with `budget_tokens: 5000` and increase only if you're not satisfied with the reasoning quality.

**When Extended Thinking is worth it**

- Users asking for advice that needs to be explainable and trustworthy
- Multi-step problem solving where intermediate steps matter
- Legal, medical, or financial contexts where confident errors are costly

**When Extended Thinking isn't worth it**

- Standard conversational chat
- Content generation (product descriptions, summaries)
- Quick lookup or completion tasks

For most Rork apps, Sonnet without Extended Thinking is the right default. Reserve it for specific features where the cost is justified.

## Model Selection in Practice

Here's how to think about which Claude 4 model to use for different parts of your app:

```javascript
function getModelForTask(taskType) {
  const modelMap = {
    // High-frequency, low-complexity
    "autocomplete": CLAUDE_MODELS.fast,
    "classification": CLAUDE_MODELS.fast,
    "short_summary": CLAUDE_MODELS.fast,
    
    // Main conversational features
    "chat": CLAUDE_MODELS.balanced,
    "content_generation": CLAUDE_MODELS.balanced,
    "translation": CLAUDE_MODELS.balanced,
    
    // Premium or complex features
    "legal_advice": CLAUDE_MODELS.advanced,
    "medical_context": CLAUDE_MODELS.advanced,
    "complex_planning": CLAUDE_MODELS.advanced,
  };
  
  return modelMap[taskType] ?? CLAUDE_MODELS.balanced;
}
```

A common mistake is defaulting everything to Opus "because it's the best." For a chat app where users send dozens of messages, using Opus across the board is expensive and often unnecessary — Sonnet handles the vast majority of conversational tasks just as well.

## Common Migration Issues

**`model_not_found` errors**

Old model strings still exist somewhere in your code. Search systematically:

```bash
# Find all old model references
grep -r "claude-3" --include="*.js" --include="*.ts" .
grep -r "claude-2" --include="*.js" --include="*.ts" .
```

Update every match to the appropriate Claude 4 equivalent.

**Responses get truncated more often**

Claude 4 tends to give more complete answers than Claude 3.x for the same max_tokens value. If you were previously running with 512 and getting cut-off responses, try 1024 or 2048.

**Extended Thinking responses are too slow for the UI**

If you're using Extended Thinking in a live chat interface, add a loading indicator that reflects the longer wait time. Alternatively, consider running Extended Thinking only for asynchronous features (background analysis, report generation) rather than real-time chat.

**Streaming feels laggy in React Native**

Calling `setState` on every text delta from the stream can cause performance issues on lower-end devices. A simple fix is to batch updates with a short delay:

```javascript
let buffer = "";
const flushBuffer = debounce(() => {
  setPartialResponse((prev) => prev + buffer);
  buffer = "";
}, 50);

stream.on("text", (text) => {
  buffer += text;
  flushBuffer();
});
```

## Start with One Feature

The practical approach to migration: pick one feature in your app, swap it to claude-sonnet-4-6, and observe the quality difference before migrating everything. If you have a chat interface, that's usually the right place to start — the improvement in response coherence and instruction-following is immediately noticeable.

After a week of testing, you'll have a clear sense of whether Extended Thinking is worth enabling for specific use cases, and which model tier makes sense for different parts of your app. That informed perspective is worth more than a big-bang migration done all at once.

Claude 4 represents a meaningful jump in capability — particularly for apps where users rely on the AI for real decisions. Taking the time to migrate thoughtfully will show up as a better experience for your users.

## What Actually Improves in Practice

It's worth being concrete about where Claude 4 makes a noticeable difference in a real Rork app, versus where the upgrade is marginal.

**Instruction following in complex prompts**

If your system prompt has more than five or six rules, Claude 4 follows them with higher consistency. Apps that use detailed persona instructions, strict formatting requirements, or multi-conditional logic will see the most improvement here.

**Handling ambiguous requests**

Claude 4 is better at recognizing when a user's message is ambiguous and either asking a clarifying question or making a sensible interpretation explicit. This reduces the "confidently wrong" responses that erode user trust in AI features.

**Code generation and debugging**

For apps that include any coding assistance features — even simple things like generating SQL queries or formatting data — Sonnet 4.6 writes cleaner, more idiomatic code than previous models.

**What hasn't changed much**

Basic factual retrieval, simple question answering, and translation are all handled similarly well by Claude 3.5 Sonnet and Claude Sonnet 4.6. If your app is primarily doing these tasks, the upgrade is still worthwhile for consistency, but don't expect a dramatic difference in perceived quality.

The areas where you'll see the biggest ROI from upgrading are long conversation coherence, complex instruction sets, and Extended Thinking for high-stakes decisions.
