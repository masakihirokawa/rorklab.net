I was reworking the part of my wallpaper app that suggests categories for new images when I opened the Gemini API deprecations page and stopped scrolling. The December 1 row did not say "shutdown." It said the calls would be **automatically routed** to another model.

I had been assuming that a deprecation means errors. Errors show up in Crashlytics, and I would catch them in the logs the next morning. Rerouting is different: the app keeps running as if nothing happened. What changes is the wording and length of the answers, and the price per token.

The one thing I want to say up front: **a deadline that reroutes is harder to notice than a deadline that breaks.** There are seven days left, counting today. If you added an AI feature to an app built with Rork, here is how I'd check it before then.

## What happens on December 1

The Gemini API [Deprecations](https://ai.google.dev/gemini-api/docs/deprecations) page says that from December 1 the following calls are routed to successor models.

<thead><tr><th>Model name your app calls today</th><th>Routed to from December 1</th></tr></thead>

<tr><td><code>gemini-2.5-flash</code></td><td><code>gemini-3.5-flash-lite</code></td></tr>
<tr><td><code>gemini-2.5-pro</code></td><td><code>gemini-3.8-flash</code></td></tr>

Worth noting: once routed, you are billed at **the successor model's rate**. If you set a monthly budget around 2.5 pricing, that number needs another look too. On the developer forum someone has already asked for an extension because an audio relevance check behaved differently on the successor. My guess is that the more your code depends on the exact shape of an answer, the more likely it is to feel this.

If you use versioned names such as `-001`, or anything ending in `-preview`, check those rows on the same page. They may not be handled the same way.

## Step 1: Find every model name your app calls

With Rork-built apps, it is common not to know exactly where the model name lives. I assumed it wasn't in the screen code, and it wasn't — it was hard-coded in a server function I had forgotten about.

The most reliable first move is to ask Rork's chat once:

> List every place in this project that calls the Gemini API, as file name and model name. Do not change any code.

If you have the exported code locally, you can also search from a terminal:

```bash
# Run at the root of the exported project
grep -rnE "gemini-2\.5-(flash|pro)" --include='*.ts' --include='*.tsx' --include='*.js' --include='*.json' . \
  | grep -v node_modules
```

Sort each hit into **inside the app binary** or **on a server** (a Supabase Edge Function, Cloudflare Workers, and so on). That split decides Step 4. I wrote more about where these values should live in [environment variables vs. an Edge Function for API keys](/en/articles/rork-ai/rork-api-key-placement-env-variables-vs-supabase-edge-function).

## Step 2: Send the same inputs to today's model and the successor

You don't have to wait for December 1. The successor models can be called by name today, so send the same inputs to both and put the answers side by side.

This script runs as-is on Node.js 18 or later. Put about ten real prompts your app sends into `inputs.json`.

```javascript
// compare-models.mjs — send the same inputs to two models and compare shape and time
// Run: GEMINI_API_KEY=YOUR_API_KEY node compare-models.mjs inputs.json
import { readFile } from "node:fs/promises";

const PAIRS = [["gemini-2.5-flash", "gemini-3.5-flash-lite"]]; // add a row if you use 2.5-pro
const KEY = process.env.GEMINI_API_KEY;
if (!KEY) throw new Error("GEMINI_API_KEY is not set");

async function ask(model, text) {
  const started = Date.now();
  const res = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent`,
    {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-goog-api-key": KEY },
      body: JSON.stringify({ contents: [{ parts: [{ text }] }] }),
    }
  );
  const ms = Date.now() - started;
  if (!res.ok) return { model, ms, error: `${res.status} ${await res.text()}` };
  const data = await res.json();
  const out = data.candidates?.[0]?.content?.parts?.map((p) => p.text ?? "").join("") ?? "";
  let isJson = false;
  try { JSON.parse(out.replace(/^\x60{3}(json)?\s*|\x60{3}\s*$/g, "")); isJson = true; } catch {}
  return { model, ms, chars: out.length, isJson, tokens: data.usageMetadata?.totalTokenCount, head: out.slice(0, 60) };
}

const inputs = JSON.parse(await readFile(process.argv[2], "utf8"));
for (const [oldModel, newModel] of PAIRS) {
  for (const [i, text] of inputs.entries()) {
    const [a, b] = [await ask(oldModel, text), await ask(newModel, text)];
    console.log(`#${i + 1}`, JSON.stringify(a), "\n   ", JSON.stringify(b));
  }
}
```

Before judging whether the answers are better or worse, check whether **the shape is the same**. `isJson` turning false on only one side, the character count nearly doubling, a new preamble sentence at the top — when a screen or a parser breaks, it is almost always one of those three. Looking at latency (ms) and token count on the same line also gives you a rough idea of the cost change.

## Step 3: Pin the answer shape on your side

If the shape wobbles, tighten the request before changing models. In the Gemini API you can pass `responseMimeType: "application/json"` and a `responseSchema` in `generationConfig` to ask for JSON in a fixed structure. Anywhere you only wrote "please reply in JSON" in the prompt is a good place to switch over.

If you cache AI answers, check that the model name is part of the cache key. Otherwise old answers keep showing up after the switch. I covered that in [sweeping the cache on the day you swap models](/en/articles/rork-ai/ai-answer-cache-key-model-and-prompt-version-sweep-on-swap).

## Step 4: Switch yourself, or let the routing happen?

This is where the Step 1 split matters.

- **The name lives on a server**: if the comparison looks fine, I'd change the model name yourself before December 1. You'll know exactly when it changed, and you keep the decision to roll back.
- **The name lives inside the app binary**: changing it means an app review, and a build submitted this week may not clear in time. In that case, assume the routing will happen, ship the Step 3 shape pinning first, and plan to move the model name to the server side.

The line I draw for my own apps: **Google sets the date; I set the moment of the switch.** If I wait for the routing, I can't watch the change happen.

Claude API's Sonnet 4.5 also retires on November 30, the same week. If your app uses both, checking alongside [the Sonnet 4.5 model ID sweep](/en/articles/rork-ai/scan-app-for-old-claude-model-ids-before-sonnet-4-5-retires) saves you a second pass.

## What to do next

If you can, make the Step 1 list today and split each hit into "app binary" or "server." Once that list exists, the comparison itself is not heavy work. As an indie developer, the one thing I try to hold to — even for small apps — is not letting the day my answers change arrive without my knowing.
