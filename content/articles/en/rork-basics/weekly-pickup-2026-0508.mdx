## A Minimal Version-Pinned Prompt

Pulling from #1 — the most basic shape of a version-pinned prompt. The pattern works well beyond Rork, anywhere you're generating code with AI.

```text
[Dependencies and current versions]
- React Native: 0.74.x
- React Navigation: 6.x (the v5 → v6 API differences are large)
- React Native Reanimated: 3.x (do NOT use the v2 "useAnimatedStyle" examples)

[What to implement]
- A 200ms fade animation when navigating from Screen A to Screen B.

[Constraints]
- Use the React Navigation 6 "screenOptions" API.
- Explicitly handle the reverse animation on back navigation.
```

The non-obvious habit: spell out "what version *not* to write" alongside "what version *to* write." Models snap back into older idioms surprisingly often when given only the positive target — adding the negative cue stabilizes output.

## Reader Questions

### Should I pick Rork or Rork Max?

My current take: Rork for lightweight prototyping or personal projects, Rork Max when you're aiming for production quality. The kinds of production-design topics in #3, #4, and #5 are much easier to apply with Rork Max under the hood.

### Can I make AI-generated code production-grade from the first draft?

Honestly, not yet. A two-step approach is the realistic answer: lift the baseline with version-pinned prompts (#1), then add hardening with the field-tested capture designs in #4 and #5.

### Where should I look first when the ATT dialog won't appear?

In my experience, two checks first: confirm `NSUserTrackingUsageDescription` is in `Info.plist`, and check the timing of the call. The opening of #5 walks through this diagnosis in three steps.
