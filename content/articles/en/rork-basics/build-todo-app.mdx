One night I assumed a Todo app would take ten minutes, so I packed every feature into a single prompt. A screen appeared. Pressing "Add" did nothing, I had no idea where to start fixing it, and the clock kept moving.

Looking back, the app wasn't the problem. My request was simply too big. What I'd like to say up front is this: **a Todo app finishes faster when you grow it one piece at a time than when you ask for everything at once.** Here are the six steps I now follow, so you can skip the detour I took.

A correction, too. An earlier version of this page described creating the project with terminal commands. Rork works by sending it plain-language messages in the app or browser, so that description didn't match what you actually do. I've rewritten the whole thing.

## What we're building, and the line I draw first

The app does only four things:

- Adds one task at a time
- Marks a task as done with a checkbox
- Deletes a task
- Keeps the list after you close and reopen the app

No due dates, categories, or notifications this time. I know the temptation, but that's exactly how I got lost. **Add things after the app works, and add only one at a time.** I tell myself that before I start.

You'll need a Rork account and, ideally, a real phone. Spacing and text size often look fine in a preview and wrong on a device, so I'd rather you check on the phone.

## Step 1: Ask for the screen only

The first prompt asks for looks, not behavior.

```text
Create the screen for a simple Todo app.
- A title at the top: "My Tasks"
- A text input and an "Add" button
- A list of tasks below (empty at first)
- When the list is empty, show "No tasks yet"
Only the layout for now. I'll add behavior later.
```

The short line "only the layout for now" matters. Without it, Rork may helpfully add features you didn't ask for.

When the preview appears, check four things by eye: title, input, button, empty-state text. If all four are there, move on.

## Step 2: Make "Add" work

```text
When I type text and tap "Add", put the new task at the top of the list.
Do nothing if the input is empty. Clear the input after adding.
```

Always test the empty case. I once skipped it and found a column of blank tasks on my phone. If you don't specify what happens on empty input, nobody decides.

## Step 3: Add complete and delete, one prompt each

```text
Add a checkbox to the left of each task.
When checked, strike through the text and turn it light gray.
Tapping again restores it.
```

```text
Add a delete button (trash icon) to the right of each task.
Tapping it removes only that task from the list.
```

If you ask for both together and one breaks, you can't tell which. Asked separately, the culprit is always the last prompt. **When I'm stuck, I suspect only the most recent step.** That alone saved me a lot of wandering.

## Step 4: Keep the data

So far, closing the app wipes the list.

```text
Save the task list on the device so it's still there after reopening the app.
Update the saved data whenever I add, complete, or delete a task.
```

Rork chooses the storage method. If you're curious, ask "Which storage method did you use?" and it will explain.

The test is simple: add three tasks, fully quit the app, reopen it. If three remain, it works. Do this on the phone. I've seen lists that looked saved in the preview vanish on a device.

## Step 5: Polish the look

Only after the behavior is settled. Reverse the order and every color tweak risks changing behavior, leaving you unsure which change caused what.

```text
Change the colors to a calm, light-blue theme.
Give task rows rounded corners and a little space between rows.
Make the text a comfortable size on a real phone. Don't change any behavior.
```

"Don't change any behavior" is cheap insurance. If something still changes, go back one state and ask again with a narrower request.

## Step 6: Run the whole loop on a phone

1. Tap "Add" with an empty input
2. Add three tasks
3. Check one off
4. Delete one
5. Fully quit and reopen the app

If all five behave, you have a working Todo app. When you're ready to think about shipping, [building your first Rork app in 30 minutes](/articles/rork-basics/rork-first-app-30-minutes-guide) is a good companion.

## When you get stuck

Three places where I stalled:

First, **a button does nothing.** Usually the behavior from the last prompt never got in. Ask, "Explain what happens, in the current code, when I tap Add."

Second, **fixing one thing broke another.** Adding features can rewrite existing parts. I wrote up how to fence off what shouldn't change in [adding features to a Rork app without confusing the AI](/articles/rork-basics/rork-add-feature-incremental-prompt-guide).

Third, **it keeps drifting somewhere odd.** Don't push through. Go back to the last good state and ask again. Re-asking turned out shorter than patching, every time.

## Small first, one piece at a time

These six steps work for most small apps, not only Todo: looks, behavior, saving, polish, device check, in that order.

**Ask for one thing at a time, and verify on a real phone.** I still keep to that, even as my apps have grown.

For your next step, just send the Step 1 prompt. Behavior can come afterward.
