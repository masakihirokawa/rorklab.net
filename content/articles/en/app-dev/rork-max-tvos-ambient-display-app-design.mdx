The thought came to me one evening: what if the artwork from my own wallpaper app simply played on the living-room TV? I had been running iPhone wallpaper apps as an indie developer for a few years, and I suddenly wanted to see them on a large screen. Apple TV tends to fall outside the usual no-code or cross-platform conversation, but once Rork Max started generating native Swift, it finally became a realistic option.

tvOS works quite differently from iPhone. There is no touch; instead of a finger, you operate through a concept called focus. It is also assumed to stay on for long stretches, so power draw and burn-in deserve attention. Here I will use a quiet "ambient display app" that just keeps playing video as a vehicle for walking through how to refine the Swift that Rork Max generates.

## Why build Apple TV with Rork Max

Standard Rork builds cross-platform with React Native (Expo), but the heart of tvOS — the focus engine, Top Shelf, and low-level AVPlayer control — does not come naturally without native Swift. Rork Max generates native Swift for iPhone, iPad, Apple Watch, Apple TV, and Vision Pro, so when you are targeting Apple TV, this is the foundation.

My own rule of thumb is simple. When I want to ship iOS and Android together quickly, I use the React Native version; when I want to reach into Apple hardware or OS integration, I use Rork Max. Apple TV is a textbook case of the latter, because the cross-platform advantage simply does not exist here.

If you ask Rork Max to "make an ambient app for Apple TV that plays video full-screen on a loop," it returns a SwiftUI scaffold. As-is, though, rough edges remain: it plays, but flashes black at the seam, or focus moves in ways you did not intend. Everything from here is the hand-work.

## Building a seamless video loop

The first thing you hit is the loop seam. A naive implementation that rewinds the same clip with `AVPlayer` and `seek(to: .zero)` inserts a faint black frame on every rewind. On a large TV, that instant is clearly noticeable.

The fix is the combination of `AVQueuePlayer` and `AVPlayerLooper`. Internally it prefetches the next item and stitches playback without a gap.

```swift
import AVFoundation
import SwiftUI

final class AmbientPlayerModel: ObservableObject {
    let player: AVQueuePlayer
    private var looper: AVPlayerLooper?

    init(resourceName: String) {
        guard let url = Bundle.main.url(forResource: resourceName, withExtension: "mp4") else {
            self.player = AVQueuePlayer()
            return
        }
        let item = AVPlayerItem(url: url)
        let queue = AVQueuePlayer()
        // AVPlayerLooper handles the seamless loop
        self.looper = AVPlayerLooper(player: queue, templateItem: item)
        self.player = queue
        queue.isMuted = true
        queue.actionAtItemEnd = .advance
    }

    func start() { player.play() }
    func stop() { player.pause() }
}
```

The key is to keep `AVPlayerLooper` retained as a property. Make it a local variable and it gets released, and the loop stops. Rork Max's initial output often leaves this as a local variable, so I promote it to a property every time.

On the SwiftUI side, wrapping `AVPlayerLayer` thinly is easier to control than using `VideoPlayer`. `VideoPlayer` carries playback control UI that just gets in the way for an ambient use case.

```swift
struct PlayerLayerView: UIViewRepresentable {
    let player: AVQueuePlayer

    func makeUIView(context: Context) -> PlayerUIView {
        let view = PlayerUIView()
        view.playerLayer.player = player
        view.playerLayer.videoGravity = .resizeAspectFill
        return view
    }
    func updateUIView(_ uiView: PlayerUIView, context: Context) {}
}

final class PlayerUIView: UIView {
    override class var layerClass: AnyClass { AVPlayerLayer.self }
    var playerLayer: AVPlayerLayer { layer as! AVPlayerLayer }
}
```

Setting `videoGravity` to `.resizeAspectFill` fills the TV's aspect ratio without margins. My wallpaper assets have all sorts of aspect ratios, so switching this to `.resizeAspect` produced black bars on the sides and broke the ambient immersion.

## Working with the focus engine

Every interaction on tvOS goes through focus. Even on a screen with no interactive elements, the moment you touch the remote, Apple TV looks for "what to focus next." For ambient display I generally place no focusable target and just want to show the screen, so I keep focusable elements to a minimum.

That said, you still need one doorway into settings. I settled on a faint button at the bottom edge, toggled by the play/pause button on the remote.

```swift
struct AmbientRootView: View {
    @StateObject private var model = AmbientPlayerModel(resourceName: "loop_main")
    @State private var showsControls = false

    var body: some View {
        ZStack(alignment: .bottom) {
            PlayerLayerView(player: model.player)
                .ignoresSafeArea()

            if showsControls {
                Button("Choose what to show") { /* go to settings */ }
                    .padding(.bottom, 60)
            }
        }
        .onAppear { model.start() }
        .onPlayPauseCommand { showsControls.toggle() }
    }
}
```

`onPlayPauseCommand` is tvOS-specific and responds to the play/pause button on the Siri Remote. In an app that always shows something, having one such "hidden doorway" lets you keep the screen clean while preserving operability.

## Starting the experience before launch with Top Shelf

The top row of the Apple TV home screen — the band that expands when focused — is Top Shelf. Lining up thumbnails of your work there conveys the mood before the app even launches. For ambient apps, I feel this first few seconds of impression carries directly into continued use.

Top Shelf is implemented as a separate App Extension from the main app. After asking Rork Max to add the extension target, you flesh out the part that returns `TVTopShelfContentProvider` by hand.

```swift
import TVServices

final class ContentProvider: TVTopShelfContentProvider {
    override func loadTopShelfContent() async -> TVTopShelfContent? {
        let items = AmbientCatalog.featured.map { piece -> TVTopShelfSectionedItem in
            let item = TVTopShelfSectionedItem(identifier: piece.id)
            item.title = piece.title
            item.setImageURL(piece.thumbnailURL, for: .screenScale1x)
            item.setImageURL(piece.thumbnailURL2x, for: .screenScale2x)
            item.displayAction = TVTopShelfAction(url: piece.deepLink)
            return item
        }
        let section = TVTopShelfItemCollection(items: items)
        section.title = "Today's ambient"
        return TVTopShelfSectionedContent(sections: [section])
    }
}
```

The deep link you place in `displayAction` is received by the main app's `onOpenURL` and routed straight to the matching clip. Launch from Top Shelf and the chosen piece begins playing full-screen — when that flow is smooth, people set the remote down.

## The tension between always-on and power use

The fate of an ambient app is being left on. tvOS tries to fall back to the standard screen saver after a stretch of idle time, but if you want to keep your own video running, you need control equivalent to `isIdleTimerDisabled`. Do that without limits, though, and you get an app that "never turns off," which lands on the user's electricity bill.

As a compromise, I cap continuous playback and, once a set time passes, fade out quietly and hand off to the standard sleep. The table below shows the values I tuned while operating it.

<table>
  <thead>
    <tr><th>Setting</th><th>Initial</th><th>Tuned</th><th>Reason</th></tr>
  </thead>
  <tbody>
    <tr><td>Continuous playback cap</td><td>Unlimited</td><td>4 hours</td><td>Balance of left-on protection and power</td></tr>
    <tr><td>Video bitrate</td><td>20 Mbps</td><td>8–10 Mbps</td><td>Little perceptible difference on a big screen, less heat</td></tr>
    <tr><td>Fade duration</td><td>None</td><td>3 seconds</td><td>An abrupt cut feels jarring</td></tr>
  </tbody>
</table>

Bitrate mattered most. At TV viewing distance, the difference between 20 and 10 Mbps is barely visible, yet device heat and file size change noticeably. For ambient use, calm matters more than flash, so you can cut here decisively without losing the value.

## The next step

Start by looping a single clip you have with `AVQueuePlayer` and `AVPlayerLooper`, connect it to a TV, and check the seam with your own eyes. The moment the black frame disappears, the point of this approach clicks. From there, add Top Shelf and the time cap, and a quiet single screen for the living room takes shape.

I am still refining mine, but there is a different kind of satisfaction in seeing my own work play quietly on a large screen than on an iPhone. I hope this helps anyone who, like me, builds as an indie developer and wants to bring their work to a new place.
