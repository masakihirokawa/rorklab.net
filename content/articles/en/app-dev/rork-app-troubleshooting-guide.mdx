When you're new to Rork, it's hard to tell whether a problem is your prompt, the tool, or the underlying code. "The app doesn't work" could mean a dozen different things. Here are the ten issues that come up most often, along with what actually fixes them.

## 1. The prompt isn't doing what you expected

This is the most common sticking point. Rork interprets your prompt and generates code—so the quality of the output depends heavily on the specificity of the input.

**Vague prompts produce vague results:**

```
❌ "Make the button look better"
❌ "Fix the layout on this screen"

✅ "Make the blue circle button in the bottom-left of the Home screen slightly larger and give it more rounded corners"
✅ "Change the Submit button's background color to #3B82F6 and make the text white"
```

Name the element you want changed, describe its current state, and describe what you want. The more specific, the better.

**When words aren't enough, add a screenshot**

If you're trying to match a reference design or describe a visual problem, attach an image and say "change this part to look like this." It works better than trying to describe the visual in text.

## 2. Build failed

```
Build failed: Unable to compile app
```

**Try 1: Refresh the project state**

Click the refresh button (🔄) in Rork to reset the project state. Consecutive rapid changes sometimes leave the project in a broken intermediate state.

**Try 2: Undo and retry in smaller steps**

Use Undo to back out the most recent prompt, then try again in smaller pieces. Asking for many changes at once makes build failures much more likely.

**Try 3: Wait a few minutes**

Occasionally the Rork server is briefly unavailable. A few minutes is usually enough.

## 3. Preview looks fine but device looks wrong

The Rork preview targets a specific screen size. Different device sizes—especially smaller iPhones or tablets—can expose layout issues that don't appear in the preview.

**Specify your target device:**

```
"Make sure the layout renders correctly on iPhone 16 Pro (393×852 pt)
 as well as larger screen sizes like iPad"
```

**Safe area issues:**

If content is getting clipped behind the notch, Dynamic Island, or home indicator:

```
"Ensure all content is inside the Safe Area.
 Specifically, add appropriate padding to keep the navigation bar
 and bottom content clear of the status bar and home indicator"
```

## 4. API calls are failing

**Check 1: API key in environment variables**

Never paste an API key directly into a prompt or code. Add it to Rork's Environment Variables section, then reference it by name. This keeps it secure and avoids re-entering it every time.

**Check 2: CORS errors in browser preview**

```
Access to fetch at '...' blocked by CORS policy
```

Some APIs block browser requests for CORS reasons. Test on a real device or simulator instead, or ask Rork to route the API call through a server-side function.

**Check 3: Give Rork the full API spec**

```
"Call this API with the following configuration:
 Endpoint: https://api.example.com/v1/items
 Method: GET
 Header: Authorization: Bearer [VARIABLE_NAME]
 Response: JSON array of items with id, name, and price fields"
```

The more complete the spec, the more accurate the implementation.

## 5. Navigation isn't working

Button presses not triggering screen transitions, or back navigation not working as expected.

```
"When the user taps the 'View Details' button on the Home screen,
 navigate to the Detail screen with a slide-right animation.
 The navigation bar on the Detail screen should show a back button
 that returns to the Home screen"
```

Name the source element, the destination screen, and the animation type explicitly.

## 6. Data disappears when the app restarts

By default, Rork apps don't persist data between app sessions. If you need data to survive an app close:

```
"Save the user's name and email to local storage using AsyncStorage
 so the data persists when the app is closed and reopened"
```

For data that needs to sync across devices or users, ask Rork to connect a backend service like Supabase or Firebase.

## 7. Images aren't showing up

**HTTP vs HTTPS**

iOS apps block HTTP image URLs by default. Make sure your image URLs use HTTPS.

**Aspect ratio and clipping:**

```
"Display the profile image as a circle, 80×80 points.
 Crop from center and maintain the original aspect ratio"
```

## 8. Lists are slow or scroll is janky

For any list with significant data:

```
"Implement the product list using FlatList with virtualization enabled.
 The list should scroll smoothly with 1,000+ items.
 Add a keyExtractor using the item's id field"
```

Without explicit virtualization guidance, Rork may generate a basic ScrollView implementation that renders all items at once.

## 9. Push notifications aren't arriving

**First check: Is the device granting permission?**

```
"When the app launches, request notification permission.
 If granted, retrieve the device push token and log it to the console"
```

If you're seeing the token in the console, the problem is on the notification service side. If no token appears, the permission request isn't working correctly.

## 10. The app is crashing

When the app crashes on a specific action, paste the full error message directly into Rork:

```
"The following error is occurring. Please find the cause and fix it:

TypeError: Cannot read property 'map' of undefined
  at ProductList (ProductList.js:23)

Steps to reproduce:
1. Open the Home screen
2. Tap a product category
3. App crashes before the list appears"
```

Error message + reproduction steps together give Rork everything it needs to identify and fix the issue. Describing the symptoms without the error message forces Rork to guess.

---

Nine out of ten Rork problems resolve with one of three moves: make the prompt more specific, paste the exact error message, or try the change in smaller steps. The specific wording matters more than most people expect when working with AI code generation.

When you're stuck, look at your prompt first and ask: does it name the exact element, describe the current state, and say exactly what should change?
